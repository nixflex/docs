Connect the intended number to a business destination and verify the result end to end.

Using the dashboard? See [the business guide](/guides/business/integrations).

## Prerequisites

Keep the account credential in `NIXFLEX_API_KEY` on your server. Examples copied from the reviewed kit candidates need Node/CLI 0.10.0 or Python 0.3.0, which are not yet published. Use cURL until the matching release is available. Set all identifiers and the API host for the intended account and environment. Use an authorised test destination with fictional business data.

## 1. Read the saved connection

<CodeGroup>

```bash cURL
curl --request GET \
  --url "https://api.nixflex.com/v1/integrations/zapier/number/%2B12025550123" \
  --header "Authorization: Bearer $NIXFLEX_API_KEY"
```

```javascript Node
import { Nixflex } from 'nixflex';
const c = new Nixflex({apiKey:process.env.NIXFLEX_API_KEY,baseUrl:'https://api.nixflex.com',maxRetries:0});
const result = await c.integrations.get("zapier", "+12025550123");
// Keep private responses out of logs and AI conversations.
```

```python Python
import os
from nixflex import Nixflex
with Nixflex(api_key=os.environ["NIXFLEX_API_KEY"], base_url="https://api.nixflex.com", max_retries=0) as c:
    result = c.integrations.get('zapier', '+12025550123')
```

```powershell CLI (PowerShell)
nixflex integrations get zapier '+12025550123' --json --base-url "https://api.nixflex.com"
```

## 2. Save the intended destination

Choose the documented Zapier or Make number integration PUT route and save the authorised HTTPS destination. Each connection has its own settings and DELETE route; do not assume changing one also changes the other.

## 3. Define what success means

Treat automation triggers as event delivery, not an exactly-once transaction. Deduplicate work before sending texts, creating appointments or charging a customer. A repeated event must not repeat an irreversible downstream action.

## 4. Test a complete workflow

Use one approved test call and inspect both its Nixflex result and the receiving system. Check missing fields, delayed processing and duplicate delivery. Do not promise a notification arrives within a fixed number of seconds.

## 5. Disconnect and reconcile

Use the documented integration DELETE route to stop future use. Previously delivered external records remain subject to that system’s controls. If a save or deletion response is lost, read the current settings before repeating it.

## Example response

GET returns the safe saved integration configuration. The settings response confirms configuration state; external delivery and business-action results must be checked separately.

## Errors and limits

| Condition | Handling |
| --- | --- |
| Invalid credentials/destination | Correct configuration before retrying. |
| Saved but no notification | Inspect call state and external delivery separately. |
| Duplicate event | Deduplicate before repeating a side effect. |
| Unknown save/delete result | Read current configuration. |
| Data deleted in Nixflex | Manage previously sent external copies separately. |
