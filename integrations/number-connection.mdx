## Prerequisites

Keep `NIXFLEX_API_KEY` private on the server and use `https://api.nixflex.com`. Use owned identifiers; SDK and CLI examples need the [documented minimum versions](/sdks/ecosystem#install-a-client). Prepare the number’s authorised connection details through your private configuration process.

## 1. Read existing numbers

Node and Python below use their standard HTTP clients. Keep `NIXFLEX_API_KEY` on the server. The CLI examples require a kit version supporting the command; see [release status](/sdks/ecosystem). No example retries a mutation automatically.

<CodeGroup>

```bash cURL
curl --fail-with-body --request GET \
  --url "https://api.nixflex.com/v1/phone-numbers/%2B12025550100" \
  --header "Authorization: Bearer $NIXFLEX_API_KEY"
```

```javascript Node
const response = await fetch('https://api.nixflex.com/v1/phone-numbers/%2B12025550100', {

  redirect: 'error',

const result = await response.json();
if (!response.ok) throw new Error(`HTTP ${response.status}: ${result?.error?.code ?? "unavailable"}`);

```

```python Python
import os, json
from urllib.request import HTTPRedirectHandler, Request, build_opener

class NoRedirect(HTTPRedirectHandler):

    method='GET',
    headers={'Authorization': 'Bearer ' + os.environ['NIXFLEX_API_KEY']},
)
with build_opener(NoRedirect).open(request, timeout=30) as response:
    result = json.load(response)

```

## 2. Check the target account and agent

Use an active agent owned by the same account. A number already connected elsewhere or still settling an earlier operation cannot be treated as a fresh import. Do not change origin labels to bypass account checks.

## 3. Prepare the documented import

Use the supported dashboard flow for a new import. The [number import contract](/api-reference/phone-numbers/import) omits the existing legacy credential payload; it is not a complete credential validator. Field names can depend on that contract; do not invent neutral replacements for required values. Keep credentials in protected server configuration, never in customer-facing instructions.

## 4. Reconcile the saved state

Submit the intended import once and retain any returned operation information. Read back the owned number and verify the real routing result. A saved credential or signature-key candidate is not proof its later callback verification succeeded.

## 5. Move with the supported update

To change agents within the account, use an agent-only number PATCH after busy work settles. Do not remove and re-import as the normal move procedure. Removal has its own external-cleanup and uncertain-state handling.

## Example response

A number read returns `{"phone_number":{...}}` with safe public settings and read-only `source`. Private credentials and internal operation tokens are excluded.

## Errors and limits

| Condition | Handling |
| --- | --- |
| Already connected or pending | Reconcile existing state before a new import. |
| Busy number | Wait for current work to settle. |
| Unknown routing outcome | Preserve pending state; do not claim completion. |
| Remove connection | It does not guarantee cancellation of external rental. |
| Connection-specific fields | Use the exact API contract; do not rename enums. |
