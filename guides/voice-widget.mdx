Let visitors ask questions by text or voice on your website. Your web agent uses a business number for its setup and inbox, even though visitors do not dial it. Its website instructions are separate from phone and SMS instructions.

**The important part**

- Website instructions and knowledge switches are separate from phone and SMS.
- Install the current generated snippet and test a real conversation on the site.

- Visitor-supplied contact details are not verified identity; public custom functions need their own review.

## Before you start

- Use an Owner or Admin login and a dashboard-managed number.
- Have permission to edit the website or send installation instructions to its maintainer.

## Steps

<Steps>

<Step title="Create the web agent">

<span id="1-create-the-web-agent" />

Open **Web agent**, choose **Create web agent** and select the number. For an existing setup, choose **Edit web agent**. Check the attached agent, because its knowledge is shared with that number.

</Step>

<Step title="Write website instructions">

<span id="2-write-website-instructions" />

Describe the business, the questions the website agent should answer and what to say when unsure. Save within the displayed limit. If you use knowledge, enable website chat and website voice separately in the attached agent’s Knowledge settings.

</Step>

<Step title="Choose the visitor experience">

<span id="3-choose-the-visitor-experience" />

Choose the design, colours, display name and quick questions. Configure contact fields and decide whether visitors must save them before chatting or calling. Enable website voice if wanted; it also needs Web agent on.

</Step>

<Step title="Install the saved snippet">

<span id="4-install-the-saved-snippet" />

Choose **Install**, then **Copy code and instructions** and follow the website-specific guidance. Use the current generated snippet. If the preview says installation is not ready, use its design preview and wait for installation to become available.

</Step>

<Step title="Test on the website">

<span id="5-test-on-the-website" />

Open the test site, save the requested contact fields, send a question and try a voice call. Allow microphone access when asked. Check the saved conversation in the dashboard. Connected reports loading, so test the actual conversation too.

</Step>

</Steps>

## What happens next

Visitors use the website instructions and enabled knowledge. Built-in calendar booking, SMS, transfers and keypad actions are not available on the website. Website custom functions require their separate switch and must be suitable for public visitors.

## Check the result

| Result | What it means | What to do |
| --- | --- | --- |
| Connected | The widget reported loading. | Test an actual message and voice call. |
| Installation not ready | The snippet is not yet available for installation. | Use the design preview and wait for installation readiness. |
| Voice unavailable | Required switches or microphone access may be missing. | Check Web agent, website voice and browser microphone access. |
| New visitor identity | The browser may have different or cleared storage. | Review the conversation itself; do not assume identity continuity. |

## Common questions

<AccordionGroup>

<Accordion title="Does each website get different knowledge?">

Numbers attached to one agent share its knowledge. Use separate agents for different factual answers.

</Accordion>

<Accordion title="Will visitors always be recognised?">

Recognition depends on the browser’s saved information. Another browser or cleared storage can create a new visitor.

</Accordion>

<Accordion title="Can I remove the Nixflex footer?">

The widget keeps its Powered by Nixflex footer.

</Accordion>

<Accordion title="Must I copy a new snippet after changes?">

Follow the installation screen. Some newer visitor and installation features require a current snippet; do not assume an old embed gains every feature.

</Accordion>

</AccordionGroup>
