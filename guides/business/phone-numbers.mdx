- Importing a number changes its call routing. Arrange the handover before saving.

- A pending or unknown result needs a status check before another change. Do not delete and reimport to clear uncertainty.

## Before you start

- Use an Owner or Admin login.
- Have an active number in full international format and its connection details.
- Create the agent that will answer it.

## Steps

<Steps>

<Step title="Open Phone Numbers">

<span id="1-open-phone-numbers" />

Choose **Phone Numbers** and select **Import number**. Confirm you are working with the intended business line. Importing changes its call routing, so arrange a suitable handover from any existing answering service.

</Step>

<Step title="Complete the connection">

<span id="2-complete-the-connection" />

Enter the number and the connection fields shown for its setup. Keep credentials private. The number must already be active for the intended calls or texts; importing does not buy a number or enable destinations in your telephone account.

</Step>

<Step title="Choose the agent">

<span id="3-choose-the-agent" />

Select the agent and complete the import. Wait for the result. If the request is still pending or its result is unknown, inspect the number’s state before trying again. Do not assume a lost response means no routing changed.

</Step>

<Step title="Check its switches">

<span id="4-check-its-switches" />

Review inbound, outbound, SMS auto-reply, Web agent, website voice, website custom functions and Live Monitor. Website voice also needs Web agent on. Enabling a channel does not write its instructions or connect its integrations.

</Step>

<Step title="Move it when needed">

<span id="5-move-it-when-needed" />

Choose **Move number**, select the number and the new agent, and confirm the change. A busy number cannot move until its current work finishes. Number settings, integrations and history stay with the number; inherited voice and knowledge follow the new agent.

</Step>

</Steps>

## Update carrier details

To replace connection details for an existing number, open **Phone Numbers → Provider → Update carrier details**. The Owner or an Admin enters the new details in the private fields. Stored secrets are not shown. The new carrier account must contain that exact number; this action does not switch carriers.

Wait for the confirmed result. Your number, agent, instructions, switches, integrations and history stay in place. Follow any fresh test-call or approval request shown afterwards. If the result is unknown, check the status and contact support before retrying. If Nixflex specifically asks you to finish a pending save, use the same details. Do not delete and reimport the number to clear an uncertain result.

## What happens next

Test an incoming call and any outgoing or text feature you intend to use. Check the attached agent and knowledge after a move, especially when branches have different facts.

## Check the connection result

| What you see | What it means | What to do |
| --- | --- | --- |
| Connected to the intended agent | The saved assignment is in place. | Test incoming calls and each enabled outgoing or text channel. |
| Number busy | Current work prevents a move. | Let that work finish, then check again. |
| Save pending or unknown | Routing may have changed even without a reply. | Inspect the number’s current state before another attempt. |
| Number absent from a list | The screen may show only dashboard-managed numbers. | Check where the number was originally managed. |

## Common questions

<AccordionGroup>

<Accordion title="Do I keep ownership?">

Yes. Number rental and telephone charges stay with your telephone account.

</Accordion>

<Accordion title="Does removing it cancel the rental?">

No. Removing the connection in Nixflex is separate from releasing the number in your telephone account. Cleanup can remain pending.

</Accordion>

<Accordion title="Why is a number absent from a dashboard list?">

Some dashboard screens show only numbers added there. Numbers managed through code remain managed through code.

</Accordion>

</AccordionGroup>
