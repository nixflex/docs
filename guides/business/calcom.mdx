## Before you start

- Use an Owner or Admin login.
- Have access to the intended Cal.com account and a connected Nixflex number.

## Steps

<Steps>

<Step title="Choose the business number">

<span id="1-choose-the-business-number" />

Open **Integrations**, select the agent and the phone number that should book appointments. Calendar settings belong to that number, so check your selection before entering any connection details.

</Step>

<Step title="Open Cal.com">

<span id="2-open-calcom" />

Open the **Cal.com** card. Have the intended account’s connection key, username and event slug ready. Use a test calendar while setting up and keep connection details private.

</Step>

<Step title="Set the appointment details">

<span id="3-set-the-appointment-details" />

Enter the requested fields and select the calendar’s actual time zone. Check the event type exists and represents the service callers should book. Do not use a default time zone simply because it appeared in an example.

</Step>

<Step title="Save the connection">

<span id="4-save-the-connection" />

Choose **Save** and check the saved state. Once a key is stored, its field stays empty and says **Saved — leave blank to keep**. Leave it blank for ordinary settings changes; enter a new key only when replacing it. Stored keys are not displayed. If the result cannot be checked, refresh the card before entering another change. A saved connection still needs a real booking test.

</Step>

<Step title="Test a booking">

<span id="5-test-a-booking" />

Call from your test phone. Approve the name read-back, then the email separately. The agent spells the part before @; familiar domains use words and unusual domains are spelled too. A correction repeats that field's check. After approval, booking messages omit the address. Verify the appointment in Cal.com, and test an unavailable time and a correction. Then remove the test booking. Cal.com handles its own emails; the agent must not claim an unconfirmed send or promise inbox delivery.

</Step>

</Steps>

## What happens next

Describe the booking task in the phone and SMS instructions you use. Knowledge can explain services and policies, but a live calendar action confirms the appointment.

## Check the booking setup

| What you see | What it means | What to do |
| --- | --- | --- |
| Connection saved | The selected number has saved settings. | Make a controlled booking test. |
| Saved key field empty | The stored secret is hidden. | Leave it blank to keep the existing key. |
| Save outcome unknown | You do not know whether the new settings took effect. | Refresh the card before making another change. |
| Conversation promises a booking | The spoken answer is not the final record. | Check Cal.com and the available booking result. |

## Common questions

<AccordionGroup>

<Accordion title="Does connecting send text confirmations?">

Text confirmation also depends on In-Call SMS and recipient eligibility. Check actual delivery separately.

</Accordion>

<Accordion title="Can I disconnect later?">

Use **Disconnect** on the selected number’s calendar card. This removes the Nixflex connection; it does not delete appointments already in your calendar.

</Accordion>

<Accordion title="Does this enable website booking?">

No. Built-in website calendar actions are unavailable.

</Accordion>

</AccordionGroup>
