## Prerequisites

Keep `NIXFLEX_API_KEY` private on the server and choose the matching API host. Use owned identifiers; SDK and CLI examples need the [exact reviewed candidate](/sdks/ecosystem). Set `NXF_AGENT_ID`, `NXF_PHONE_NUMBER` and `NXF_TO_NUMBER` to the intended owned sender and approved recipient.

## 1. Prepare a clear purpose

Describe the business, reason for calling, two or three questions and a polite finish. Include `prompt` on the call request. Supply `dynamic_vars` for known values and validate required placeholders before sending.

## 2. Create the call

<CodeGroup>

```bash cURL
curl --request POST \
  --url "https://api.nixflex.com/v1/calls/outbound" \
  --header "Authorization: Bearer $NIXFLEX_API_KEY" \
  --header "Content-Type: application/json" \
  --data "{\"agent_id\":\"$NXF_AGENT_ID\",\"from_number\":\"$NXF_PHONE_NUMBER\",\"to_number\":\"$NXF_TO_NUMBER\",\"prompt\":\"Confirm the requested appointment\"}"
```

```javascript Node
import Nixflex from 'nixflex';
const baseUrl = 'https://api.nixflex.com';
const client = new Nixflex({apiKey:process.env.NIXFLEX_API_KEY,baseUrl,maxRetries:0});
const result = await client.calls.create({agent_id:process.env.NXF_AGENT_ID,from_number:process.env.NXF_PHONE_NUMBER,to_number:process.env.NXF_TO_NUMBER,prompt:"Confirm the requested appointment"});
// Handle result privately; do not log secrets or call content.
```

```python Python
import os, json
from pathlib import Path
from nixflex import Nixflex
base_url = "https://api.nixflex.com"
with Nixflex(os.environ["NIXFLEX_API_KEY"], base_url=base_url,max_retries=0) as client:
    result = client.calls.create(agent_id=os.environ["NXF_AGENT_ID"],from_number=os.environ["NXF_PHONE_NUMBER"],to_number=os.environ["NXF_TO_NUMBER"],prompt="Confirm the requested appointment")
# AsyncNixflex supports the same calls with await (and async with).
```

```bash CLI
NIXFLEX_API_KEY="$NIXFLEX_API_KEY" nixflex calls create --agent "$NXF_AGENT_ID" --from "$NXF_PHONE_NUMBER" --to "$NXF_TO_NUMBER" --prompt "Confirm the requested appointment" --base-url https://api.nixflex.com --json
```

## 3. Save the returned identity

Persist `call_id` with your operation record. Acceptance is not a connected call. If the network response is lost, reconcile before repeating; do not enable automatic transport retries for call creation.

## 4. Read the outcome

Read the call or consume its signed event. Use observed answers and analysis as reviewable data. A summary can be delayed or unavailable and is not a guarantee every requested question was answered.

## 5. Plan follow-up deliberately

Respect contact restrictions and the person’s wishes. If you send a follow-up text, use an explicit eligible sender and approved wording. A failed wait in your client does not hang up the call or prove it was never placed.

## Example response

The create response identifies the accepted call and current state. Read the [create schema](/api-reference/calls/create-outbound) and retain any safe outcome or retry fields returned on failure.

## Errors and limits

| Condition | Handling |
| --- | --- |
| Contact refusal | Respect suppression, location and local-hours reasons. |
| Capacity or balance refusal | Resolve the account condition before new work. |
| Unknown transport outcome | Reconcile existing work; do not blindly resend. |
| Client wait expired | Keep tracking the original call. |
| Missing analysis | Preserve unknown fields and review the conversation. |
