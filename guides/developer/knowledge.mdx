Build a review-first workflow: **agent base → source → preparation job → draft → accept → publication job → live topics**. Knowledge belongs to the agent, and all its attached numbers use that base when the channel is enabled.

Using the dashboard? See [teach your agent about your business](/guides/business/knowledge).

## Prerequisites

- An account API credential in `NIXFLEX_API_KEY` and an owned active agent ID in `NXF_AGENT_ID`.
- Knowledge enabled for the account. API-managed and mixed-origin agents can be hidden from dashboard knowledge screens while remaining accessible to the owning API key.
- A durable operation record in your application. Knowledge writes require an `Idempotency-Key`: 8–128 letters, digits, dots, underscores, colons or hyphens. The `prompt:` prefix is reserved. Use one key per intended operation and retain it across an uncertain response.

The examples use the production API address. Choose the intended environment and its matching credential before running anything. Node/CLI 0.10.0 and Python 0.3.0 knowledge methods are release candidates; use cURL until the corresponding kit release is available. No example here is a promise that an unpublished package is installed.

## 1. Read capabilities and create the agent base

Read [capabilities](/api-reference/knowledge/get-knowledge-capabilities) and `GET /v1/agents/{agent_id}/knowledge-base`. The scope reply contains `own` and `effective`; they can be null before creation. Create the singleton with `PUT` at the same path, a new idempotency key and this body:

```json
{"settings":{"channels":["inbound"],"match":"Strict","not_found":"I don't have that information right now."}}
```

Save `own.id` as `NXF_KNOWLEDGE_BASE_ID` and its integer `rev`. An update to an existing base needs its current `expected_revision`. The settings channels are `inbound`, `outbound`, `web_voice`, `web_chat` and `sms`; only inbound starts enabled. Campaigns use outbound, with no separate campaign switch. `not_found` must be nonblank and at most 500 characters.

[Create or update an agent base](/api-reference/knowledge/put-agents-target-knowledge-base) documents the scope envelope. Retired number-knowledge routes return 410; never create a number-level base. Old retained number-base rows are not automatically converted into live agent knowledge. Re-add the intended facts to the current agent and review them explicitly.

## 2. Add a source with review enabled

Set `NXF_IDEMPOTENCY_KEY` to a fresh operation key. The same text import is shown in all four tabs:

Use this body in each example. Save it as `request-112.json` for the CLI.

```json
{
  "source": {
    "type": "text",
    "title": "Appointments",
    "text": "Appointments are available Monday to Friday."
  },
  "review": true
}
```

`review:true` is deliberate. The public API defaults to false, which can publish after preparation; dashboard imports always require review. Flags and review reminders can force a draft even when false was requested.

For files, POST raw bytes to the same source endpoint with `Content-Type: application/octet-stream`, `X-Filename`, `X-Review: true` and the idempotency header. Do not send base64 or a local path. Supported contents are UTF-8 text, PDF with selectable text and DOCX. A preview via [source measure](/api-reference/knowledge/post-agents-target-knowledge-base-source-measure) counts privately without saving a source; it is not publication clearance.

For websites, create a [discovery job](/api-reference/knowledge/post-knowledge-bases-kb-website-discoveries), read its `result.pages`, let the user choose IDs, then submit `discovery_id`, `page_ids` and `review:true` to [website imports](/api-reference/knowledge/post-knowledge-bases-kb-website-imports). A direct `source.type:url` or `qa` is refused.

## 3. Poll the job and review its draft

An import returns HTTP 202. Example response, with illustrative IDs:

```json
{"id":"11111111-1111-4111-8111-111111111111","kb":"22222222-2222-4222-8222-222222222222","kind":"import","state":"pending","stage":"pending","progress":{"percent":0},"result":null,"error":null}
```

Poll [GET job](/api-reference/knowledge/get-knowledge-jobs-id) using the returned `id`. Use a bounded delay, for example one second increasing to five seconds, and stop when the user leaves the screen. This is a client choice, not a required server interval. Honour `next_retry_at` and HTTP retry guidance. Resume later from the same job ID rather than submitting another import.

| State | Client action |
| --- | --- |
| `pending`, `running` | Keep polling; show server `stage` and `progress.percent`. Progress measures completed stages, not time remaining. |
| `needs_review` | Read `result.draft_id` and show the draft for review. |
| `ready` | Inspect the job kind and result. An unchanged or duplicate-only import can be ready without publishing new topics. |
| `failed` | Read the job’s safe `error`. HTTP 200 for a failed job is still a failed operation. |
| `cancelled`, `deleted` | Stop polling and reconcile current state. |

Read [the draft](/api-reference/knowledge/get-knowledge-bases-kb-drafts-id). Older drafts can be normalised on read, so retain the returned `data.edit_revision`, not an earlier cached value. Show each topic’s `facts`, title and review reasons. Edit with `expected_revision`, `expected_draft_revision`, `topic_id` and `topic`; save before accepting.

## 4. Accept selected topics and wait for publication

POST to [accept draft](/api-reference/knowledge/post-knowledge-bases-kb-drafts-id-accept) with a new operation key. Use the current base revision, current draft edit revision and the explicit IDs the reviewer selected:

```json
{"expected_revision":1,"expected_draft_revision":0,"topic_ids":["33333333-3333-4333-8333-333333333333"]}
```

Those values are examples, not defaults to hard-code. If warnings exist, collect acknowledgement and send `acknowledge_warnings:true`. Individually approved flagged pieces go in `approved_flagged_topic_ids`; never populate that array automatically. An unticked replacement retains the existing live topic.

Acceptance returns another job. Poll until its publication is confirmed, then reread the base and [live topics](/api-reference/knowledge/get-knowledge-bases-kb-topics). Lists use `items,next_cursor`, with limit 1–100. A stale topic cursor requires restarting the list. The old live answer is suppressed during a live-topic edit; a source import does not replace accepted facts merely because preparation started.

## 5. Test, maintain and export

Create a [test session](/api-reference/knowledge/post-agents-target-knowledge-base-test-sessions) for the agent with `{"mode":"knowledge","channel":"inbound"}` and a new key. POST `{"text":"When are appointments available?"}` with another key to [session messages](/api-reference/knowledge/post-knowledge-test-sessions-id-messages). Save the session ID and read the answer and supplied topic evidence. `selection:whole_base` means the small base was supplied whole, including for an unrelated question. Evidence is supplied context, not a claim that every topic influenced the answer.

Test is knowledge-only: no full-agent mode, number context, call purpose, training or correction-note endpoints. It performs no call, booking or message action. Questions read current facts; the latest 100 messages are retained for context. A session needs live unsuppressed knowledge. Use a complete call test separately for agent behaviour.

Refresh selected saved website sources explicitly. Topic deletion prevents a same-source refresh from resurrecting the piece; deleting the last topic also removes its source and retained original. A new explicit addition is a separate operation.

Create an [export job](/api-reference/knowledge/post-knowledge-bases-kb-exports), poll it, then read `/v1/knowledge/exports/{id}`. Default JSON preserves developer metadata; `?format=text` returns `filename`, `content_type` and `text`. Exports last one hour and require an unchanged revision. Rebuild a stale export with bounded retries. Raw uploaded files are excluded. Whole-base deletion revokes access first and returns a cleanup job; track it to completion.

## Errors and limits

| Status or condition | Meaning | Recovery |
| --- | --- | --- |
| 400 `invalid_input` | Invalid source, test mode or field | Correct the request. |
| 409 `stale_revision` | The base, source, draft or cursor changed | Read current state, review again and use the correct revision for that resource. |
| 409 `idempotency_conflict` | Same key used for different input | Preserve the original operation; use a new key only for a new intention. |
| 409 `review_required`, `suspicious_review_required` | Review is incomplete | Collect explicit choices; do not auto-approve warnings. |
| 409 `knowledge_missing` | No live usable knowledge for Test | Publish a topic first. |
| 410 `number_knowledge_removed` | Number-level knowledge is retired | Use the current attached agent. |
| 413 file/source/knowledge limits | Input or saved inventory is too large | Reduce input or remove unneeded sources. |
| 415/422 file validation | Unsupported, unsafe or unreadable content | Fix the source; image-only PDFs need selectable text or pasted text. |
| 429 `busy` or an allowance limit | Work or account limit reached | Wait for current work or the stated reset; do not create duplicates. |
| 503 `knowledge_loading` | Test could not load/check current knowledge in time | Retry that completed refusal with a fresh key; retain the old key for an unknown network outcome. |
| Other 503 or network failure | Dependency unavailable or outcome uncertain | Retry bounded reads; reconcile writes with their original key and job before repeating. |

| Limit | Value |
| --- | --- |
| Source / saved base | 20,000 / 100,000 tokens |
| Packed topic | 800 tokens |
| File / PDF | 10 MiB / 200 pages |
| Sources / topics per base | 50 / 1,000 |
| Bases / private storage per account | 20 / 100 MiB |
| Active jobs | 8 per account |
| Test question | 4,000 characters |
| Test sessions | 100 starts per day; no question-count gate within an active session |

Read capabilities and usage instead of inferring entitlement from old training counters. Local file checks are not a comprehensive virus scan. When a scanner is configured but unavailable, PDF/DOCX jobs can wait at `safety_check` or `safety_waiting`; use the server retry time and expiry message.
