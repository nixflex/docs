## Read the current campaign

Use [campaign detail](/api-reference/sms/campaigns-get) with the saved ID. Preserve `sent_count`, `delivered_count`, `failed_count` and `reply_count` as distinct fields. Do not derive one by subtracting unrelated totals or treat message acceptance as delivery.

Replies can arrive after the original send. Campaign reply association depends on its configured window and context; actual auto-reply still depends on the number’s SMS settings. Inspect the related [inbox](/guides/developer/agent-inbox) when your workflow needs the conversation.

## Resolve contact holds

Missing consent, contact hours, suppression and uncertain transport outcomes require different decisions. Record genuine consent using the documented consent action, honour recipient-local policy and keep unknown sends visible. A new campaign is not a way to reconcile the original send.

## Cancel, resume or edit

Use [cancel](/api-reference/sms-campaigns/post-sms-campaigns-id-cancel) to stop future dispatch and [resume](/api-reference/sms-campaigns/post-sms-campaigns-id-resume) only when the current state and contact checks allow it. Read back the campaign after a confirmed result. After a lost response, reconcile that same campaign before another write.

The [update route](/api-reference/sms-campaigns/patch-sms-campaigns-id) permits only documented fields and states. It is not a way to alter an already accepted message at its destination.

## Keep deletion separate

Deleting a voice or SMS campaign cancels waiting work, hangs up its running calls, then removes the campaign and recipient list. Calls already made and texts already sent stay in history. Used charges stay in billing; there are no refunds. Owner and Admin can delete; Member cannot. Cancel alone stops future dispatch and lets active calls finish; Delete also requests their hang-up. Use [DELETE SMS campaign](/api-reference/sms/campaigns-delete). If hang-up is not confirmed, HTTP 503 `hangup_pending` returns `error.details.deleted:false` and `error.details.retry_pending:true`. Deletion stays queued and continues automatically. Repeating the same DELETE for the same account and ID safely resumes it. A lost response or `deletion_unavailable` is not success: check the list, then repeat that same DELETE if needed. Missing and foreign IDs share HTTP 404. Bulk call deletion and account closure keep separate safety rules.

| Observation | What to show or do |
| --- | --- |
| Sent but delivery not confirmed | Retain the actual delivery state; do not mark it delivered. |
| Reply arrives later | Associate it using the current campaign and conversation rules. |
| Unknown send outcome | Reconcile the existing recipient; do not automatically resend. |
| Control response lost | Read the campaign before repeating the control. |
| Delete result unconfirmed | Show queued or unconfirmed, check the list, and resume with the same DELETE if needed. |
