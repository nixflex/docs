```json
{"error":{"type":"conflict","code":"do_not_contact","message":"This recipient is on your do-not-contact list. The message was not sent.","doc_url":"https://docs.nixflex.com/errors/do_not_contact","details":{}}}
```

| Result | Application action |
| --- | --- |
| 400 validation | Correct the request. Do not repeat it unchanged. |
| 401 authentication | Check the full server credential and intended environment privately. |
| 403 permission | Respect the role or account restriction. A shared key is not a browser workaround. |
| 404 owned resource | Check the identifier and ownership; do not infer another account's data. |
| 409 conflict | Follow the exact code and inspect current state. |
| 429 rate limit | Honour `Retry-After`; apply the operation's retry rules. |
| 503 or lost connection | A write may have happened. Reconcile before trying again. |

## SMS suppression change

Single `POST /v1/sms` suppression now returns **409 `do_not_contact`**, with type `conflict`. It previously returned **400 `invalid_request`**. Update code that matches the old response. Nothing was sent: stop and respect the recipient's opt-out. Campaign recipients remain held individually with `hold_reason: do_not_contact`.

## Preserve uncertainty

Call and campaign deletion are awaiting the reviewed B57 contract. Follow the DOCS-PENDING note on the [deletion reference](/api-reference/sms/campaigns-delete); do not implement the old settlement-wait rules as a claim about the next release. A missing response still does not prove any operation completed.

An accepted call or SMS request is not delivery proof. Save returned identifiers and read the resulting record. For number credentials, `carrier_outcome_unknown` needs support investigation; `credential_save_pending` permits a deliberate retry with identical details to finish the local save. Never delete and re-import to recover.

Show a safe message and retain the code and operation ID when present. Keep full bodies, caller details and credentials out of logs. See the [error catalog](/api-reference/errors) and [retry contract](/api-reference/retries).
