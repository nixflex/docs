## Prerequisites

Keep the account credential in `NIXFLEX_API_KEY` on your server. Examples copied from the reviewed kit candidates need Node/CLI 0.11.0 or Python 0.4.0, which are not yet published. Use cURL until the matching release is available. Set all identifiers and the API host for the intended account and environment. Choose an active owned agent, an eligible sender and recipients you are permitted to contact. The example below only lists existing campaigns.

## 1. Read existing campaigns

<CodeGroup>

```bash cURL
curl --request GET \
  --url "https://api.nixflex.com/v1/campaigns?status=running&limit=2" \
  --header "Authorization: Bearer $NIXFLEX_API_KEY"
```

```javascript Node
import { Nixflex } from 'nixflex';

const c = new Nixflex({
  apiKey: process.env.NIXFLEX_API_KEY,
  baseUrl: 'https://api.nixflex.com',
  maxRetries: 0,
});
const result = await c.campaigns.list({"status": "running", "limit": 2});
```

```python Python
import os
from nixflex import Nixflex

with Nixflex(
    api_key=os.environ["NIXFLEX_API_KEY"],
    base_url="https://api.nixflex.com",
    max_retries=0,
) as c:
    result = c.campaigns.list(status='running', limit=2)
```

```powershell CLI (PowerShell)
nixflex campaigns list --status running --limit 2 --json --base-url "https://api.nixflex.com"
```

## 2. Prepare and preview recipients

Build rows with `phone`, nested `variables`, and known `country`/`timezone` values. Supply a nonblank campaign `prompt`; use `prompt_override` only for deliberate row-specific instructions. Preview local hours and validate every required value. Choose `duplicate_policy:reject` if duplicate contacts must be prevented; `warn` retains them.

## 3. Create executable work

POST `/v1/calls/batch` with `agent_id`, `from_number`, `prompt` and recipients. `schedule_type:now` requests launch immediately; `schedule` uses `scheduled_date` in YYYY-MM-DD form and may run automatically when due. `duplicate_choice_required` is advisory, not a sending lock. Consent and current dispatch checks still apply.

## 4. Track and control the existing campaign

Save `campaign_id` even if launch is uncertain. Read campaign state and holds. Use the documented consent, cancel and resume endpoints for that same campaign. Cancel prevents further dispatch; it does not hang up active calls. Resume does not mean repeat completed recipients.

## 5. Reconcile before replacement

`reuse_campaign_id` replaces an owned never-launched draft or scheduled voice campaign; it is not an idempotency key. Do not recreate after `campaign_outcome_unknown`. There is no public voice campaign deletion endpoint.

## Example response

Creation returns `campaign_id`, recipient validation and current status. Immediate launch can also return `queued`, `failed` and legacy `dialed`; `dialed` counts enqueued jobs, not connected calls. [Create response fields](/api-reference/calls/batch-create) define the exact shape.

## Errors and limits

| Condition | Handling |
| --- | --- |
| Duplicate warning | Review it before calling create; warn does not stop dispatch. |
| Missing consent/location/contact hold | Resolve that reason on the existing campaign. |
| Unknown creation or launch outcome | Reconcile using the saved campaign ID. |
| Maximum recipients | Up to 100,000 accepted rows; request-size limits can apply first. |
| Wider hours | Record a valid explanation; current policy still applies. |

## Delete content deliberately

Deleting a voice or SMS campaign cancels waiting work, hangs up its running calls, then removes the campaign and recipient list. Calls already made and texts already sent stay in history. Used charges stay in billing; there are no refunds. Owner and Admin can delete; Member cannot. Cancel alone stops future dispatch and lets active calls finish; Delete also requests their hang-up.

If hang-up is not confirmed, HTTP 503 `hangup_pending` returns `error.details.deleted:false` and `error.details.retry_pending:true`. Deletion stays queued and continues automatically. Repeating the same DELETE for the same account and ID safely resumes it. A lost response or `deletion_unavailable` is not success: check the list, then repeat that same DELETE if needed. Missing and foreign IDs share HTTP 404. Bulk call deletion and account closure keep separate safety rules.

Read [delete call data](/guides/business/privacy/delete-call-data) for the dashboard task and [single-call deletion](/api-reference/calls/delete) for response fields.
