The **web agent** is an embeddable widget that puts a floating **Call + Chat** launcher on any website. Visitors can call your AI phone number, or chat in text with an assistant you control. It is a single `<script>` tag - no build step, no dependencies.

<Note>
  Everything about the widget's look and behaviour is controlled by `data-*` attributes on the script tag. The design lives in the snippet, not in the number - so any number with an agent can power any design.
</Note>

## Quick start

<Steps>
  <Step title="Copy the snippet">
    Grab the embed code from your dashboard (**Web Agent** tab), or use the example below.
  </Step>
  <Step title="Set your number">
    Put one of your numbers (with an agent attached) in `data-number`.
  </Step>
  <Step title="Paste it before the closing body tag">
    Drop the script just before `</body>` on any page. The launcher appears in the corner.
  </Step>
</Steps>

```html
<script
  src="https://nixflex.com/button.js"
  data-number="+441234567890"
  data-design="1"
  data-color="#25D366"
  data-name="Acme Coffee">
</script>
```

## How it works

- **Call** is a `tel:` link that dials `data-number` - it opens the phone dialer (shows "Call now" on mobile). No browser audio is used.
- **Chat** sends the visitor's message to the widget endpoint, and the web agent replies in text using **that number's web instructions** (see below).

<Note>
  The chat endpoint allows requests from any origin, so the widget works on any customer website with no domain whitelisting.
</Note>

## Designs

The widget ships with several ready-made designs (different launcher shapes, colours, and open-panel styles). Browse them in the dashboard **Web Agent** tab, preview each one, and copy the snippet for the design you like. Set the one you want with `data-design` and tint it with `data-color`.

## Teaching the web agent what to say

The web agent answers **only from its own web instructions** - the `web_prompt` you set for that number. It does **not** borrow your phone agent's prompt or knowledge. If you leave the box empty, the agent knows nothing about your business and simply tells visitors to call.

So put everything the agent should know right in the box: your services, hours, prices, address, and how to behave in chat. For example:

```
You are the online assistant for Acme Dental in Leeds.
Open Mon-Fri 9am-5pm. A check-up is 45 pounds, a clean is 60 pounds.
Free parking on Oak Lane. Keep replies under two sentences.
If someone wants to book, tell them to call us.
```

**Dashboard:** on the **Web Agent** page, pick the number and click **Set up agent**. Write the instructions in the box and save - a live counter shows how much room you have.

<Note>
  This box controls **web chat only**. It does not change your phone calls (they use their own prompt) and it does not change your [SMS agent](/sms/sms-agent) (which has its own `sms_prompt`). Each channel is independent.
</Note>

There is a limit of about **5,000 tokens** (~20,000 characters). The dashboard shows a live counter and the engine enforces the same cap, so a very long prompt is rejected rather than slowing every reply.

## Set it up with the API

You can manage the web agent per number from the API instead of the dashboard - useful for a platform onboarding many websites. Set `web_prompt` with a PATCH:

```bash
curl -X PATCH https://api.nixflex.com/v1/phone-numbers/+447446466847 \
  -H "Authorization: Bearer KEY_ID:KEY_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "web_prompt": "You are the online assistant for Acme Dental. Open Mon-Fri 9am-5pm. A check-up is 45 pounds. If someone wants to book, tell them to call."
  }'
```

Send an empty string to clear it. The maximum is 20,000 characters. See [Update phone number](/api-reference/phone-numbers/update) for the full endpoint.

## What the web agent will and will not do

The web agent is **answer-only by design**. It will:

- Answer questions from its web instructions
- Remember the current conversation (see below)

It will **not** book, reschedule, cancel, or change appointments over web chat - even if the instructions say it can. This boundary is enforced in the engine, not left to the prompt, so it always holds. When a visitor wants to book or needs a person, the agent tells them to call the business. Voice calls (and the [SMS agent](/sms/sms-agent)) are where bookings happen.

## Memory

Each visitor's browser keeps their own conversation and sends the recent history with every message, so the agent remembers what was said earlier in the same chat (roughly the last 20 back-and-forth exchanges). Because each browser holds only its own history, two visitors chatting at the same time never see each other's messages - conversations are isolated by design. There is no shared server-side web memory, so nothing carries over between different visitors or between separate visits.

## Offering the widget to your users

If you run a platform and want to give the widget to your own end-users (each on their own website), you do not rebuild the designs - they already exist in `button.js`. You just choose which design each user gets and supply their number. Three ways:

<CardGroup cols={3}>
  <Card title="One design for all" icon="1">
    Hard-code a single `data-design` and only swap `data-number` per user. Simplest.
  </Card>
  <Card title="Let users pick" icon="2">
    Show a small design picker in your own app; write the chosen `data-design` into each user's snippet. Recommended.
  </Card>
  <Card title="Fully custom" icon="3">
    Build your own widget front-end and call `POST /v1/widget/message` directly with the user's number. Total control.
  </Card>
</CardGroup>

## Notes

- **Cost:** a chat message uses AI text usage; a call uses voice minutes (billed like any call). The greeting bubble is free.
- **One widget per page** is recommended.
- The widget script is served from `https://nixflex.com/button.js` and is safe to cache.
