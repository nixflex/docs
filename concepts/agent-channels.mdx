Batch 3 draft. A setting being accepted and returned by the API does not mean every
channel uses it. This table describes the current implementation, not new features.
**Web call** here means a visitor on your website. The owner's **Talk to your agent**
test is a separate authenticated browser-call path and uses the phone-agent setup.

## Compatibility-only fields

These remain accepted for old integrations. Saving them is not a promise of a runtime effect.

| Field | Actual meaning |
|---|---|
| `llm_model` | Does not select the running model. Platform routing and account BYO configuration are separate. |
| `fallback_message` | No current runtime consumer; not a configurable recognition-failure phrase. |
| `interruption_sensitivity` | Stored/loaded compatibility value, not an effective interruption tuning control. |
| `voice_speed` | No current speech effect; use `speaking_rate`. |
| `func_send_sms`, `func_cold_transfer` | Not runtime permission gates; use the effective SMS setting and phone transfer policy. |
| `phone_number` on an agent | Not number import/assignment; use the phone-numbers API. |

Interruption handling, backchannel filtering, speech normalization and voice fallback
are built-in voice policies, not missing API toggles. Their exact effect depends on
the active provider/route. Prompt caching does not guarantee a cache hit or savings.
Website chat uses its own model request and does not inherit the voice fallback chain.

## Defaults and scope

New API agents default to `dynamic_greeting: true`, maximum duration **300 seconds**
and silence timeout **10 seconds**. Explicit valid values win. Existing agents are
not migrated; PUT is partial. Null timers retain their existing runtime fallback.
`DELETE /v1/agents/:id` means **switch off**, not erase or detach numbers.

This documentation does not change pickup delay, ringing, model routing or actions.
