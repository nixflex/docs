Batch 3 draft. The product recognizes 15 language codes; that is not a promise that
every active speech provider, fallback or catalog voice supports all 15.

## Voice language modes

A specific agent `language` such as `en` or `ar` keeps voice replies in that
language. `multi` permits switching within the active route's supported set.
The engine uses language evidence and explicit requests; one foreign word, name,
number or email is not itself a language change. It is not request-only switching.

The current registry uses fixed-language Deepgram recognition for a fixed code,
and AssemblyAI auto-detection for multi. The backup recognition route differs.
The usable multilingual set is the intersection of product, recognition and speech
capabilities; fallback can shrink that set.

These are the engine's registered capabilities, not live provider availability.
For Korean, Polish or Russian on the current primary voice route, use an appropriate
fixed language and eligible voice. Registered fixed-language recognition covers
all 15 codes. The registered Inworld TTS-2 model covers those codes; the legacy
Cartesia fallback registry is English-only. Catalog voice eligibility, BYO configuration
and a provider failure can further limit a particular call. Unknown models do not
silently gain language permissions. Test the selected route before making promises.

## Initial language is not always the prompt language

For voice, the resolver considers: fixed agent language, supported caller preference,
known greeting language/template, recognized custom greeting text, developer prompt,
then the declared fallback (normally English, with a diagnostic finding).
Custom greetings are not automatically translated merely because they use Latin letters.

Outbound calls generate their own opener from the per-call purpose, not the inbound
welcome text. Public website voice resolves its starting context from the website
instructions and shares the agent's voice language setting.

## Website chat is different

Website text chat follows visitor-language website rules. It does not read the
agent's `language` as a voice-language lock, and it has no speech-recognition or
text-to-speech route. Do not apply the voice table as a claimed text-chat language limit.

## Names and pronunciation

`boosted_keywords` accepts at most 50 non-empty comma-separated terms in the
current API contract. Recognition providers apply those terms differently; it is not
a guarantee of recognition or pronunciation. Write business pronunciation guidance
in the relevant phone or website instructions, and verify the actual voice output.
