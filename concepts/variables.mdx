## Call-purpose variables

A single outbound call uses `dynamic_vars` with placeholders such as `{{name}}` in its required `prompt`. A voice campaign supplies each recipient as `{"phone":"+12025550101","variables":{"name":"Sam"}}`. Keep recipient variables nested; flattening them into the row changes the request shape.

Validate required input before submitting a call. Do not rely on an unresolved placeholder becoming a safe empty string. A missing name, appointment time or other required field should produce a clear review step in your application.

## Message and integration placeholders

Post-call templates and integration configuration can use their own documented placeholders, sometimes single braces. Do not assume a call-purpose double-brace placeholder works in every message or URL. Use the field's reference and test the final rendered value.

Treat values as data when constructing JSON, URLs or SQL. Escape them for the destination rather than concatenating untrusted caller text into commands. A supplied email or phone number is not proof the caller owns it.

## Saved records

Dynamic variables, call history and caller memory are different. Some context may be recorded with a call or deliberately saved through a context feature. Do not claim all supplied variables are immediately discarded or that a call-retention change erases every related record.
