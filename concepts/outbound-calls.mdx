---
title: "Outbound calls: understand purpose, admission and results"
description: "Understand Nixflex outbound call purposes, source numbers, recipient contact checks and campaign results before sending or retrying an external call request."
---

An outbound call is a request to contact a recipient. It needs an owned active agent, an eligible sending number, available account capacity and a purpose for that conversation. A purpose tells the agent why it is calling; it does not replace permission to contact the person.

## Single calls and campaigns

`POST /v1/calls` creates a single call. `agent_id`, `to_number` and `prompt` identify the assistant, recipient and purpose. An optional `from_number` chooses an eligible number; it is not a substitute for attaching one to the agent. Dynamic variables use `dynamic_vars`.

Campaigns prepare a set of recipients. Creation requests immediate launch by default; scheduled work can run automatically when due. Separate launch controls do not make creation a draft-only operation. Voice recipient rows use `phone` and a nested `variables` object. Campaign schedules and consent are distinct from creation. Previewing a contact window sends nothing and cannot authorise dispatch.

## Admission is checked at dispatch

Current contact restrictions, recipient-local hours, time-zone confidence, balance, active-state checks and capacity can refuse or hold work. Campaigns can hold affected rows while a single request returns a refusal. Read the reason rather than silently widening hours.

## A timeout is not proof of failure

Acceptance, ringing, connection and completion are different states. If a response is lost, reconcile the existing request or call before sending another one. A client wait timeout does not hang up the call. Retry only with the endpoint's documented duplicate-prevention rules.

Knowledge for outbound calls and campaigns uses the same agent-level channel switch. Inbound pre-call context is not an outbound-purpose mechanism.
