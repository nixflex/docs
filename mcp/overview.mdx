`nixflex-mcp` exposes your Nixflex account as tools an AI assistant can use. Once connected, you can say *"call Sam and confirm his Tuesday appointment"* or *"which calls failed today and why?"* and the assistant does it through your account - the same API the dashboard and the CLI use.

It runs on your machine and talks to the assistant over stdio. It sends your key
over HTTPS to the selected Nixflex API; tool results are visible to your assistant.
It is not true that your key or all data stays on your computer.

## Run 1 installation foundation — unpublished draft

The local MCP candidate is 0.3.1; CLI candidate is 0.9.1. These changes are not npm
publications. Do not copy a candidate-version install into a live dashboard yet.
Supported tools: Claude Desktop (Windows/Mac), Claude Code, Codex and Cursor.
VS Code setup is retired. Node 22+ is required for this MCP candidate. Both Windows
and macOS are release targets; automated macOS runs and a manual Mac test must pass
before launch. A workflow file alone is not evidence of a Mac pass.

Local unpublished Group 2 keeps the same 35 tool names. `list_phone_numbers` accepts
`phone_number` alone for one complete safe read, or list filters/cursor pagination.
Seven update switches are typed. See [number tools](/api-reference/phone-numbers/switches).
The local read-only compatibility adapter works with installed SDK 0.8.0; mutations
still use the SDK and Part 1a no-repeat guards. This is not an npm publication.

Run 1 safely updates existing Claude Desktop/Cursor config only; Codex and Claude
Code have tested config builders, with their user-facing installers coming in run 3.
The unpublished candidate refuses npm-mode setup. Maintainers can use the verified
unpacked artifact with `nixflex mcp setup claude --mcp-local <package-directory>`
(or `cursor`). That writes an absolute Node/entry-point launch, not a registry lookup.
See the repository's `FOUNDATION.md` for the secret-free staging smoke procedure.

After publication approval, the same builder generates this Windows environment-mode
entry (merge under `mcpServers.nixflex-staging`; the key must be in the CLIENT process
environment, not this file). This snippet is a draft, not a command to run now:

```json
{
  "command": "cmd.exe",
  "args": ["/d", "/s", "/c", "npx -y nixflex-mcp@0.3.1"],
  "env": {
    "NIXFLEX_CREDENTIAL_SOURCE": "environment",
    "NIXFLEX_BASE_URL": "https://nixflex-voice-engine-staging.up.railway.app"
  }
}
```

Mac/Linux launcher: command `npx`, args `["-y","nixflex-mcp@0.3.1"]`. Claude Desktop
is Windows/Mac only. The setup writer chooses the OS; it never inserts credentials
or arbitrary text into shell strings. Production uses `https://api.nixflex.com`
and a separate `nixflex` entry, not a staging key silently redirected to production.

Claude Desktop: `%APPDATA%\Claude\claude_desktop_config.json` (Windows) or
`~/Library/Application Support/Claude/claude_desktop_config.json` (Mac).
Cursor: `~/.cursor/mcp.json`. Cursor supports `${env:NIXFLEX_API_KEY}` interpolation;
Codex supports an `env_vars` allowlist. Support differs by client: do not reuse one
client's variable syntax everywhere. A separately opened GUI may not inherit a
terminal's environment. Never paste a real key into JSON, TOML, argv or chat.

**Legacy credentials:** the existing CLI file is plaintext, not an encrypted vault.
The MCP reads key and `base_url` together. An old unprofiled file without `base_url`
retains its documented production default; staging must have an explicit saved URL.
Named legacy profiles require their own URL. An explicit URL conflicting with the
saved URL is refused. Environment keys always require an explicit approved URL.
Only the exact production and staging origins above are allowed; redirects are refused.

**Config safety:** only a missing file may start empty. Malformed/unreadable files,
duplicate keys, conflicts, concurrent edits or an existing commented Nixflex block
that needs replacement cause refusal. Other entries/comments are retained. A changed
Nixflex entry needs confirmation after a redacted preview. Close other config editors
while setup runs. No key is copied into the client file. Restore/remove only the
specific entry when uninstalling; do not replace the entire file.

Run 2 adds the Claude Desktop bundle. Run 3 adds secure key setup and per-tool installs,
including Cursor's button. ChatGPT is **coming soon** until hosted OAuth after launch.

## Try it

For installation verification, request **“Use Nixflex get_usage only. Do not change
anything.”** Use a staging account and check the displayed API origin. This does
not require a real call, SMS or payment. The examples below are account actions,
not installation tests; review and approve them separately.

- "List my Nixflex agents."
- "Show my last 10 calls and tell me which ones ended badly and why."
- "What do we know about +447453573770 on +447450307843? Update the preference to prefers Tuesday mornings."
- "Set the silence hang-up on the Ringback agent to 12 seconds."
- "Import these customers onto +447450307843:" followed by a pasted list.
- "Have the Reception agent call +447700900123 and confirm the appointment on Tuesday at 11."

The last one places a real call and spends credit - the tool description says so, and the assistant will normally ask before running it.

## Tools

Every tool is one API call. Names are `snake_case`; results come back as JSON.

| Area | Tools |
|---|---|
| Account | `get_usage`, `rotate_api_key` |
| Agents | `list_agents`, `get_agent`, `create_agent`, `update_agent`, `delete_agent` |
| Calls | `create_call`, `list_calls`, `get_call`, `delete_call` |
| Campaigns | `create_campaign`, `launch_campaign` |
| Phone numbers | `list_phone_numbers`, `import_phone_number`, `update_phone_number`, `delete_phone_number`, `set_number_monitor`, `set_number_web_calls` |
| Caller context | `get_caller_context`, `set_caller_context`, `import_caller_context`, `delete_caller_context` |
| SMS | `send_sms`, `create_sms_campaign`, `launch_sms_campaign`, `list_sms_campaigns`, `get_sms_campaign`, `delete_sms_campaign` |
| Webhooks | `set_webhook`, `get_webhook`, `delete_webhook` |
| Bring your own | `get_byo_config`, `set_byo_config`, `delete_byo_config` |

`create_agent`, `update_agent`, `update_phone_number`, `import_phone_number`, `create_campaign`, `create_sms_campaign` and `set_byo_config` take a `fields` object passed straight to the API, so every field on the API reference pages is available.

## Safety rails

Draft Part 1a (unpublished): the local server disables SDK retries and retries only read-only tools once. Changes never automatically repeat after lost replies, network errors, 429 or 5xx. Unknown changes return `outcome: unknown` and `safe_to_retry: false`; check before retrying. This protection also works with the installed Node SDK 0.8.0, without waiting for an npm publication.

Area 3 batch 1 candidate: `create_call.variables` is translated to `dynamic_vars`
for `{{name}}` placeholders. Summary direction comes from the API's
`call_direction`/`call_type` (legacy `direction` fallback), never guessed from an
absent field. Null/false/zero values stay honest; no transcript is added to lists.
See [client safety](/api-reference/calls/client-safety). Bundles/install work is
parked; this does not claim your installed server has been upgraded.

- **Nothing destructive runs without `confirm: true`.** `delete_*` tools and `rotate_api_key` return a preview of what would happen and change nothing until the assistant calls again with `confirm: true` - which a well-behaved assistant only does after asking you.
- **There is no delete-all MCP tool.** Do not infer account-deletion permission from MCP access.
- **Spending tools say so.** `create_call`, `create_campaign`, `send_sms` and `create_sms_campaign` state in their descriptions that they spend credit.
- **Lists are summaries.** `list_calls` returns one line per call (status, duration, summary, sentiment); `get_call` returns the full transcript for one call.
- **Credentials are destination-bound.** The resolved key is sent only to its selected approved API origin. Tool results are shared with the assistant; a plaintext config is not secure key storage.
- **The tool list is a contract.** A test in the package starts the real server over stdio and pins all 35 tool names, descriptions and schemas - a tool cannot vanish or change shape without failing the build.

## What it is not

It manages your **account** - agents, numbers, calls, customers. It does not sit inside a live call; the agent on the phone does not use these tools. Letting the phone agent call *external* MCP servers mid-call is a separate feature and is not available yet.

## Troubleshooting

| Symptom | Fix |
|---|---|
| **nixflex** does not appear in the connectors list | The app reads its config on launch - fully quit it (system tray → Quit) and reopen. Check the JSON is valid. |
| Missing key or explicit API URL | Supply the full key and approved URL in the client process environment, or inspect your existing legacy file locally. Never send the file or key to support. |
| Destination conflict | Keep the key with its own saved URL; create a separate staging entry. Never change the URL just to make an error disappear. |
| npm candidate not published | Use the maintainer's verified local artifact; do not fall back to the old npm version. |
| "Key rejected" | The key must be the full pair `nxf_xxx:nxfs_xxx`. |
| Anything else | Claude Desktop writes the server's log to `%APPDATA%\Claude\logs\mcp-server-nixflex.log` (Windows) or `~/Library/Logs/Claude/mcp-server-nixflex.log` (macOS). The server logs to stderr only - stdout is the protocol. |
