title: "Pre-call hook: supply context before an inbound call"
description: "Configure a Nixflex inbound pre-call hook, verify its request and return caller context or an explicit refusal within the fail-open timing budget."
---

Consult your service before an incoming call begins. This hook can supply caller context or explicitly reject a call; it deliberately allows calls when the hook fails.

Using the dashboard? See [the business guide](/guides/business/integrations).

## Prerequisites

Keep the account credential in `NIXFLEX_API_KEY` on your server. Examples copied from the reviewed kit candidates need Node/CLI 0.10.0 or Python 0.3.0, which are not yet published. Use cURL until the matching release is available. Set all identifiers and the API host for the intended account and environment. Use an HTTPS receiver and verify the signing header before using supplied caller information.

## 1. Read the hook configuration

<CodeGroup>

```bash cURL
curl --request GET \
  --url "https://api.nixflex.com/v1/integrations/precall/number/%2B12025550123" \
  --header "Authorization: Bearer $NIXFLEX_API_KEY"
```

```javascript Node
import { Nixflex } from 'nixflex';
const c = new Nixflex({apiKey:process.env.NIXFLEX_API_KEY,baseUrl:'https://api.nixflex.com',maxRetries:0});
const result = await c.integrations.get("precall", "+12025550123");
// Keep private responses out of logs and AI conversations.
```

```python Python
import os
from nixflex import Nixflex
with Nixflex(api_key=os.environ["NIXFLEX_API_KEY"], base_url="https://api.nixflex.com", max_retries=0) as c:
    result = c.integrations.get('precall', '+12025550123')
```

```powershell CLI (PowerShell)
nixflex integrations get precall '+12025550123' --json --base-url "https://api.nixflex.com"
```

</CodeGroup>

## 2. Choose the scope

A configured number URL wins over the agent URL; otherwise the agent setting applies. If neither is configured, this hook does not run. Use the documented number or agent integration route, not an outbound call-purpose field.

## 3. Verify the request

The POST body contains `event:call.inbound`, `from`, `to` and `call_id`. Current code attaches a signature when a signing value is available. Verify exact raw bytes using the [signature helper](/advanced/webhooks). Reject unverified requests in your service; do not accept them because the caller data looks plausible.

## 4. Return a clear decision

A successful JSON response containing `{"action":"reject","reason":"account_inactive"}` explicitly refuses the call. Other valid responses allow it. A permitted `caller` object can supply validated current-call context. Invalid context fields are ignored individually; do not assume every supplied field was accepted.

## 5. Design for fail-open

The whole request and reply-body read share a five-second budget. Timeout, network failure, unsuccessful HTTP or invalid/oversized JSON causes the call to proceed. Reply bodies are limited to 64 KiB. Protect sensitive downstream actions with their own authorisation, because this hook is not a fail-closed security boundary.

## Example response

Illustrative receiver reply: `{"action":"accept","caller":{"name":"Sam"}}`. This provides call context; later learning and call records follow their own policies, so it is not a promise that no related information will ever be stored.

## Errors and limits

| Condition | Engine behaviour |
| --- | --- |
| Explicit reject in successful JSON | Refuse the call. |
| Timeout/non-success/invalid JSON | Proceed under fail-open policy. |
| Invalid caller field | Drop that field rather than reject the whole call. |
| No configured URL | Proceed without the hook. |
| Outbound call | This inbound hook is not used as its purpose mechanism. |
