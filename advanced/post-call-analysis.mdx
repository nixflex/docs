Collect a small set of useful answers from completed conversations and send confirmed results into your workflow.

Using the dashboard? See [the business guide](/guides/business/call-history).

## Prerequisites

Keep the account credential in `NIXFLEX_API_KEY` on your server. The supplied client candidates are Node/CLI 0.11.0 and Python 0.4.0. Use the matching reviewed archive; a registry install alone does not establish that these methods are available. See the [client release guidance](/sdks/ecosystem). Set all identifiers and the API host for the intended account and environment. Choose the business questions the call should answer and how your system represents unknown values.

## 1. Read the agent configuration

Node and Python below use their standard HTTP clients. Keep `NIXFLEX_API_KEY` on the server. The CLI examples require a kit version supporting the command; see [release status](/sdks/ecosystem). No example retries a mutation automatically.

<CodeGroup>

```bash cURL
curl --fail-with-body --request GET \
  --url "https://api.nixflex.com/v1/agents/agent_example" \
  --header "Authorization: Bearer $NIXFLEX_API_KEY"
```

```javascript Node
const response = await fetch('https://api.nixflex.com/v1/agents/agent_example', {
  method: 'GET',
  headers: { Authorization: `Bearer ${process.env.NIXFLEX_API_KEY}` },
});
const result = await response.json();
if (!response.ok) throw new Error(JSON.stringify(result));
console.log(result);
```

```python Python
import os, json
from urllib.request import Request, urlopen

request = Request(
    'https://api.nixflex.com/v1/agents/agent_example',
    method='GET',
    headers={'Authorization': 'Bearer ' + os.environ['NIXFLEX_API_KEY']},
)
with urlopen(request, timeout=30) as response:
    print(json.load(response))
```

```powershell CLI (PowerShell)
nixflex agents get agent_example --json --base-url https://api.nixflex.com
```

## 2. Define focused fields

Use the documented `data_extraction_fields` shape in the agent contract. Name each field clearly, choose a supported type and explain what counts as evidence. Avoid requesting information the conversation never asks for.

## 3. Keep unknown answers unknown

Define downstream handling for absent, null or uncertain results. Do not turn a missing answer into false, zero or customer consent. A generated summary can be incomplete or mistaken.

## 4. Wait for current results

Call completion, analysis and event delivery can finish separately. Read the call or process verified events; use bounded polling rather than promising every field appears within a fixed number of seconds.

## 5. Validate business actions separately

Review important extracted facts against the conversation. Use the calendar, message or transfer result to confirm an action; analysis saying “booked” is not independent proof the calendar write succeeded.

## Example response

The call record can include summary and structured analysis when available. Preserve the published schema and nullable fields; do not invent a guaranteed analysis object for every call.

## Errors and limits

| Condition | Handling |
| --- | --- |
| Analysis absent | Wait or show unavailable; do not create an answer. |
| Contradictory conversation | Route important decisions for review. |
| Retention removes source data | Respect current availability. |
| External action mentioned | Verify its actual operation result. |
