Manage the account connection and verify how it behaves during real work. Configuration success and runtime success are separate.

Using the dashboard? See [the business guide](/guides/business/your-own-model).

## Support scope

The account service and storage interfaces shown here are existing compatibility interfaces, outside the supported public API inventory. They describe an existing integration dependency, not a new public API commitment. Use the signed-in dashboard for new setup; confirm support before building a new dependency on these routes or older kit commands.

## Prerequisites

Keep the account credential in `NIXFLEX_API_KEY` on your server. Examples copied from the reviewed kit candidates need Node/CLI 0.10.0 or Python 0.3.0, which are not yet published. Use cURL until the matching release is available. Set all identifiers and the API host for the intended account and environment. Use authorised connection details and keep all secrets out of examples.

## 1. Read the safe configuration

Node and Python below use their standard HTTP clients. Keep `NIXFLEX_API_KEY` on the server. The CLI examples require a kit version supporting the command; see [release status](/sdks/ecosystem). No example retries a mutation automatically.

<CodeGroup>

```bash cURL
curl --fail-with-body --request GET \
  --url "https://api.nixflex.com/v1/account/llm" \
  --header "Authorization: Bearer $NIXFLEX_API_KEY"
```

```javascript Node
const response = await fetch('https://api.nixflex.com/v1/account/llm', {
  method: 'GET',
  headers: { Authorization: `Bearer ${process.env.NIXFLEX_API_KEY}` },
});
const result = await response.json();
if (!response.ok) throw new Error(JSON.stringify(result));
console.log(result);
```

```python Python
import os, json
from urllib.request import Request, urlopen

request = Request(
    'https://api.nixflex.com/v1/account/llm',
    method='GET',
    headers={'Authorization': 'Bearer ' + os.environ['NIXFLEX_API_KEY']},
)
with urlopen(request, timeout=30) as response:
    print(json.load(response))
```

```powershell CLI (PowerShell)
nixflex llm get --json --base-url https://api.nixflex.com
```

</CodeGroup>

## 2. Review compatibility

The connection expects a compatible streaming chat-completions protocol and tool calling. Use a public HTTPS endpoint and model identifier from your authorised connection. The saved connection is account-scoped; do not promise it independently replaces every internal task or channel.

## 3. Save and verify

PUT `/v1/account/llm` with `endpoint`, `model` and write-only `api_key`. A completion/tool probe checks the connection before saving. Use your own approved endpoint, such as `https://model.example.com/v1`, with real credentials stored privately. Probe success does not guarantee future availability.

## 4. Test calls and fallback

Test short replies, a tool action and a slow/unavailable endpoint. Runtime fallback can change which processing path served the call. Do not promise uninterrupted audio, fixed savings or zero additional charges from a successful configuration test.

## 5. Disconnect deliberately

DELETE `/v1/account/llm` clears the connection for future work. Inspect actual call and billing outcomes; third-party model charges and Nixflex charges are separate.

## Example response

GET returns a safe saved-configuration projection without the full secret. Preserve its enabled and verification state; it is not a live service-health guarantee.

## Errors and limits

| Condition | Handling |
| --- | --- |
| Verification fails | Correct the endpoint, permissions or credentials before saving. |
| Runtime dependency fails | Read the call’s actual fallback or unavailable state. |
| Secret changed externally | Update the saved connection and test again. |
| Unknown save response | Read the current configuration before repeating it. |
| Pricing or retention | Use current Billing and the policy for the actual path. |
