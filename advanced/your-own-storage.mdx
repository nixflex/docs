Manage the account connection and verify how it behaves during real work. Configuration success and runtime success are separate.

Using the dashboard? See [the business guide](/guides/byo-storage-r2).

## Support scope

The account service and storage interfaces shown here are existing compatibility interfaces, outside the supported public API inventory. They describe an existing integration dependency, not a new public API commitment. Use the signed-in dashboard for new setup; confirm support before building a new dependency on these routes or older kit commands.

## Prerequisites

Keep the account credential in `NIXFLEX_API_KEY` on your server. The supplied client candidates are Node/CLI 0.11.0 and Python 0.4.0. Use the matching reviewed archive; a registry install alone does not establish that these methods are available. See the [client release guidance](/sdks/ecosystem). Set all identifiers and the API host for the intended account and environment. Use authorised connection details and keep all secrets out of examples.

## 1. Read the safe configuration

Node and Python below use their standard HTTP clients. Keep `NIXFLEX_API_KEY` on the server. The CLI examples require a kit version supporting the command; see [release status](/sdks/ecosystem). No example retries a mutation automatically.

<CodeGroup>

```bash cURL
curl --fail-with-body --request GET \
  --url "https://api.nixflex.com/v1/account/storage" \
  --header "Authorization: Bearer $NIXFLEX_API_KEY"
```

```javascript Node
const response = await fetch('https://api.nixflex.com/v1/account/storage', {
  method: 'GET',
  headers: { Authorization: `Bearer ${process.env.NIXFLEX_API_KEY}` },
});
const result = await response.json();
if (!response.ok) throw new Error(JSON.stringify(result));
console.log(result);
```

```python Python
import os, json
from urllib.request import Request, urlopen

request = Request(
    'https://api.nixflex.com/v1/account/storage',
    method='GET',
    headers={'Authorization': 'Bearer ' + os.environ['NIXFLEX_API_KEY']},
)
with urlopen(request, timeout=30) as response:
    print(json.load(response))
```

```powershell CLI (PowerShell)
nixflex storage get --json --base-url https://api.nixflex.com
```

</CodeGroup>

## 2. Prepare the bucket

Choose an authorised S3-compatible bucket, HTTPS endpoint and region. Give the credential only the required object permissions, including the verification probe and its cleanup. This requires a reachable connection; an air-gapped bucket cannot receive remote uploads.

## 3. Save and verify

PUT `/v1/account/storage` with `bucket`, `access_key`, `secret_key`, and the appropriate `endpoint` and `region`. The secret is write-only. The save probe checks access before committing settings; a successful probe is not proof every future upload will succeed.

## 4. Handle fallback and playback

The recording path verifies uploaded objects. If the customer bucket fails, fallback to standard Nixflex storage can be attempted and the call can record a storage failure event. Both paths can fail. Therefore this setting alone does not promise exclusive regional residency or that no recording can ever be lost.

## 5. Manage your own lifecycle

Customer-bucket recordings are shown as customer storage rather than a permanent public audio URL. Manage your own authorised access and object retention. DELETE `/v1/account/storage` changes future storage configuration; it does not delete existing bucket files.

## Example response

GET returns a safe saved-configuration projection without the full secret. Preserve its enabled and verification state; it is not a live service-health guarantee.

## Errors and limits

| Condition | Handling |
| --- | --- |
| Verification fails | Correct the endpoint, permissions or credentials before saving. |
| Runtime dependency fails | Read the call’s actual fallback or unavailable state. |
| Secret changed externally | Update the saved connection and test again. |
| Unknown save response | Read the current configuration before repeating it. |
| Pricing or retention | Use current Billing and the policy for the actual path. |
