```http
Authorization: Bearer KEY_ID:KEY_SECRET
```

The values above are placeholders. Copy the full credential through the Owner's **API key** dashboard screen. The current dashboard manages one shared account key; it does not create a separate restricted key for each teammate or application.

## Keep the key server-side

Store it in a secret manager or environment variable such as `NIXFLEX_API_KEY`. Call the API from your server. Do not embed it in a website widget, URL, mobile bundle, screenshot or repository. Avoid logging request headers or full error objects that include them.

| Action | Who or what it changes |
| --- | --- |
| Invite a teammate | Adds personal login access under an organisation role |
| Reveal the shared API key | Owner dashboard action |
| Rotate the shared key | Replaces API authentication; old consumers need the new credential |
| Remove a teammate | Revokes their membership, not copies of a shared key held elsewhere |
| Use a signing credential | Verifies incoming events; not automatically the same secret as API access |

## Rotate deliberately

Inventory applications using the key, prepare their secret configuration, rotate from the Owner's flow and update the consumers. Do not assume a grace period keeps the old credential valid. Recheck a read-only request after the change and investigate 401 responses without printing either key.

## Signed requests are separate

Organisation signing uses a separate signing secret. Retrieve it through the documented organisation-server-key operation or an Owner personal session; other personal roles cannot retrieve it. Use it to verify incoming request bytes, and keep it out of logs and automatic tool output. API-key rotation does not change that separate signing secret. See [webhook verification](/advanced/webhooks).

## Handle refusals

Check that the full key and target environment match. An account can also be inactive or temporarily unavailable. Read the error code and message; repeated retries cannot fix an invalid credential or role decision.
