<div className="nxf-important">

**The important part**

- The replacement carrier account must contain the exact number and match its current carrier.
- The tool accepts only `phone_number`, `provider` and `confirm`; never add secrets to those arguments.
- Private credentials are read only after `confirm: true`; missing configuration sends no request.
- An unknown routing outcome needs checking before retry. A pending-save completion uses exactly the same private details.

</div>

## Before you start

Use the reviewed, unpublished 96-tool MCP 0.5.0 candidate with `update_phone_number_credentials`. Have the local client administrator privately configure only the number’s current carrier pair. The tool uses organisation authority; dashboard roles do not narrow the shared key.

## Complete the task

<Steps>

<Step title="Choose the existing number and carrier">

Inspect the owned number and confirm its current provider. This action keeps its agent, instructions, switches, integrations and history; it does not buy, reimport or switch the number to another carrier.

</Step>

<Step title="Supply the selected pair privately">

For `provider: twilio`, the process needs `NIXFLEX_TWILIO_SID` and `NIXFLEX_TWILIO_TOKEN`. For `provider: telnyx`, it needs `NIXFLEX_TELNYX_API_KEY` and `NIXFLEX_TELNYX_CONNECTION_ID`. These are variable names, not values to paste. Use the private launcher or secret manager for your client.

</Step>

<Step title="Check the client’s configuration route">

Codex can forward the selected variable names; Cursor can use environment references. Follow the relevant client guide. The Desktop bundle exposes only the Nixflex API-key field, with no carrier-secret fields. If its host cannot privately supply the pair, use the supported dashboard, CLI or SDK workflow.

</Step>

<Step title="Review and confirm one update">

Show the exact number and current provider to the person approving the change. Call `update_phone_number_credentials` with those fields and `confirm: true`. Keep client approval enabled and never ask the assistant to inspect or print the environment.

</Step>

<Step title="Read the result and complete the stated follow-up">

The server still checks number ownership, account state and pending operations. A replacement can change routing and may require fresh number verification. Follow the returned result, verify the intended channels and avoid automatic retries.

</Step>

</Steps>

## Read the result

| What you see | What it means | What to do |
| --- | --- | --- |
| `confirmation_required`, `sent: false` | The update was not sent. | Review the number and change before confirmation. |
| `credentials_not_configured` | The selected private pair is missing; no request was sent. | Have the administrator fix private setup without exposing values. |
| `carrier_outcome_unknown` | The carrier outcome is uncertain. | Contact support before retrying. |
| `credential_save_pending` | A pending save permits a specific completion path. | Complete manually with exactly the same private details. |
| Update confirmed | The existing number has a saved update result. | Follow verification guidance and test the channels you use. |
