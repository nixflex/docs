Build your integration around one read first, then add a workflow with clear outcomes.

1. Store the full organisation API key in your server's secret store. Read [authentication](/authentication).
2. Follow the [quickstart](/quickstart) to read an owned resource without changing it.
3. Handle [errors](/guides/developer/errors), [pagination](/guides/developer/pagination), [rate limits](/guides/developer/rate-limits) and [duplicate work](/guides/developer/idempotency).
4. Receive [signed webhooks](/advanced/webhooks), verifying the exact raw bytes before parsing JSON.

## Before sending work

Use an owned agent and number, verify recipient permission, and check the route's retry rules. An unknown network result does not prove a call or message was never sent. Store returned identifiers and reconcile before repeating a mutation.

Node/CLI 0.10.0 and Python 0.3.0 examples describe current candidate capabilities. Check [kit release status](/sdks/ecosystem) before installing or relying on a new command. Use cURL when a corresponding package release is unavailable.

Prefer the dashboard? Start with [business setup](/business) and its five-step task guides.
