title: "In-call SMS: control texts sent during Nixflex phone calls"
description: "Configure the Nixflex in-call text switch, request permitted messages and handle booking confirmations without confusing this setting with other SMS workflows."
---

Allow or prevent texts requested during a telephone call, including supported booking-confirmation texts.

Using the dashboard? See [the business guide](/guides/business/call-actions).

## Prerequisites

Keep the account credential in `NIXFLEX_API_KEY` on your server. Examples copied from the reviewed kit candidates need Node/CLI 0.10.0 or Python 0.3.0, which are not yet published. Use cURL until the matching release is available. Set all identifiers and the API host for the intended account and environment. Replace `agent_example` with an owned agent. This update changes future agent behaviour.

## 1. Read the current settings

Read the agent and any relevant number override before changing shared behaviour. A prompt alone cannot grant an action capability.

## 2. Save the intended setting

Node and Python below use their standard HTTP clients. Keep `NIXFLEX_API_KEY` on the server. The CLI examples require a kit version supporting the command; see [release status](/sdks/ecosystem). No example retries a mutation automatically.

<CodeGroup>

```bash cURL
curl --fail-with-body --request PUT \
  --url "https://api.nixflex.com/v1/agents/agent_example" \
  --header "Authorization: Bearer $NIXFLEX_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{"incall_sms_enabled":true}'
```

```javascript Node
const response = await fetch('https://api.nixflex.com/v1/agents/agent_example', {
  method: 'PUT',
  headers: { Authorization: `Bearer ${process.env.NIXFLEX_API_KEY}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({"incall_sms_enabled":true}),
});
const result = await response.json();
if (!response.ok) throw new Error(JSON.stringify(result));
console.log(result);
```

```python Python
import os, json
from urllib.request import Request, urlopen

request = Request(
    'https://api.nixflex.com/v1/agents/agent_example',
    method='PUT',
    headers={'Authorization': 'Bearer ' + os.environ['NIXFLEX_API_KEY'], 'Content-Type': 'application/json'},
    data='{"incall_sms_enabled":true}'.encode('utf-8'),
)
with urlopen(request, timeout=30) as response:
    print(json.load(response))
```

```powershell CLI (PowerShell)
nixflex agents update agent_example --set incall_sms_enabled=true --json --base-url https://api.nixflex.com
```

</CodeGroup>

This agent switch governs in-call texts. It is independent of `post_call_sms_enabled`, the number’s SMS auto-reply switch and explicit API sends.

## 3. Write a narrow instruction

Use a specific instruction such as “After a successful booking, offer a text with its confirmed time.” A `[SEND_SMS: message]` tag requests an action; it is not a delivery receipt. A disabled gate prevents this path even if a prompt asks for it.

## 4. Test the actual outcome

Use an approved test recipient and verify the recorded send outcome. Check both an enabled and disabled configuration. Calendar success, SMS acceptance and handset delivery are separate outcomes.

## 5. Review the result

Read back configuration after a confirmed update. Inspect the call and action result separately; a saved switch is not proof a real business action succeeded. If a write response is lost, reread the object before repeating it.

## Example response

The agent update returns the safe saved agent projection. Check the intended fields in a fresh [agent read](/api-reference/agents/get); call outcomes are separate records.

## Errors and limits

| Condition | Handling |
| --- | --- |
| In-call SMS off | This path does not send; other SMS paths have their own controls. |
| Missing eligible sender/recipient | Do not promise a text was sent. |
| Contact restriction | Respect the refusal. |
| Booking text fails | Keep the booking result distinct from the text result. |
