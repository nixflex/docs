## Prerequisites

Keep `NIXFLEX_API_KEY` private on the server and choose the matching API host. Use owned identifiers; SDK and CLI examples need the [exact reviewed candidate](/sdks/ecosystem). Replace `agent_example` with an owned agent. This update changes future agent behaviour.

## 1. Read the current settings

Read the agent and any relevant number override before changing shared behaviour. A prompt alone cannot grant an action capability.

## 2. Save the intended setting

Node and Python below use their standard HTTP clients. Keep `NIXFLEX_API_KEY` on the server. The CLI examples require a kit version supporting the command; see [release status](/sdks/ecosystem). No example retries a mutation automatically.

The agent’s `transfer_type` selects `cold` or `warm`. Review the permitted transfer destination and existing transfer controls before enabling a handoff. An optional `transfer_whisper` supplies a static briefing for a warm transfer.

## 3. Write a narrow instruction

Explain the business situations that need a person and the approved destination. A warm transfer can brief the recipient before connection; a cold transfer does not provide the same briefing. Do not say the person answered until the handoff result confirms it.

## 4. Test the actual outcome

Test an answered destination, busy/unanswered destination and caller hangup. Return-to-agent and fallback behaviour depend on the active transfer path and observed result; do not assume every failure reconnects the AI or retries an alternative person.

## 5. Review the result

Read back configuration after a confirmed update. Inspect the call and action result separately; a saved switch is not proof a real business action succeeded. If a write response is lost, reread the object before repeating it.

## Example response

The agent update returns the safe saved agent projection. Check the intended fields in a fresh [agent read](/api-reference/agents/get); call outcomes are separate records.

## Errors and limits

| Condition | Handling |
| --- | --- |
| Destination unavailable | Follow the observed failure path; do not promise reconnection. |
| Caller hangs up during handoff | Stop new business actions. |
| Warm briefing | Static text or generated context is not guaranteed to arrive instantly. |
| Costs and recordings | Depend on the actual connected legs and recording source. |
| Website visitor | Built-in telephone transfer is unavailable. |
