A connected Google Calendar lets an eligible agent check appointment availability and request booking changes. Connect it through the signed-in [business setup guide](/guides/business/google-calendar); the public integration-settings API does not provide a substitute OAuth connection route.

## How the calendar is used

The connection stores authorisation for the selected business calendar. The booking path generates candidate appointments from working hours, subtracts existing busy times and uses the agent's time zone. Built-in defaults are 30-minute appointments, 09:00–17:00, Monday–Friday unless the saved configuration overrides them. Confirm the actual configuration before describing those hours to a customer.

The agent can check availability, book, find an existing appointment, reschedule or cancel through the supported calendar tools. Lookup can require the attendee's email and exact date/time when several matches exist. A self-reported email is not verified identity, so define appropriate business checks for sensitive changes.

## Confirmation and real outcomes

`require_booking_confirmation` can require a read-back before a mutation. The effective number/agent setting applies. A time can still become unavailable after an earlier lookup; only a successful write confirms the appointment.

Ambiguous or nonexistent local times must be clarified. The engine checks the call is still live before a new write, but a lost network response does not prove an external calendar change was rolled back. Reconcile the calendar instead of blindly repeating it.

## Texts and disconnection

An in-call confirmation text needs the separate in-call SMS gate and an eligible sender. A calendar update can succeed while the text fails. Disconnecting authorisation prevents future use; it does not cancel appointments already created or erase copies held by the calendar.
