The `[SEND_SMS:]` tag sends a text message to the caller from your Twilio number. Useful for booking confirmations, links, addresses, payment links, or anything easier to read than hear.

## Turning it on
In-call SMS is controlled by one setting on the agent, `incall_sms_enabled`.

| Setting | What happens |
|---|---|
| **On** | The agent can text the caller during the call, and booking confirmations are texted automatically. Standard SMS rates apply. |
| **Off** | No texts are sent at all - no mid-call text, no booking confirmation text. The agent confirms every detail out loud instead. |

With the setting off, the agent is never taught the `[SEND_SMS:]` action, so it does not offer a text. If a prompt uses the tag anyway, the engine blocks the send and the agent tells the caller the text did not go out - turn the setting on if you want texting.

New agents start with it **off**. Agents created before this setting existed were switched **on**, so their behaviour did not change.

Turn it on in the dashboard (agent, then Functions, then In-Call SMS) or through the API:

```bash
curl -X PUT https://api.nixflex.com/v1/agents/agent_125207e452f8714a \
  -H "Authorization: Bearer KEY_ID:KEY_SECRET" \
  -H "Content-Type: application/json" \
  -d '{ "incall_sms_enabled": true }'
```

<Note>
  This setting covers mid-call texts and booking confirmation texts. Post-call SMS is a separate setting, `post_call_sms_enabled` - see below.
</Note>

## Syntax

    [SEND_SMS: Your text message goes here]

Everything between the colon and the closing bracket is the SMS body. The agent continues the conversation naturally — the SMS is sent in the background.

## Example

> *Caller:* "Can you send me the address?"
>
> *Agent:* "Sure, sending it now. [SEND_SMS: Acme Dental, 12 High Street, Croydon CR0 1AB. See you Tuesday at 2pm.]"

## When to use
The setting grants permission; your prompt decides when and what to text. With `incall_sms_enabled` on, add a line such as: "If the caller asks to receive any call information by text, send it using [SEND_SMS: message]."


Tell the agent in its `system_prompt` when to text the caller. Example snippet from a system_prompt:

    ACTIONS
    - Send the address by SMS if asked where you are: [SEND_SMS: 12 High Street, Croydon CR0 1AB]
    - After booking, text confirmation: [SEND_SMS: Your appointment with Acme Dental is confirmed.]
    - Send the payment link when collecting deposits: [SEND_SMS: Pay your deposit here: https://pay.example.com/abc]

<Note>
  Booking confirmations follow the same setting. With `incall_sms_enabled` on, a confirmed booking is texted to the caller automatically. With it off, the agent confirms the day, time and details out loud and no text is sent.
</Note>

## Post-call SMS

Separate from the mid-call tag, Nixflex can automatically send a text after a call ends. There are two ways to set it up, depending on your structure.

### Agent-level template

Set a `post_call_sms_template` on the agent (with `post_call_sms_enabled: true`) via the [Update agent](/api-reference/agents/update) endpoint. It then fires automatically after every answered call on that agent - both inbound and outbound - on numbers added through the dashboard.

<Note>
  The agent-level template applies only to numbers added through the dashboard. Numbers imported via the API never receive it - one agent often serves many separate businesses, and an agent-level text must never reach another business's customers. For API-imported numbers, send post-call SMS yourself from the webhook (see below).
</Note>

```bash
curl -X PUT https://api.nixflex.com/v1/agents/agent_125207e452f8714a \
  -H "Authorization: Bearer KEY_ID:KEY_SECRET" \
  -H "Content-Type: application/json" \
  -d '{ "post_call_sms_enabled": true, "post_call_sms_template": "Thanks for speaking with us today, {caller_name}. We will be in touch." }'
```

Personalise the message with variables, filled in from the call:

| Variable | Value |
|---|---|
| `{caller_name}` | The caller's name, if captured during the call |
| `{business_name}` | The agent's name |
| `{call_summary}` | A short summary of the call |
| `{agent_name}` | The agent's name |

<Tip>
  Write the template so it reads naturally for both inbound and outbound calls if the agent handles both. "Thanks for calling" only fits inbound - prefer neutral wording like "Thanks for speaking with us today", or use variables to keep it flexible.
</Tip>

### Your own, from the webhook

If one agent serves many separate businesses, a single agent-level template would send the same text to every business's customers. In that case, send the post-call SMS yourself: receive the [webhook](/advanced/webhooks) after each call and send a message tailored to that business from its own number, using the [Send SMS API](/api-reference/sms/send). Each business gets its own wording, branding, and number, with full control over when a message goes out.

### When it sends

Post-call SMS sends once, shortly after the call ends, from the business's own Twilio number. It is skipped when the call reached voicemail, when no template is configured, or when the caller's number is not available - so messages only go out when they make sense.

## Inbound SMS replies

When a caller replies to a Nixflex SMS, the agent responds automatically using its `system_prompt`. The agent's regular instructions handle the reply — there is no separate reply-handling system.

**Key principle:** if you send SMS that customers might reply to, include the relevant context in the agent's `system_prompt` so the agent knows how to handle replies, questions, or follow-up calls about that SMS.

## Sending SMS via the API

Outside of a live call, send SMS programmatically using the `message` field. See [Send SMS API](/api-reference/sms/send).

## Bulk SMS campaigns

For sending the same message to many numbers, use [SMS campaigns](/sms/sms-campaigns).

## Compliance

<Warning>
  **Your carrier, your registration.** Messages are sent through your own carrier account and numbers, so that carrier's rules apply - for example, US-bound messages require A2P 10DLC registration on your account before carriers accept them.

  You are responsible for SMS compliance: opt-in records, opt-out handling (STOP/HELP keywords), and timing restrictions. Nixflex provides the infrastructure; the compliance obligation stays with you.
</Warning>

## Twilio billing

SMS is sent through your own carrier account (the same one attached to the phone number). The carrier charges per message at their standard rates. Nixflex does not mark up SMS pricing.
