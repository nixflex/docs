## Authentication

Send Authorization: Bearer KEY_ID:KEY_SECRET using the owning account’s server-side API credential. API keys have Owner authority. With a personal dashboard session, Owner, Admin and Member may read visible knowledge; membership is checked before and after the read. Personal dashboard visibility can hide API-origin agents.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `kb` (path) | string | Yes | None | Opaque identifier. Keep it as a string. Format: uuid. |
| `id` (path) | string | Yes | None | Opaque identifier. Keep it as a string. Format: uuid. |

Do not send a request body.

This GET projects legacy normalization and repairs without saving them. Piece IDs are stable within the draft. Explicit save or accept persists the same repair through the write path. Keep the returned data.edit_revision before editing or accepting. Older deployments may differ; check the rollout for your environment.

## Example request

These examples target Node/CLI 0.11.0 and Python 0.4.0; confirm the installed version supports the method before use. The cURL tab uses Bash; CLI uses PowerShell. Python shows sync usage; AsyncNixflex uses the same JSON methods with async with and await. Set the staging credential in `NXF_STAGING_KEY` and the owned path identifiers shown below in environment variables. Keep private responses out of logs.

<RequestExample>

```bash cURL (Bash)
curl --request GET \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/knowledge-bases/$(node -p 'encodeURIComponent(process.env.NXF_KNOWLEDGE_BASE_ID)')/drafts/$(node -p 'encodeURIComponent(process.env.NXF_RESOURCE_ID)')" \
  --header "Authorization: Bearer $NXF_STAGING_KEY"
```

```javascript Node
import { Nixflex } from 'nixflex';
const c = new Nixflex({apiKey:process.env.NXF_STAGING_KEY,baseUrl:'https://nixflex-voice-engine-staging.up.railway.app',maxRetries:0});
const result = await c.knowledge.getDraft(process.env.NXF_KNOWLEDGE_BASE_ID, process.env.NXF_RESOURCE_ID);
// Keep knowledge and private results out of logs.
```

```python Python
import os
from nixflex import Nixflex

with Nixflex(api_key=os.environ["NXF_STAGING_KEY"], base_url="https://nixflex-voice-engine-staging.up.railway.app", max_retries=0) as c:
    result = c.knowledge.get_draft(os.environ["NXF_KNOWLEDGE_BASE_ID"], os.environ["NXF_RESOURCE_ID"])
    # Keep knowledge and private results out of logs.
```

```powershell CLI (PowerShell)
$env:NIXFLEX_API_KEY = $env:NXF_STAGING_KEY
nixflex knowledge getDraft "$env:NXF_KNOWLEDGE_BASE_ID" "$env:NXF_RESOURCE_ID" --json --base-url "https://nixflex-voice-engine-staging.up.railway.app"
```

</RequestExample>

MCP does not offer this operation in MCP 0.5.0. The server read is now non-persisting, but an engine deployment does not register a new MCP tool. Use the documented SDK or HTTP read; check installed tool schemas before use.

## Errors

Failures use `error.type`, `error.code`, `error.message`, `error.doc_url` and optional `error.details`. Knowledge failures include a request ID in details when available. Read the safe message as text. A job can return HTTP 200 with state `failed` and `error`; that is a job failure, not an HTTP error. Source failures can arise during preparation after the initial accepted response.

## Retry and idempotency

Use bounded retries for temporary read failures. This deployed GET does not persist repairs. Read the current edit revision before any deliberate save or acceptance; writes still need their own revision and idempotency checks.
