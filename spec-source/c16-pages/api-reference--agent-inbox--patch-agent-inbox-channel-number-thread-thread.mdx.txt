Change an owned conversation’s archive state or acknowledge messages through a known read version. This does not delete content or extend retention.

  <div><small>Scope</small><strong>Owning account</strong></div>

- This updates supported thread state; it is not a send-message endpoint.
- Read the current thread before resolving an uncertain update.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential. Send `Content-Type: application/json`.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `channel` (path) | string | Yes | None | Conversation channel. Allowed: `"sms"`, `"web"`. |
| `number` (path) | string | Yes | None | International number with + and digits; no spaces. Pattern: `^\+[1-9][0-9]{6,14}$`. |
| `thread` (path) | string | Yes | None | Opaque thread key from the conversation list. URL-encode it. Maximum 160 characters. Minimum 1 characters. |

Supply at least one field. Unknown fields and null are refused.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `archived` | boolean | No | Omitted | Set true to archive or false to unarchive. Omitted leaves state unchanged. |
| `read_version` | string | No | Omitted | Opaque decimal revision. Keep as a string to avoid precision loss. Pattern: `^[0-9]{1,18}$`. |

Use the read_version string returned by a thread read. Decimal numeric input is also accepted but strings avoid precision loss. Versions beyond received messages are refused. Read acknowledgements only advance; an older acknowledgement cannot mark later arrivals as read. A missing conversation is 404 inbox_not_found even though reading it may return an empty list. Archiving does not change retention. Requests return Cache-Control: no-store.

## Response fields

`200 OK` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `ok` | boolean | Update confirmed. Value: `true`. |
| `archived` | boolean | Current archive state. |

## Example request

These examples require Node/CLI 0.11.0 or later, Python 0.4.0 or later and MCP 0.5.0 or later. Keep `NIXFLEX_API_KEY` private. cURL uses Bash; CLI uses PowerShell and reads the key through `NIXFLEX_API_KEY`. Replace fixture identifiers and reserved example numbers with approved account-owned values. Configure the existing MCP installation for the same account at `https://api.nixflex.com` before using the shown tool arguments. Python shows the synchronous client; `AsyncNixflex` uses the same method with `async with` and `await`. This example changes state. Review the target and payload before running it.

<RequestExample>

```bash cURL
curl --request PATCH \
  --url "https://api.nixflex.com/v1/agent-inbox/web/%2B12025550123/thread/visitor%2Fplus%2B%20%C3%BC" \
  --header "Authorization: Bearer $NIXFLEX_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{"archived":false,"read_version":"999999999999999999"}'
```

```javascript Node
import { Nixflex } from 'nixflex';

const c = new Nixflex({
  apiKey: process.env.NIXFLEX_API_KEY,
  baseUrl: 'https://api.nixflex.com',
  maxRetries: 0,
});
const result = await c.inbox.update("web", "+12025550123", "visitor/plus+ \u00fc", {"archived": false, "read_version": "999999999999999999"});
```

```python Python
import os
from nixflex import Nixflex

with Nixflex(
    api_key=os.environ["NIXFLEX_API_KEY"],
    base_url="https://api.nixflex.com",
    max_retries=0,
) as c:
    result = c.inbox.update('web', '+12025550123', 'visitor/plus+ ü', archived=False, read_version='999999999999999999')
```

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 400 | [`invalid_inbox_request`](/api-reference/errors#invalid_inbox_request) | A path, query, body or settings value is invalid. | Correct the documented shape and limits. |
| 404 | [`inbox_not_found`](/api-reference/errors#inbox_not_found) | The number or thread is unavailable to this account. | Check the number, thread and account state. |
| 503 | [`agent_inbox_disabled`](/api-reference/errors#agent_inbox_disabled) | The inbox feature is disabled. | Wait for feature availability. |
| 503 | [`inbox_unavailable`](/api-reference/errors#inbox_unavailable) | The inbox read or write could not be confirmed. | Retry reads with bounded backoff; reconcile writes first. |
| 400 | [`invalid_json`](/api-reference/errors#invalid_json) | Invalid JSON body. | Correct JSON syntax. |
| 413 | [`payload_too_large`](/api-reference/errors#payload_too_large) | The request exceeds the JSON body limit. | Send a smaller request. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the full account credential. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

No idempotency key is documented. A timeout or 5xx can follow a committed change. Read the current state before deciding whether to submit again; never automatically repeat an uncertain write. Reapplying an intended archive boolean or an already acknowledged version preserves that state, but a concurrent archive edit can change user intent. Reload after uncertainty.
