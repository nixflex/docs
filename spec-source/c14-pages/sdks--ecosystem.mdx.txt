## Choose by task

| Tool | Use it for | Runtime and guide |
| --- | --- | --- |
| Node SDK | Typed server integrations and local outbound preparation | Node 18+; [Node guide](/sdks/node). |
| Python SDK | Synchronous or asynchronous server applications | Python 3.9+, httpx; [Python guide](/sdks/python). |
| CLI | Reviewed terminal operations and scripts | Ships in the Node package; [CLI quickstart](/cli/quickstart). |
| MCP server | Approved AI-client tool operations | Node 22+ for the server; [MCP developer guide](/sdks/mcp). |
| Direct HTTP | Another language or a method not exposed by your installed client | [Other languages](/sdks/other-languages) and [API reference](/api-reference/introduction). |

The website widget uses its generated installation flow, not a server SDK in the browser. Webhook processing is an HTTPS receiver you build; installing a client does not create one.

## Verify the reviewed candidate

These are the exact reviewed candidate archives. They are not a claim of public registry publication or completed live-write acceptance. Obtain the approved archive and compare its SHA-256 before installation. A version check alone cannot distinguish an earlier candidate with the same version.

| Archive | SHA-256 |
| --- | --- |
| `nixflex-0.11.0.tgz` | `0155f64c3fa28305cda95328b2f89959121d3dc07eef4af6723214ee45a6e3b3` |
| `nixflex-0.4.0-py3-none-any.whl` | `8465c4e04fbedbb5262ae8f1c7fdc47c5c3d814377764c3316476903e64f47eb` |
| `nixflex-0.4.0.tar.gz` | `b66f40717d8875a758831e01b7cec604ab3b2df18f1e14e83c73949474fbabd7` |
| `nixflex-mcp-0.5.0.tgz` | `21404fa3130b771e4b710c4aba08f0f60a7caca1398587812a6b52129a804c69` |

For example, inspect a supplied archive locally in PowerShell:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\nixflex-0.11.0.tgz'
```

Stop if the supplied release manifest and file disagree. Do not install an unknown archive merely because its filename matches.

## Understand the added call workflow

The reviewed clients support local outbound preparation, a saved request UUID, a read-only request-state lookup and a read-only post-call booking result. Preserve the same account, base URL, UUID and inputs across reconciliation. The request-state lookup cannot place a call.

Node uses `prepareOutboundCall`, `calls.outboundRequest` and `calls.bookings`. Python uses `prepare_outbound_call`, `calls.outbound_request` and `calls.bookings`. The CLI exposes `calls prepare`, `calls outboundRequest` and `calls bookings`. MCP adds `get_outbound_call_request` and `get_call_bookings`, bringing this exact candidate to 96 tools.

Earlier installation guides may describe a 94-tool candidate with the same package version. Confirm the package hash and actual tool inventory before using the two new reads. The 19 approved Knowledge tools remain; no direct calendar-booking or knowledge-publication tool is implied.

## Keep safety and coverage explicit

Node and Python automatically retry eligible GET reads only. Mutations are not automatically retried, including after network loss or a malformed response. The SDK’s behaviour does not make an application-level retry loop safe.

Google Calendar connection/settings and in-place number credential updates are included in these candidates. Sensitive credential operations use private input and safe result projections. Compatibility account model, voice and storage routes are outside the supported public client inventory; use the dashboard for new setup.

| Failure | Decision |
| --- | --- |
| Installed method missing | Verify the exact candidate; use documented HTTP rather than inventing a method. |
| Unknown call launch | Read the saved UUID and call ID; do not allocate a replacement automatically. |
| SMS `do_not_contact` | Stop without resending; retain older 400 handling as well as current 409. |
| Booking result incomplete | Keep its actual state instead of reporting zero bookings. |
