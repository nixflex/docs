## Make a read without an SDK

Set `NIXFLEX_API_KEY` privately. Use `https://api.nixflex.com` as the API origin, without `/v1`. This Python standard-library example makes one usage read, refuses redirects and avoids printing private response data:

```python
import json
import os
from urllib.error import HTTPError
from urllib.parse import urlsplit
from urllib.request import HTTPRedirectHandler, Request, build_opener

class NoRedirect(HTTPRedirectHandler):
    def redirect_request(self, request, file, code, message, headers, new_url):
        return None

base = "https://api.nixflex.com".rstrip("/")
parsed = urlsplit(base)
if parsed.scheme != "https" or not parsed.netloc or parsed.path or parsed.query or parsed.fragment or parsed.username:
    raise ValueError("Use the intended HTTPS API origin without a path or credentials")
request = Request(base + "/v1/usage", method="GET", headers={
    "Authorization": "Bearer " + os.environ["NIXFLEX_API_KEY"],
    "Accept": "application/json",
})
try:
    with build_opener(NoRedirect).open(request, timeout=30) as response:
        usage = json.load(response)
    if not isinstance(usage, dict):
        raise ValueError("Unexpected usage response")
    print("Usage read succeeded.")
except HTTPError as error:
    print({"status": error.code})
    raise SystemExit(1)
```

Apply the same boundary in Java, Go, PHP or another HTTP client: private headers, an explicit timeout, no credential-bearing redirects, safe JSON parsing and operation-specific result handling. Keep response bodies private.

## Construct requests from the contract

| Part | Rule |
| --- | --- |
| Base URL | Use the selected API origin and `/v1` exactly once. |
| Authentication | `Authorization: Bearer KEY_ID:KEY_SECRET`, stored server-side. |
| Path values | URL-encode each identifier, especially a number’s leading plus sign. |
| JSON body | Send documented fields and `Content-Type: application/json`. |
| File input | Use the specific raw-byte Knowledge upload contract, not generic JSON/base64. |
| Output | Preserve null, pending, unavailable and confirmed-empty states. |

An HTTP success can mean queued or accepted work. Read its operation state before reporting a call, delivery, publication or booking as complete.

## Handle failures before adding writes

Keep a fallback for non-JSON and incomplete error responses. Inspect safe HTTP status, machine code and request ID; avoid logging complete private bodies. Retry eligible reads with a bound and server guidance.

For an unknown write, preserve the original operation identity and reconcile first. Outbound calls use a saved UUID in `request_id`; Knowledge writes use their documented `Idempotency-Key`. Neither mechanism is a universal idempotency header for every endpoint.

## Use the public OpenAPI artifact carefully

The API reference is generated from the reviewed public OpenAPI 3.1 contract with 149 operations. Use that contract when generating a client, and verify the served artifact is actually available and matches the reviewed release. The conventional raw-spec URL alone is not proof that a deployment exposes it.

If a docs preview does not serve the raw JSON, obtain the reviewed release artifact rather than scraping HTML into a guessed schema. Preserve operation IDs, nullable fields, error responses and required revisions. Test a generated client against local fixtures before relying on writes.

Do not generate routes from dashboard requests or compatibility account interfaces outside the supported public inventory. Personal ownership and closure flows are not invented public endpoints.

## Receive events securely

Use the [raw-byte signature examples](/advanced/webhooks) for your receiver. Verify before JSON parsing, save durably, deduplicate atomically and acknowledge promptly. An SDK install or generated HTTP client does not create a webhook listener.
