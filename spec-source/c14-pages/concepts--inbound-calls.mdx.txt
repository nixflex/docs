## What shapes the conversation?

The agent's call instructions are combined with supported number overrides and current call context. Caller memory and name greeting are separate controls. Inbound knowledge is enabled by default for a new base; saved facts are supplied according to the current agent, settings and available lookup time.

A configured [pre-call hook](/advanced/precall-gate) can provide temporary context or explicitly reject the call. Its failure policy is fail-open, so it cannot serve as the sole security boundary for a protected action.

## Which actions can happen?

Calendar, text, transfer, keypad and custom-function actions require their own connections and permissions. A prompt alone cannot enable a disabled action. Recording is resolved from number and agent settings and depends on the actual recording path succeeding.

## What remains afterwards?

History and post-call analysis can arrive at different times. A completed call is not proof that its recording, summary, text or webhook delivery succeeded. Use the result's current status and recording access endpoint, then apply the configured retention policy.
