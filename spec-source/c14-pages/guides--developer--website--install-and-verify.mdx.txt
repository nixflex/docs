## Prepare the owned number

Choose the number whose website conversations should appear in the inbox. Read its current [website settings](/web-assistant/overview) server-side. Website instructions are separate from telephone and SMS instructions, and knowledge has independent website-chat and website-voice channels.

Effective voice requires both `web_agent_enabled` and `web_calls_enabled`, plus current account, agent, balance and admission checks. Turning the Web agent off does not erase the saved voice preference; it prevents effective access.

## Save settings with the current revision

Keep the returned decimal `revision` as a string. Send only intended settings through [PATCH website settings](/api-reference/web-agent/patch-agent-web-number). A focused illustrative body is:

```json
{"revision":"12","settings":{"web_name":"Appointment assistant","web_calls_enabled":true}}
```

Replace `12` with the observed revision; never hard-code it. On `widget_settings_changed`, read again and review the competing changes. Omitted top-level settings remain unchanged, but `web_appearance` is a complete replacement, not a nested merge.

## Copy the current installation

Use the dashboard’s Install snippet for this number and environment. If installation is not ready, resolve that environment configuration first. Do not substitute an older SDK script, manufacture a browser token or embed a server credential.

Place the supplied snippet in the intended site using its actual installation instructions. Keep account-management calls on your server. Test the resulting deployed page, including any embedding and browser security restrictions that differ from the dashboard preview.

## Verify the visitor journey

| Check | Expected decision |
| --- | --- |
| Open and send a chat | The intended number’s website conversation appears in its inbox. |
| Start voice with permission | The browser can request microphone access and show the actual connection result. |
| Deny microphone permission | The page gives a recoverable state without claiming a connected call. |
| Supply fictional contact details | The inbox retains them as visitor-supplied, unverified information. |
| Reopen after browser storage changes | Do not assume the same visitor identity will be recognised. |

Only test approved actions. Built-in telephone booking, SMS, transfers, keypad and menu navigation remain unavailable in the website channel.

## Review public custom functions

`web_functions_enabled` defaults off. Enabling it allows the number’s enabled custom functions after current checks; every such function must be suitable for an unverified public visitor. Do not grant account access based only on a visitor’s self-reported email or phone number.
