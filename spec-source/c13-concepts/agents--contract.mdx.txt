Use these fields with the matching engine and client versions.
See [settings by channel](/concepts/agent-channels) and
[privacy/action inheritance](/concepts/agent-inheritance) before treating a saved field
as an effective behaviour on every channel.
All four read/write responses use the same reviewed projection. Responses never contain
`twilio_auth_token`; `twilio_account_sid` is a legacy readable account identifier.

## Inputs

No coercion of strings into booleans/numbers. Valid 0/false values are preserved.
Omitted fields retain defaults (create) or the saved value (update).
Pickup delay is the deliberate legacy exception: this release does not alter its
validation, values or defaults.

`func_end_call` governs duration/silence timers; it is not a blanket prohibition on model END_CALL.
This release does not turn inert compatibility settings into features, and does not
change channel rules, billing, recording, pickup timing or the dashboard's direct writes.

Extraction entries: required `name` (unique identifier, 1-64 letters/digits/underscores,
starting with a letter/underscore; __proto__/constructor/prototype forbidden) and
`type` (text / selector / boolean / number). Optional `description` and
`format_example` are strings up to 2000; `optional` is boolean.
`choices` is up to 100 unique non-blank strings, each at most 200 characters;
a selector requires at least one. Unknown nested properties reject the whole request.

## Errors and warnings

Empty/unknown-only PUT: 400 empty_agent_update.
Mixed supported/unknown fields: supported fields save, with a JSON `warnings` array
containing code unknown_fields, unknown names, and "These fields were not saved."
Unknown input values are not echoed. Empty POST still creates defaults.

Known invalid input fails before writing. Dedicated prompt, recording-source,
remember-callers, retention, voice-selection and credential errors remain.
Missing/foreign agent: 404 not_found. Database failure: 503 agent_store_unavailable.
Catalog lookup outage: 503 catalog_unavailable. No blind write retries.

## Kits

See the feature-branch examples/agent-contract.md in Node+CLI, Python and MCP.
The CLI passes write fields via repeated `--set` or `--body`. Agent list adds `--offset`,
`--status` and `--search`; mutation-retry behavior is unchanged. MCP publishes named settings while retaining
unknown keys so the engine can issue its warning. No package publication in this run.

DELETE soft-disables only and retains the legacy response `{"message":"Agent deleted"}`.
It does not detach numbers, erase history or make GET of an owned disabled agent return 404.

The safety byte count normalizes each trimmed term (NFKD, removes combining marks, lowercases, removes whitespace) to detect duplicates. Each unique normalized term costs the UTF-8 bytes of its first trimmed original spelling plus 4 bytes. Empty and duplicate normalized terms add no bytes. This conservative count is not a tokenizer. Term length counts Unicode code points, not UTF-16 code units.

Automatic knowledge terms are read-only. They come from valid, unsuppressed live pieces, keep source spelling, and are ranked by importance, essential identity, repeated support and stable tie-breaks. Generic terms are filtered. The default limit is 80 per agent; platform configuration can choose 0–100. Customer terms take priority and stay first on calls; duplicates and weaker automatic terms are removed to fit the call limits. The returned list is not a promise that every term will be sent on a call. Read [automatic keyterms](/api-reference/knowledge/get-agents-target-knowledge-keyterms).

More than 20 terms returns 400 invalid_agent_field with message "Keep up to 20 words - remove some to save" and details.field "boosted_keywords".

- [`keyterms_term_too_long`](/api-reference/errors#keyterms_term_too_long): Keep each word or phrase within 50 characters to save Shorten the term. details.field is boosted_keywords; details.limit is 50.
- [`keyterms_list_too_large`](/api-reference/errors#keyterms_list_too_large): This list is {over_bytes} bytes over the 450-byte safety limit. Shorten or remove some words to save. Shorten the list. details.field is boosted_keywords, limit is 450, actual_bytes is the calculated size, and over_bytes is the excess. For one excess byte the message uses byte.
