## Prerequisites

Keep the account credential in `NIXFLEX_API_KEY` on your server. Examples copied from the reviewed kit candidates need Node/CLI 0.11.0 or Python 0.4.0, which are not yet published. Use cURL until the matching release is available. Use identifiers owned by the intended account. The API address is `https://api.nixflex.com`.

## 1. Read history

<CodeGroup>

```bash cURL
curl --request GET \
  --url "https://api.nixflex.com/v1/calls/history?period=month&outcome=failed&limit=25" \
  --header "Authorization: Bearer $NIXFLEX_API_KEY"
```

```javascript Node
import Nixflex from 'nixflex';
const baseUrl = 'https://api.nixflex.com';
const client = new Nixflex({apiKey:process.env.NIXFLEX_API_KEY,baseUrl,maxRetries:0});
const result = await client.calls.history({period:"month",outcome:"failed",limit:25});
// Handle result privately; do not log secrets or call content.
```

```python Python
import os, json
from pathlib import Path
from nixflex import Nixflex
base_url = "https://api.nixflex.com"
with Nixflex(os.environ["NIXFLEX_API_KEY"], base_url=base_url,max_retries=0) as client:
    result = client.calls.history(period="month",outcome="failed",limit=25)
# AsyncNixflex supports the same calls with await (and async with).
```

```bash CLI
nixflex calls history --period month --outcome failed --limit 25 --base-url https://api.nixflex.com --json
```

## 2. Page using server values

Use the endpoint’s documented filters, bounds and pagination. Do not treat one response as the whole account history. Keep call identifiers opaque and preserve unknown timestamps or outcomes.

## 3. Show separate processing states

Display call state, analysis, costs and recording availability separately. Missing summary or structured data is not a confirmed negative answer. A requested end or deletion can remain pending.

For confirmed booking changes, receive the signed [`call.bookings` event](/api-reference/call-bookings). Its action timeline and final booking results answer different questions: create then cancel produces two actions and zero active results. Deduplicate by trusted account, event and call ID before updating your view; the event can arrive separately from `call.completed`.

### Read the retained booking result

Call `GET /v1/calls/{id}/bookings` with the owned call ID. This read does not contact a calendar or place a call. Its result describes this call, not the current calendar inventory.

```javascript Node · booking read
const response = await fetch('https://api.nixflex.com/v1/calls/call_example/bookings', {
  headers: {Authorization: `Bearer ${process.env.NIXFLEX_API_KEY}`},
});
const payload = await response.json();
if (!response.ok) throw new Error(`HTTP ${response.status}: ${payload.error?.code || 'unknown'}`);
const view = bookingView(payload); // helper below; keep private booking data off logs
```

```javascript State mapping
function bookingView(payload) {
  if (!payload || typeof payload.call_id !== 'string' || !payload.call_id) throw new Error('Invalid booking response');
  if (payload.state === 'ready') {
    const rows = payload.result?.final;
    if (!Array.isArray(rows) || rows.length === 0 || rows.some(item => !item || !['active', 'cancelled'].includes(item.status))) {
      throw new Error('Unrecognised booking rows');
    }
    return {state: 'ready', activeBookings: rows.filter(item => item.status === 'active').length, result: payload.result};
  }
  if (!['none', 'processing', 'deleted', 'unavailable'].includes(payload.state) || payload.result !== null) {
    throw new Error('Unrecognised booking result');
  }
  return {state: payload.state, activeBookings: payload.state === 'none' ? 0 : null, result: null};
}
```

If this helper rejects an unrecognised response, keep the result unavailable rather than showing zero. It checks the fields used for this count; validate any other fields before using them in your application.

| State | UI meaning | Refresh behaviour |
| --- | --- | --- |
| `ready` | Confirmed result; count active final rows. | Use the retained result. |
| `none` | Complete evidence confirms no successful booking mutation. | Show zero for this call. |
| `processing` | Tracked work is still unfinished. | Offer bounded refresh. |
| `deleted` | Retained content is no longer available. | Respect retention; do not rebuild from logs. |
| `unavailable` | The evidence cannot establish a result. | Keep booking count unknown. |

A failed GET is not `none`. On 503, preserve the previous uncertainty and retry the read with a limit. For an uncertain outbound launch, [read the original request UUID](/api-reference/calls/get-outbound-request). A new UUID would create a new call intent.

## 4. Request a current recording link

Use `GET /v1/calls/{id}/recording` when the user asks to play a recording. Read `status`, `url` and `expires_at`. Available links are short-lived; do not save them as permanent public URLs. Other statuses can have `url:null`.

## 5. Apply retention and deletion honestly

Read the configured policy and actual current state. Cleanup waits for required finalisation and post-call decisions. Customer-owned storage has its own lifecycle. Deleting one call does not erase every caller record or external integration copy.

Single-call deletion can now finish for a narrowly verified empty recording: the call has ended and settled, recording was skipped, no stored recording row or carrier copy exists, the upload fence is closed, and all post-call work and memory decisions have finished. The server must have fresh ownership and absence proof. A missing URL, an empty file list or a completed call alone is not enough. Unknown or missing evidence stays pending or refused. This does not change bulk or account deletion, and required financial records remain.

Show `unavailable` with `reason:tracking_unavailable` as unavailable tracking, not proof that a recording was erased. Read the [single-call deletion contract](/api-reference/calls/delete) before offering a delete action.

## Example response

A recording access reply has `call_id`, `status`, `url` and `expires_at`. For example, `{"call_id":"call_example","status":"pending","url":null,"expires_at":null}` means no usable recording link is available yet.

## Errors and limits

| Condition | Handling |
| --- | --- |
| 404 or inaccessible call | Check ownership; do not reuse cached access. |
| Recording pending | Offer a later bounded refresh. |
| expired/not_recorded/customer_bucket | Explain the returned state; do not invent a link. |
| pending_deletion | Respect revoked access and tracked cleanup. |
| unavailable with tracking_unavailable | Keep recording state unknown; do not show a deletion success. |
| Optional analysis absent | Keep it unknown rather than manufacturing a result. |
