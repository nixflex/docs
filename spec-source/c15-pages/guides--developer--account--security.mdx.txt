## Choose the right identity

| Identity | Intended use | Boundary |
| --- | --- | --- |
| Personal dashboard login | A teammate using the dashboard | Current organisation membership, role and personal authentication checks. |
| Organisation API key | Your trusted server integrating with Nixflex | Owner authority for documented API operations; keep it out of browsers. |
| Short-lived media access | An eligible dashboard listening session | Scoped access; it is not the organisation API key. |

Do not expose a shared key to a browser to work around a Member refusal. A server that holds the key must enforce its own signed-in-user permissions and account-to-resource mapping.

## Personal two-factor setup

The dashboard's **Settings → Security** flow verifies an authenticator code before enabling two-factor authentication. A second authenticator can provide a backup. This is a personal-login workflow, not a public `/v1` API for enrolling users or changing their roles. Link people to [account security](/guides/business/account-security).

## Handle authentication failures

Stop on invalid credentials and verify the API host and complete key privately. For 403, check the operation's role requirement. For a fresh-login requirement, let the person complete the dashboard sign-in flow; never collect their password or one-time code in an agent prompt.

Log a request ID and safe error code. Omit account keys, auth headers, signed media URLs and customer content. Rotate a key only through the Owner's deliberate key-management workflow and update dependent servers together.
