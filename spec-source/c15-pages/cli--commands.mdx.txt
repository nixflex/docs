## Read command syntax and results

Run `nixflex --help` for the installed command inventory. The tables below omit the leading `nixflex`; angle-bracket values are placeholders, not literal arguments. Append `--base-url` for the intended host and `--json` where structured output is needed.

General creates and updates accept documented `--body '@file.json'` and repeated `--set field=value` inputs. The parser recognises booleans, null and numbers; `@file` reads text. Do not assume a future API field is accepted by an older typed command. Read back a deliberate change.

## Account and safe reads

| Command | Effect |
| --- | --- |
| `usage` | Read account usage and balance. |
| `whoami` | Read the selected key identity and usage; treat output as private. |
| `doctor` | Inspect CLI/runtime/configuration and make a connectivity read. |
| `login` / `logout` | Manage the legacy plaintext local credential file. |
| `keys create --body '@account.json' --confirm` | Create an account credential; not a connectivity test. |
| `keys rotate --confirm` | Replace the secret; existing integrations need an authorised rollout. |
| `completion <bash\|zsh\|pwsh>` | Print a completion script for review before shell installation. |

Never put a key in command history. See [private connection setup](/cli/overview).

## Agents and call reads

| Command | Effect |
| --- | --- |
| `agents list` / `agents get <id>` | Read agents using supported filters. |
| `agents create --body '@agent.json'` | Create the specified agent. |
| `agents update <id> --body '@changes.json'` | Update the documented supplied fields. |
| `agents delete <id> --confirm` | Request deletion of the selected agent. |
| `calls list --limit 50` | Read legacy offset results; no agent filter. |
| `calls history --agent <id> --limit 50` | Read filtered history with the returned paging contract. |
| `calls get <id>` / `calls read <id>` | Read legacy or explicit detail projection respectively. |
| `calls recording <id>` | Read current authorised playback availability and expiry. |
| `calls bookings <id>` | Read ready, none, processing, deleted or unavailable booking evidence. |

## Prepare, send and reconcile one call

| Command | Effect |
| --- | --- |
| `calls prepare --body '@intent.json' --output prepared-call.json --json` | Generate and save a UUID locally; sends nothing and never overwrites. |
| `calls create --body '@prepared-call.json'` | Send the approved saved call once. |
| `calls create ... --request-id <uuid>` | Use an explicitly saved UUID with the exact original inputs. |
| `calls outboundRequest <uuid>` | Read durable request state without dispatching. |

`--var name=Sam` maps to `dynamic_vars` for `{{name}}`. Use one variables alias only. `--wait` on a send polls for completion; its timeout is not a hangup timer. A late result must not cause another call. Follow the complete [CLI quickstart](/cli/quickstart).

## Campaigns and contact controls

| Family | Tasks and boundary |
| --- | --- |
| `campaigns list`, `create`, `launch`, `consent`, `cancel`, `resume`, `delete` | Voice campaign work; creation can launch immediately. Cancel lets active calls finish; Delete requests their hang-up. |
| `sms campaigns list`, `get`, `create`, `launch`, `update`, `consent`, `cancel`, `resume` | SMS campaign work; sent, delivered and replies remain separate. |
| `contacts` commands | Contact-hour previews and suppression operations from the installed help. |

Prefer complete JSON bodies for nested recipient variables, country and time-zone data. A CSV convenience importer does not make every column a top-level recipient policy field. Review [voice preparation](/guides/developer/campaigns/prepare-and-launch) or [SMS preparation](/guides/developer/sms-campaigns/prepare-and-send) before creating work.

`calls delete` and `sms campaigns delete` require confirmation and use the same-ID deletion flow: queued hang-up continues automatically, used charges remain, and a repeated DELETE safely resumes the request. `calls delete-all` keeps the separate bulk safety checks. Use [HTTP voice campaign deletion](/api-reference/voice-campaigns/delete) when that method is unavailable in your installed client.

## Numbers, callers, SMS and inbox

| Family | Tasks and boundary |
| --- | --- |
| `numbers list`, `get`, `usage`, `update`, `delete` | Owned-number reads and deliberate changes; move with an agent-only update. |
| `numbers web-calls <number> get` | Read the website-call preference; effective voice also needs the Web agent enabled. |
| `callers get`, `set`, `import`, `delete` | Number-scoped caller context; imports batch records and need partial-result handling. |
| `sms send` | Send one message; acceptance is not delivery and opt-outs must stop sending. |
| `web-agent` commands | Website settings with the observed revision. |
| `inbox` commands | Channel-scoped conversations, messages, read state and archive changes. |

For a new number import, use the supported dashboard setup. The public import schema omits legacy credential fields. Never copy carrier secrets into `--set` arguments or invent credential aliases.

## Google Calendar and number credentials

| Command | Effect |
| --- | --- |
| `integrations getGoogleCalendar <number>` | Read the safe connection state; the engine may check existing access internally. |
| `integrations connectGoogleCalendar <number> --return-url <https-url> --confirm` | Create a private ten-minute consent link for the authorised person. |
| `integrations updateGoogleCalendarSettings <number> --body '@calendar-settings.json' --confirm` | Save supplied settings; hours replace the complete seven-day map. |
| `integrations disconnectGoogleCalendar <number> --confirm` | Remove saved access; dispatched calendar work cannot be recalled. |
| `numbers updateCredentials <number> --provider twilio --confirm` | Update the existing carrier connection using its private environment pair. |

The credential command accepts private environment variables or `--credentials-stdin` from a trusted private process pipe. It rejects `--key`, `--body`, `--set`, credential files and secret command arguments. Use `NIXFLEX_TWILIO_SID` plus `NIXFLEX_TWILIO_TOKEN`, or select `telnyx` with `NIXFLEX_TELNYX_API_KEY` plus `NIXFLEX_TELNYX_CONNECTION_ID`.

Stop on `carrier_outcome_unknown`. `credential_save_pending` needs deliberate completion with identical input, not a general automatic retry. A credential update does not switch carriers or remove/re-import the number.

## Handle failures

Check both exit code and result. A preview can exit successfully without sending, and a failed command can follow an accepted write. Keep only safe codes and IDs in diagnostics. Reconcile the saved resource or request before repeating a mutation.

## Delete content and inspect the result

| Command | Effect |
| --- | --- |
| `calls delete ID --confirm` | End a running call and remove its content; recording cleanup can remain queued. |
| `campaigns delete ID --confirm` | Cancel waiting voice work, end running calls and remove the campaign and recipients. |
| `sms campaigns delete ID --confirm` | Remove an SMS campaign and waiting work; sent messages cannot be recalled. |

The new voice command without `--confirm` is a local preview with zero requests. Run the confirmed command only after approving the exact campaign. Configure `NIXFLEX_API_KEY` privately and set `NIXFLEX_BASE_URL` and `NXF_CAMPAIGN_ID` for that account:

```bash
nixflex campaigns delete "$NXF_CAMPAIGN_ID" --confirm --json --base-url "$NIXFLEX_BASE_URL"
```

Each confirmed command sends one DELETE. A 503 `hangup_pending` remains a structured error with `deleted:false` and `retry_pending:true` in its details; display queued, not deleted. Other uncertain errors keep the original code in `details.original_code`. No command retries automatically. Use fresh reads, then deliberately repeat the same DELETE if needed. History and used charges remain; no refund. `calls delete-all --confirm` keeps its separate guarded bulk contract.
