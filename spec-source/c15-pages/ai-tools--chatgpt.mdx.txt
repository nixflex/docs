## Use documentation without connecting an account

Give ChatGPT [the documentation index](https://docs.nixflex.com/llms.txt), then the relevant `.md` page, such as [business knowledge](https://docs.nixflex.com/guides/business/knowledge.md). If your chat cannot fetch pages, paste the non-secret text you want it to use. Do not include keys, private recordings or unnecessary customer details.

Ask it to explain steps and draft content. It cannot read your real calls, create an agent, check your balance or confirm a booking merely by reading these docs.

## Advanced: an admin-managed tunnel

The current [Secure MCP Tunnel guide](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) supports forwarding a **stdio** server to ChatGPT. This is an additional operator-managed connection, not a Nixflex-tested candidate feature.

1. Have your administrator confirm tunnel permissions and association with the intended ChatGPT workspace. Follow the official guide to create or reuse a tunnel and install `tunnel-client`.
2. [Install the Nixflex candidate](/ai-tools/overview#install-the-supplied-local-package). Configure the tunnel's stdio command to run Node with that package's absolute `index.js` path. Provide the Nixflex key, API URL and environment credential source privately to the server process. The tunnel also needs its own runtime credential; keep both secrets out of chats and config values.
3. Use the documented `tunnel-client doctor` check, then keep `tunnel-client run` active. Check readiness before discovery.
4. In ChatGPT Plugins, add a custom MCP server and select **Tunnel**. Choose the authorised tunnel and complete its authentication settings. Restrict the plugin to authorised people: the Nixflex key gives organisation authority, not each user's dashboard role.
5. Inspect the discovered tools and try `get_usage` only. Treat compatibility and write behaviour as unverified until tested. A tunnel connection does not add missing booking or knowledge-write tools.

## If Nixflex supplies a hosted MCP connection

ChatGPT web supports remote MCP through streaming HTTP or SSE, subject to workspace policy. A local Codex config does not connect a web chat. The current [ChatGPT custom MCP guide](https://developers.openai.com/api/docs/guides/custom-mcp-server) describes the connection flow.

The current kit supplies no hosted URL. If Nixflex later supplies a supported option, obtain its exact URL, authentication and tool list. In ChatGPT **Plugins → Add custom MCP server**, use those details, complete sign-in and install the plugin. Keep the key out of chat and URLs, and keep private account tools authenticated.

Inspect the discovered tools; do not assume they match the local kit’s 96. Start with an approved `get_usage` read, if available, before allowing changes.

## Five prompts to try

These work as planning prompts without a connection. Agent creation, call reads and usage become account actions only when a configured connection exposes the named tools. Each prompt says what to do when no connection is available.

### 1. Plan or create an agent

> Help me create a Nixflex agent named Willow Reception. Read the setup docs and draft its instructions. If connected tools include list_agents and create_agent, check the existing names and wait for my approval before creating it. Otherwise give me the dashboard steps and clearly say no agent was created.

### 2. Add knowledge with human review

> Help me add opening hours to Willow Reception's knowledge. Ask me for the business facts and draft a topic I can review. The current Nixflex MCP cannot publish knowledge. Show the dashboard add, review and approval steps, and never claim the draft is live.

### 3. Check calls only when connected

> If an approved Nixflex connection exposes list_calls, summarise the latest five completed calls for the agent I choose, using confirmed outcomes and hiding personal details. If not connected, show me how to find them in Call History. Do not invent call data or contact anyone.

### 4. Prepare a calendar booking

> Help me set up booking through Google Calendar for my Nixflex number. Explain the number's connection, opening hours, invite switch and full-name spelling, email-local-part spelling, a domain spoken as words, and one combined read-back followed by one clear yes. Give me a manual test script. The local MCP has no direct booking tool; do not say an appointment was made or send a call or text.

### 5. Read usage or show where to find it

> If an approved Nixflex connection exposes get_usage, read and explain the actual returned usage, balance and period. Otherwise direct me to Billing and say you cannot see my balance. Do not guess charges, request my key or change any billing setting.

## Use only tools exposed by your connection

With a verified connection, follow [calendar consent and settings](/ai-tools/calendar-settings) or [private number-credential setup](/ai-tools/number-credentials). The four writes require `confirm: true`; missing confirmation sends no request. A tunnel does not configure private carrier credentials for you.

Disconnect cannot recall dispatched work or guarantee remote revocation. Invitation settings do not prove delivery, and direct booking and knowledge publication remain unavailable. Never automatically retry an unknown write.

## Check a booking result without creating one

If the verified connection exposes `get_call_bookings`, it can read the retained result for a known call. If it exposes `get_outbound_call_request`, it can check a saved outbound request ID without dialling. Keep `processing`, `deleted` and `unavailable` distinct from a confirmed empty result. See [call results and uncertain requests](/ai-tools/overview#check-bookings-and-uncertain-call-requests).

## What an AI answer does not prove

A written plan is not a saved agent, a confirmed calendar event or a delivered message. Check the tool result and dashboard when an action is available. An unknown result needs reconciliation before retrying. For details, read [Nixflex capabilities and key handling](/ai-tools/overview).
