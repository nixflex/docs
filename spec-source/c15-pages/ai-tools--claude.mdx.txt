## Claude Desktop

Install Node 22 or later. In Claude Desktop settings, open **Developer**, then **Edit Config**. Add this server to your private `claude_desktop_config.json`, preserving any other servers. Replace the key placeholder only in this private configuration, and choose the API host that matches the key.

<CodeGroup>

```json macOS or Linux
{
  "mcpServers": {
    "nixflex": {
      "command": "npx",
      "args": ["-y", "nixflex-mcp"],
      "env": {
        "NIXFLEX_API_KEY": "YOUR_PRIVATE_NIXFLEX_KEY",
        "NIXFLEX_BASE_URL": "https://api.nixflex.com",
        "NIXFLEX_CREDENTIAL_SOURCE": "environment"
      }
    }
  }
}
```

```json Windows
{
  "mcpServers": {
    "nixflex": {
      "command": "cmd.exe",
      "args": ["/c", "npx", "-y", "nixflex-mcp"],
      "env": {
        "NIXFLEX_API_KEY": "YOUR_PRIVATE_NIXFLEX_KEY",
        "NIXFLEX_BASE_URL": "https://api.nixflex.com",
        "NIXFLEX_CREDENTIAL_SOURCE": "environment"
      }
    }
  }
}
```

</CodeGroup>

The private `env` field supplies the key to the server process. This file is not an encrypted vault: restrict access and keep it out of projects, shared folders, screenshots and chats. Restart Claude Desktop, inspect the Nixflex tools, then use the read-only prompt below. See the [local MCP setup guide](https://modelcontextprotocol.io/docs/develop/connect-local-servers) if the settings layout differs.

Removing this server does not revoke the Nixflex key. Number-credential updates also need the selected carrier pair privately supplied to the server process; see [private number credentials](/ai-tools/number-credentials).

## Claude Code

Install Node 22 or later. Have your private launcher supply `NIXFLEX_API_KEY`, the matching `NIXFLEX_BASE_URL` and `NIXFLEX_CREDENTIAL_SOURCE=environment`, then start Claude Code from that environment. Register the server with no secret on the command line:

<CodeGroup>

```powershell Windows PowerShell
claude mcp add --transport stdio --scope user nixflex -- cmd /c npx -y nixflex-mcp
```

```bash macOS or Linux
claude mcp add --transport stdio --scope user nixflex -- npx -y nixflex-mcp
```

</CodeGroup>

Reopen Claude Code and inspect `/mcp`. Keep tool approvals enabled. The [Claude Code MCP guide](https://code.claude.com/docs/en/mcp) describes local server setup and configuration scope.

## Verify with one read

> Use Nixflex get_usage only. Summarise usage without making changes, sending messages or starting calls. Never print credentials.

A working connection should expose **97 tools**. If it does not, check the installed version before using the prompts. The four calendar and credential writes—calendar connect, settings, disconnect and number-credential update—require `confirm: true`; without it, no request is sent. Never automatically retry a write whose result is unknown. See [the calendar controls and private credential limits](/ai-tools/overview#google-calendar-and-number-credentials).

## Five prompts to try

### 1. Create an agent

> List my Nixflex agents first. Draft a new agent named Willow Reception for service questions. Show its instructions and proposed settings, then wait for my approval before using create_agent. Do not attach numbers, place calls or change an existing agent.

### 2. Add knowledge with a review step

> Help me add opening-hours knowledge for Willow Reception. Read its current knowledge with the available Nixflex tools, ask me for the missing hours, and draft the text for review. This MCP cannot publish knowledge: show me how to add and approve it in the dashboard. Do not claim it is live.

### 3. Check calls

> Use Nixflex list_calls to find the latest five completed calls for Willow Reception. Summarise only confirmed outcomes and flag missing information. Do not call anyone, send messages or delete records. Keep personal details out of the summary.

### 4. Prepare calendar booking

> Help Willow Reception prepare Google Calendar booking. List my numbers and let me choose. With my approval, check get_google_calendar. If consent is needed, show the number and return URL for approval before connect_google_calendar with confirm: true. Give me the ten-minute link to open myself, then check status again. Show hours and invite-setting changes for approval before update_google_calendar_settings with confirm: true. Give me a test-call script with full-name spelling, email-local-part spelling, a domain spoken as words, and one combined read-back followed by one clear yes. There is no direct booking tool; do not place a call or claim an appointment or invitation delivery.

### 5. Read usage

> Use Nixflex get_usage to explain my current usage and balance. Label the period actually returned and say when a figure is missing. Do not estimate an invoice, add credit, change billing or reveal any key.

## Read bookings and saved call requests

Use `get_call_bookings` with a known call ID to read that call’s retained result. Use `get_outbound_call_request` with the original saved request ID to investigate an uncertain launch. These reads do not book or dial. Keep unknown outcomes separate from failure and never allocate a replacement ID as an automatic retry. See [the result states and call preparation workflow](/ai-tools/overview#check-bookings-and-uncertain-call-requests).

## Limits and documentation

Claude can prepare human calendar consent, check status, update settings and disconnect the selected number. Disconnect cannot recall dispatched work or guarantee remote revocation; `send_invites` is not delivery proof. Number credentials come only from the server's private environment, never tool input. Claude cannot publish knowledge, accept personal ownership offers or book directly with this tool set. Calls and messages need explicit approval and can spend credit. See [all capabilities and limits](/ai-tools/overview#what-the-tools-can-do).

For documentation-only work, give Claude [llms.txt](https://docs.nixflex.com/llms.txt) or [this page as Markdown](https://docs.nixflex.com/ai-tools/claude.md). Documentation access does not connect your account.
