## Install the SDK

Install the package in your server application:

```bash
npm install nixflex
```

These examples require Node SDK 0.11.0 or later. The SDK uses native fetch and has no runtime dependencies. The CLI ships in the same package.

## Make one safe read

Set `NIXFLEX_API_KEY` and `NIXFLEX_BASE_URL` privately for the intended account and environment. The base URL is the origin without `/v1`; the client adds that prefix. Save this as an ES module, for example `read-usage.mjs`:

```javascript
import Nixflex, { NixflexError } from 'nixflex';

const apiKey = process.env.NIXFLEX_API_KEY;
const baseUrl = process.env.NIXFLEX_BASE_URL;
if (!apiKey || !baseUrl) throw new Error('Configure the account and API host privately.');
const client = new Nixflex({apiKey, baseUrl, timeoutMs: 30_000, maxRetries: 0});

try {
  const usage = await client.usage.get();
  if (!usage || typeof usage !== 'object') throw new Error('Unexpected usage response.');
  console.log('Usage read succeeded.');
} catch (error) {
  if (error instanceof NixflexError) {
    console.error({status: error.status, code: error.code, requestId: error.requestId});
    process.exitCode = 1;
  } else {
    throw error;
  }
}
```

Keep the returned usage object private. Avoid logging complete error objects because details or upstream messages can contain request data.

## Prepare a call without sending it

The following local script reads a private `intent.json` containing the reviewed call fields. It generates the UUID and saves an exclusive file; it sends no request. Store the file in an application-owned private directory and retain its account/environment binding.

```javascript
import { readFileSync, writeFileSync } from 'node:fs';
import { prepareOutboundCall } from 'nixflex';

const intent = JSON.parse(readFileSync('intent.json', 'utf8'));
const prepared = prepareOutboundCall(intent);
writeFileSync('prepared-call.json', JSON.stringify(prepared, null, 2) + '\n', {
  encoding: 'utf8', flag: 'wx', mode: 0o600,
});
console.log('Prepared locally; no call sent.');
```

Use the [outbound workflow](/guides/developer/call-requests) for the complete input shape. POSIX file mode does not establish Windows ACL protection; apply your platform’s private-directory permissions. Never run preparation again as a retry.

## Send the saved intention once

This separate script places a paid call. Run it only after approval of the saved recipient, sender and purpose. Do not wrap it in an automatic retry loop.

```javascript
import Nixflex, { NixflexError } from 'nixflex';
import { readFileSync, writeFileSync } from 'node:fs';

const apiKey = process.env.NIXFLEX_API_KEY;
const baseUrl = process.env.NIXFLEX_BASE_URL;
if (!apiKey || !baseUrl) throw new Error('Configure the original account and API host.');
const saved = JSON.parse(readFileSync('prepared-call.json', 'utf8'));
const client = new Nixflex({apiKey, baseUrl, maxRetries: 0});
try {
  const receipt = await client.calls.create(saved);
  writeFileSync('call-receipt.json', JSON.stringify(receipt, null, 2) + '\n', {
    encoding: 'utf8', flag: 'wx', mode: 0o600,
  });
  console.log('Receipt saved; inspect the call separately.');
} catch (error) {
  if (error instanceof NixflexError) {
    console.error({status: error.status, code: error.code, requestId: saved.request_id});
    process.exitCode = 1;
  } else {
    throw error;
  }
}
```

A local receipt-write failure can occur after a call was accepted. Reconcile the saved UUID rather than running the send again. Typed calls with `request_id` return `OutboundRequestReceipt`, where to/from are optional; no-ID calls retain the older response type.

## Reconcile with reads

Read `client.calls.outboundRequest(saved.request_id)` separately. For `accepted`, retain `call_id` and use `calls.read(call_id)` for current detail and `calls.bookings(call_id)` for booking evidence. `pending` and `unknown` require reconciliation, never a replacement UUID. A 404 is not permission to redial.

Booking states are `ready`, `none`, `processing`, `deleted` and `unavailable`. Only ready carries the result. Count active rows in `result.final`; do not count every action in `timeline` or turn unavailable into an empty list.

## Choose the resource and paging method

| Task | Method |
| --- | --- |
| Agent reads | `client.agents.list()` and `client.agents.get(id)` |
| Filtered call history | `client.calls.history({agent: id, limit: 50})` |
| Private playback access | `client.calls.recording(callId)`; honour returned expiry. |
| Owned number settings | `client.phoneNumbers.get(number)` and focused `update`. |
| Knowledge | `client.knowledge`; use saved idempotency keys and revisions. |
| Calendar and integrations | `client.integrations`; use exact documented methods and private inputs. |

`calls.iter(100)` takes a numeric page size from 1 to 200, not a query object. It uses offset pages and is not a frozen snapshot. For filtered reads use `calls.history`; legacy `calls.list` does not accept an agent filter. See [pagination](/guides/developer/pagination).

## Handle errors and webhooks

The default timeout is 30 seconds. `maxRetries` defaults to one eligible GET retry, with a supported range of 0–3; writes are never automatically retried. `NixflexOutcomeUnknownError` means a mutation may already have happened. The outbound request family also exposes `NixflexOutboundRequestError` and its pending, unknown, conflict and unavailable variants.

| Failure | Recovery |
| --- | --- |
| Authentication or permission refusal | Correct the account/environment or authorised role. |
| Read rate limit | Honour retry guidance with a bound. |
| Unknown write | Read saved state before another deliberate operation. |
| SMS `do_not_contact` | Stop; do not resend around the refusal. |

For webhooks, use the strict raw-byte verifier and durable receiver in the [webhook guide](/advanced/webhooks). Provision the separate organisation signing secret where organisations are enabled; the full API authentication string is not the signing secret.

## Delete content deliberately

The client supports `calls.delete`, `campaigns.delete` and `sms.campaigns.delete`. Each invocation sends one DELETE and never repeats it automatically. Authorise the exact account and identifier first. A voice/SMS campaign success requires `campaign_id`, `deleted:true` and `message`; a call success requires `call_id`, `deleted:true`, `recording_deleted` and `recording_cleanup`.

The exact queued response raises `NixflexServerError`: status 503, code `hangup_pending`, and details `deleted:false` plus `retry_pending:true`. It is not success. The server continues automatically; a later deliberate repeat of the same DELETE is safe. Other uncertain failures use `outcome_unknown`; inspect `details.original_code` and current state privately. No error or 404 is converted into deletion success.

Bulk call cleanup keeps its separate guard and counters. It does not use this queue classification. See [delete a call](/api-reference/calls/delete), [delete a voice campaign](/api-reference/voice-campaigns/delete) and [delete an SMS campaign](/api-reference/sms/campaigns-delete).

Set `NXF_CAMPAIGN_ID` to the voice campaign you explicitly intend to delete. The example sends one request:

```javascript
import Nixflex, { NixflexServerError } from 'nixflex';

const apiKey = process.env.NIXFLEX_API_KEY;
const baseUrl = process.env.NIXFLEX_BASE_URL;
const campaignId = process.env.NXF_CAMPAIGN_ID;
if (!apiKey || !baseUrl || !campaignId) throw new Error('Configure the account, host and approved campaign ID.');
const client = new Nixflex({apiKey, baseUrl, maxRetries: 0});
try {
  const receipt = await client.campaigns.delete(campaignId);
  if (receipt.deleted !== true || receipt.campaign_id !== campaignId || typeof receipt.message !== 'string') {
    throw new Error('Deletion is not confirmed.');
  }
  console.log('Campaign deletion confirmed; history and used charges remain.');
} catch (error) {
  if (error instanceof NixflexServerError && error.status === 503 &&
      error.code === 'hangup_pending' && error.details?.deleted === false &&
      error.details?.retry_pending === true) {
    console.log('Deletion queued; the server continues after hang-up.');
  } else {
    // Keep the error private. Reconcile an unknown result before a deliberate repeat.
    throw error;
  }
}
```

The current voice and SMS methods return `CampaignDeleteResponse`. The older exported `SmsCampaignDeleteResponse` alias remains source-compatible with old receipts; it is not the current success proof. The call type includes the required `recording_cleanup` union.

### Client helpers

| Helper | Purpose |
| --- | --- |
| `new Nixflex(options)` | Create a server-side client with an explicit API host and private credential. |
| `Nixflex.createKey(params, baseUrl)` | Create a new account credential only when account creation is intended; see [create an account key](/api-reference/account/create-key). It is not a connectivity check. |
| `prepareOutboundCall(params)` | The exported equivalent of `client.calls.prepare`; creates and validates an intention locally. |
| `verifyWebhookSignature(rawBody, signatureHeader, keySecret, options)` | The exported equivalent of `client.webhooks.verify`; see [webhook verification](/advanced/webhooks). |
| `HttpClient.request(method, path, body, query, options)` | Low-level transport for a documented route. Prefer a typed resource method; the public API contract still applies. |
