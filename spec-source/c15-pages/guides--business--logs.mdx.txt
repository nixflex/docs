## Find the request

1. Open **Logs** and choose the API request view or **Errors**.
2. Search for an endpoint, or paste an exact request ID beginning with `req_`.
3. Narrow the list by method, status family or date range when needed.
4. Open a row to read its time, method, endpoint, status, duration, error code and request ID.
5. Load more rows for earlier results. Keep the same filters while checking a particular incident.

The list refreshes periodically. A failed refresh or an empty filter result does not prove no request was made.

## Read the status

| Status | Meaning | Next step |
| --- | --- | --- |
| 2xx | The HTTP operation returned success. | Check its returned record or corresponding history for completion. |
| 4xx | Authentication, input, permissions or current state blocked the request. | Read the error code and correct its cause. |
| 429 | Too many requests. | Respect the retry delay; do not repeat a write automatically. |
| 5xx or unknown | The result may be incomplete or uncertain. | Check the saved call or campaign before trying again. |

## Check webhook deliveries

Open the webhook delivery view to review the call, agent, attempt count, response status and delivery times. A destination rejection needs its receiver settings checked. An unconfirmed delivery does not prove the business action failed or that replaying it is safe.

Use the request ID, approximate time and safe error code when asking a developer or support for help. Do not copy keys, signed URLs, customer transcripts or full request bodies into a support message.
