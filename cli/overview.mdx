The `nixflex` command lets you do from a terminal what you would otherwise do in the dashboard or with the API: create an agent, place a call, load a customer list, launch a campaign, check your balance. It ships inside the [`nixflex`](https://www.npmjs.com/package/nixflex) npm package - the same package as the Node SDK - and every command is a call into that SDK, so the CLI can never say something the API does not do. A test in the package fails if any SDK method has no command.

```bash
npx nixflex --help
```

## Install

Run it without installing (`npx nixflex ...`), or install once:

```bash
npm install -g nixflex
nixflex --version
```

Requires Node.js 18 or newer. No other dependencies are installed.

## Authenticate

The CLI needs your full API key - both halves, `nxf_xxx:nxfs_xxx`. It looks in three places, in this order:

| Order | Where | Use it for |
|---|---|---|
| 1 | `--key nxf_xxx:nxfs_xxx` on the command | One-off commands against another account |
| 2 | `NIXFLEX_API_KEY` environment variable | CI, scripts, servers |
| 3 | `~/.nixflex/config.json` | Your own machine - written by `nixflex login` |

```bash
nixflex login          # prompts for the key and verifies it against the API
nixflex whoami         # which key is in use, plus usage and balance
nixflex logout         # removes the stored key
```

<Note>
  Legacy `login` stores plaintext in `~/.nixflex/config.json`; this is not an encrypted vault. POSIX file mode is not a guarantee of Windows ACL protection. The file contains `api_key` and optional `base_url`; staging must retain its explicit URL. Never put keys in scripts, shell history, chat or client JSON. The [MCP foundation draft](/ai-tools/overview) binds key and URL together; the candidate MCP clients use separate private key setup; legacy CLI login still writes this plaintext file.
</Note>

## Output

Every command prints a table for humans. Add `--json` for scripts - the output is then exactly what the API returned, and errors come back as JSON on stdout too. Progress messages go to stderr, so stdout can be piped safely.

```bash
nixflex agents list --json | jq '.[].agent_id'
```

## Safety rails

- **Destructive commands preview first.** `agents delete`, `calls delete`, `calls delete-all`, `numbers delete`, `callers delete`, `sms campaigns delete`, `webhooks delete`, `storage|llm|tts delete` and `keys rotate` all show what would happen and stop until you add `--confirm` (or `--yes`).
- **Nothing is retried or batched silently.** `callers import` sends a file in chunks of 1,000 and reports progress; a bad row stops its chunk before anything in it is written.
- **Prompts from files.** Anywhere a prompt or message is accepted, `@path/to/file.txt` reads it from disk.
- **Use the command contract.** General creates and updates accept `--set` and `--body`; sensitive number credentials accept only private environment or stdin input.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success |
| `1` | The API returned an error, or the command was wrong (a suggestion is printed for typos) |
| `2` | No API key found (run `nixflex login`) |
