Commands support `--json` output and `--base-url`. Use a privately configured `NIXFLEX_API_KEY`; the number credential command explicitly rejects `--key`. Destructive commands preview and stop unless you pass `--confirm` (alias `--yes`).

## Google Calendar and number credentials

These five commands ship in the supplied **Node/CLI 0.11.0 K6 candidate**, not as a
claim of public registry availability. Confirm your installed version first.
Each write previews with zero requests unless you pass `--confirm`; the commands
below are separate actions, not a sequence to run against a real number.

| Command (after `nixflex`) | Behaviour |
| --- | --- |
| `integrations connectGoogleCalendar <number> --return-url <https-url> --confirm` | Return a private ten-minute link for human consent; never auto-open. |
| `integrations getGoogleCalendar <number> --json` | Read six status fields; the engine may refresh/check existing credentials internally. |
| `integrations updateGoogleCalendarSettings <number> --body @calendar-settings.json --confirm` | Change supplied settings; hours replace all seven days. |
| `integrations disconnectGoogleCalendar <number> --confirm` | Remove saved access; cannot recall dispatched work. |
| `numbers updateCredentials <number> --provider twilio --confirm` | Read the private environment pair and update this number's routing/settings in place. |

```powershell
nixflex integrations getGoogleCalendar '+12025550123' --json
# A separate approved change; the file contains settings only, never secrets:
nixflex integrations updateGoogleCalendarSettings '+12025550123' --body '@calendar-settings.json' --confirm
```

For example, `calendar-settings.json` can contain `{"send_invites":false}`.
Other fields are `timezone`, `hours`, `slot_minutes` (15/30/45/60) and `calendar_id`.
Omitted fields remain saved. A closed day is `null`; invitations do not prove inbox delivery.

For credentials, privately configure `NIXFLEX_TWILIO_SID` + `NIXFLEX_TWILIO_TOKEN`,
or use `--provider telnyx` with `NIXFLEX_TELNYX_API_KEY` + `NIXFLEX_TELNYX_CONNECTION_ID`.
Alternatively `--credentials-stdin` accepts the exact JSON pair from a trusted private
process pipe. This command rejects `--key`, `--body`, `--set`, credential files and
secret command-line flags. It returns only a safe receipt. No automatic write retry:
stop on `carrier_outcome_unknown`; only manually complete `credential_save_pending`
with identical input. [Review the routing consequences](/api-reference/phone-numbers/credentials).

SMS JSON errors preserve 409 `conflict` / `do_not_contact`; stop without resending,
while retaining old 400 handling. Booking model additions do not create a CLI listener.

## Setting any field

General create/update commands accept `--set field=value` - as many times as you like - and `--body @file.json` for nested objects. Values are parsed: `true`, `false`, `null`, numbers, and `@path` reads a file. Any field the API accepts works, including ones added after this CLI was released.

```bash
nixflex agents update agent_15d1a9ee16294087 --set silence_hangup_seconds=12 --set incall_sms_enabled=true
nixflex agents update agent_15d1a9ee16294087 --set system_prompt=@prompt.txt
nixflex numbers import --body @number.json
```

Named flags exist for common fields; `--set` covers the rest. Use documented names:
number PATCH can ignore unknown fields alongside valid fields. Check read-back.

## Account

| Command | What it does |
|---|---|
| `nixflex login` | Store your API key in `~/.nixflex/config.json` after verifying it. Reads `NIXFLEX_API_KEY` if set. |
| `nixflex logout` | Remove the stored key. |
| `nixflex whoami` | The key id in use, plus usage and balance. |
| `nixflex usage` | Usage and balance - [GET /v1/usage](/api-reference/account/usage). |
| `nixflex doctor` | CLI version, Node version, where the key came from, base URL, and whether the API answers. |
| `nixflex keys rotate --confirm` | New secret. **The current one stops working immediately** - update every integration, then `nixflex login` again. Previews without `--confirm`. |
| `nixflex completion <bash\|zsh\|pwsh>` | Prints a shell completion script. `nixflex completion bash >> ~/.bashrc` |

## Campaigns (voice batch)

| Command | Notes |
|---|---|
| `campaigns create --agent ID --from +44... --prompt TEXT\|@file --csv people.csv [--name NAME] [--set k=v ...]` | One prompt, many calls. Scheduling fields (`schedule_type`, `scheduled_date`, window) via `--set`. See [Create batch](/api-reference/calls/batch-create). |
| `campaigns launch <campaign_id>` | Starts a campaign created with `--set schedule_type=schedule`. Campaigns created without that dial immediately. |

CSV columns: `phone` (required, E.164), `prompt_override` (optional - replaces the campaign prompt for that person), and every other column becomes a variable the agent receives for that call.

```csv
phone,name,appointment
+447453573770,Sam,Tuesday 11:00
+447700900002,Priya,Wednesday 14:30
```

## Errors and exit codes

Errors print as `error <status> <code>: <message>` with a link to the error's page, and the process exits with code `1`. With `--json` the same information is returned on stdout as `{ "error": { "code", "status", "message", "doc_url" } }`. No key at all exits with `2`. A mistyped command exits `1` with a suggestion.

Progress lines (imports, `--wait`) go to stderr, so stdout stays clean for pipes. All codes are listed on [Errors](/reference/errors).
