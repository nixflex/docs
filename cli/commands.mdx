Every command accepts `--json` (machine-readable output), `--key` (use another API key for this command) and `--base-url` (staging). Destructive commands preview and stop unless you pass `--confirm` (alias `--yes`).

## Setting any field

Every command that creates or updates something accepts `--set field=value` - as many times as you like - and `--body @file.json` for nested objects. Values are parsed: `true`, `false`, `null`, numbers, and `@path` reads a file. Any field the API accepts works, including ones added after this CLI was released.

```bash
nixflex agents update agent_15d1a9ee16294087 --set silence_hangup_seconds=12 --set incall_sms_enabled=true
nixflex agents update agent_15d1a9ee16294087 --set system_prompt=@prompt.txt
nixflex numbers import --body @number.json
```

Named flags exist for common fields; `--set` covers the rest. Use documented names:
number PATCH can ignore unknown fields alongside valid fields. Check read-back.

## Account

| Command | What it does |
|---|---|
| `nixflex login` | Store your API key in `~/.nixflex/config.json` after verifying it. Reads `NIXFLEX_API_KEY` if set. |
| `nixflex logout` | Remove the stored key. |
| `nixflex whoami` | The key id in use, plus usage and balance. |
| `nixflex usage` | Usage and balance - [GET /v1/usage](/api-reference/account/usage). |
| `nixflex doctor` | CLI version, Node version, where the key came from, base URL, and whether the API answers. |
| `nixflex keys rotate --confirm` | New secret. **The current one stops working immediately** - update every integration, then `nixflex login` again. Previews without `--confirm`. |
| `nixflex completion <bash\|zsh\|pwsh>` | Prints a shell completion script. `nixflex completion bash >> ~/.bashrc` |

## Calls

| Command | Notes |
|---|---|
| `calls create --agent ID --to +44... --prompt TEXT\|@file [--from +44...] [--var key=value ...] [--wait] [--timeout S]` | Places a call now. `--var name=Sam` fills `{{name}}` via `dynamic_vars` in the batch 1 candidate. `--wait` polls for the end; default timeout 300 s, not a hangup timer. See [client safety](/api-reference/calls/client-safety). |
| `calls list [--limit N] [--agent ID]` | Newest first. |
| `calls get <call_id>` | |
| `calls delete <call_id> --confirm` | Requests guarded cleanup; pending/safety refusals are not deletion. |
| `calls delete-all --confirm` | Requests guarded call cleanup, not SMS or account erasure. Never blindly retry an uncertain response. |

```bash
nixflex calls create --agent agent_15d1a9ee16294087 --to +447453573770 --prompt @reminder.txt --var name=Sam --wait
```

## Campaigns (voice batch)

| Command | Notes |
|---|---|
| `campaigns create --agent ID --from +44... --prompt TEXT\|@file --csv people.csv [--name NAME] [--set k=v ...]` | One prompt, many calls. Scheduling fields (`schedule_type`, `scheduled_date`, window) via `--set`. See [Create batch](/api-reference/calls/batch-create). |
| `campaigns launch <campaign_id>` | Starts a campaign created with `--set schedule_type=schedule`. Campaigns created without that dial immediately. |

CSV columns: `phone` (required, E.164), `prompt_override` (optional - replaces the campaign prompt for that person), and every other column becomes a variable the agent receives for that call.

```csv
phone,name,appointment
+447453573770,Sam,Tuesday 11:00
+447700900002,Priya,Wednesday 14:30
```

## Numbers

| Command | Notes |
|---|---|
| `numbers list [--agent ID] [--provider twilio\|telnyx] [--limit N] [--cursor CURSOR]` | Paging opt-in; count means returned rows. Local unpublished Group2 build. |
| `numbers get <number> --json` | All safe settings, read-only source and key status. Local unpublished Group2 build. |
| `numbers import --set phone_number=+44... --set agent_id=ID --set twilio_sid=... --set twilio_token=...` | Or `--set telnyx_api_key=... --set telnyx_connection_id=...`, or `--body @number.json`. See [Import phone number](/api-reference/phone-numbers/import). |
| `numbers update <number> [--sms-reply true\|false] [--sms-prompt TEXT\|@file\|null] [--dtmf true\|false\|null] [--set k=v ...]` | `--dtmf null` inherits the agent setting. See [Update phone number](/api-reference/phone-numbers/update). |
| `numbers delete <number> --confirm` | Disconnects from Nixflex; your carrier keeps the number. |
| `numbers monitor <number> [get\|on\|off]` | Enabling is free. The listening premium applies only when a live listener actually attaches to the call, inbound or outbound. |
| `numbers web-calls <number> [get\|on\|off]` | Browser calls for the number. |

## Callers (caller context)

For all seven typed number switches and examples, see [number switches](/api-reference/phone-numbers/switches).

What the agent knows about a caller on one of your numbers. First number is yours, second is the caller's. See [Caller context](/concepts/caller-context).

| Command | Notes |
|---|---|
| `callers get <your_number> <caller_number>` | |
| `callers set <your_number> <caller_number> [--name] [--email] [--phone] [--location] [--reference] [--preference]` | Omitted fields are kept; pass `null` to remove one. |
| `callers import <your_number> <file.csv>` | Columns: `caller_number` (required), `name`, `email`, `phone`, `location`, `reference_id`, `preference`. Sent in chunks of 1,000. |
| `callers delete <your_number> <caller_number> --confirm` | Erases your fields and the engine's. |

## Errors and exit codes

Errors print as `error <status> <code>: <message>` with a link to the error's page, and the process exits with code `1`. With `--json` the same information is returned on stdout as `{ "error": { "code", "status", "message", "doc_url" } }`. No key at all exits with `2`. A mistyped command exits `1` with a suggestion.

Progress lines (imports, `--wait`) go to stderr, so stdout stays clean for pipes. All codes are listed on [Errors](/reference/errors).
