Read recording status and obtain a fresh signed download link when the managed recording is available. This operation does not read or verify an account-connected storage object.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `id` (path) | string | Yes | None | Owned call ID, including a failed-start ID if applicable. Maximum 200 characters. Minimum 1 characters. |

Do not send a request body.

Private recording access uses a 600-second link lifetime; the legacy path uses 300 seconds. Always follow expires_at. Signing an existing public object does not make its underlying public URL private. An issued link can stop working early if the content is deleted.

Status meanings: pending means explicit processing; expired means content was removed by retention; customer_bucket identifies account-connected storage without asserting availability; not_recorded is a proven never-started call; pending_deletion hides content while deletion finishes; unavailable is explicit processing failure; unknown means the record cannot prove availability. Missing historical data does not prove recording was switched off.

## Response fields

`200 OK` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `call_id` | string | The requested call ID. |
| `status` | string | available has a signed URL; other states do not. Allowed: `"available"`, `"pending"`, `"expired"`, `"customer_bucket"`, `"not_recorded"`, `"pending_deletion"`, `"unavailable"`, `"unknown"`. |
| `url` | string or null | Short-lived download URL only when available. Treat it as a bearer credential and do not log it. |
| `expires_at` | string or null | Expiry of the returned signed URL, or null. Format: date-time. |

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Kit examples use the supplied Node/CLI 0.11.0 and Python 0.4.0 candidates; these versions are unpublished. Set `NXF_CALL_ID` to the intended account-owned identifiers or approved recipient before running.

<RequestExample>

```bash cURL
curl --request GET \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/calls/$NXF_CALL_ID/recording" \
  --header "Authorization: Bearer $NXF_STAGING_KEY"
```

```javascript Node
import Nixflex from 'nixflex';
const baseUrl = 'https://nixflex-voice-engine-staging.up.railway.app';
const client = new Nixflex({apiKey:process.env.NXF_STAGING_KEY,baseUrl,maxRetries:0});
const result = await client.calls.recording(process.env.NXF_CALL_ID);
// Handle result privately; do not log secrets or call content.
```

```python Python
import os, json
from pathlib import Path
from nixflex import Nixflex
base_url = "https://nixflex-voice-engine-staging.up.railway.app"
with Nixflex(os.environ["NXF_STAGING_KEY"], base_url=base_url,max_retries=0) as client:
    result = client.calls.recording(os.environ["NXF_CALL_ID"])
# AsyncNixflex supports the same calls with await (and async with).
```

```bash CLI
NIXFLEX_API_KEY="$NXF_STAGING_KEY" nixflex calls recording "$NXF_CALL_ID" --base-url https://nixflex-voice-engine-staging.up.railway.app --json
```

</RequestExample>

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 400 | [`invalid_call_id`](/api-reference/errors#invalid_call_id) | The call ID is invalid or exceeds 200 characters. | Use the exact ID returned by a call read. |
| 404 | [`not_found`](/api-reference/errors#not_found) | The call is not available to this account. | Check the ID and owning account. |
| 503 | [`call_data_unavailable`](/api-reference/errors#call_data_unavailable) | The recording state or signed link could not be verified. | Retry the read; do not label this as not recorded. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

This is a read-only request. Retry transient connection or server failures with bounded backoff; respect Retry-After for 429. Do not retry validation or ownership errors unchanged. A later read can return newer state.
