Start one outbound call from an account-owned number assigned to an active agent. A 201 response means the call was initiated; it does not prove connection, conversation, completion or a successful outcome.

<div className="nxf-facts">
  <div><small>Method</small><strong>POST</strong></div>
  <div><small>Success</small><strong>200 / 201</strong></div>
  <div><small>Scope</small><strong>Owning account</strong></div>
</div>

<div className="nxf-important">

**The important part**

- Save one UUID request_id before a deliberate call intent if you need launch reconciliation.
- A 201 means initiated. A same-ID 200 replay returns the existing call; pending or unknown must never trigger a new UUID automatically.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential. Send `Content-Type: application/json`.

## Request fields

Send a JSON object.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `agent_id` | string | Yes | None | Owned active agent ID. Minimum 1 characters. |
| `to_number` | string | Yes | None | Recipient in E.164 format. Minimum 1 characters. |
| `prompt` | string | Yes | None | Required nonblank call purpose. No separate route-level character maximum is declared; request-size and downstream admission rules still apply. Minimum 1 characters. |
| `from_number` | string | No | Omitted | Optional owned outbound-enabled number assigned to this agent. If omitted, the oldest eligible number is selected. |
| `dynamic_vars` | object | No | Omitted | Values for `{{name}}`-style placeholders in the call purpose. Keys must match supported placeholder names. |
| `campaign_id` | string or null | No | `null` | Optional campaign association. Omitted or empty becomes null. |
| `recipient_timezone` | string | No | Omitted | Optional recipient IANA time zone. Used for recipient-local contact checks, not the business clock. |
| `recipient_country` | string | No | Omitted | Optional two-letter recipient country code. |
| `request_id` | string | No | Omitted | Account-scoped UUID for one call intent. Save it before sending. Reusing it never starts a second call; changed input conflicts. Format: uuid. Pattern: `^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[1-8][0-9a-fA-F]{3}-[89aAbB][0-9a-fA-F]{3}-[0-9a-fA-F]{12}$`. |

Only send to a recipient you are authorised to contact. This endpoint has no dry-run option. The examples use an explicit recipient variable and can place a real call when run. Optional recipient location values do not override suppression, contact hours or capacity rules.

Use dynamic_vars for single-call substitutions; campaign recipient variables are a different contract. There is no fallback to an agent-level phone_number. When from_number is omitted, selection uses the oldest eligible number by creation time then row ID. Selection does not bypass the final ownership and availability checks. Contact-hours refusals use error.code outside_hours or needs_timezone (409), or contact_policy_unavailable (503). Details include outcome:not_sent, sent:false and charged:false. Advisory messages can instead start “Outside calling hours” or “Weekend where they are” and contain the next local window. single_contact_policy is an internal policy-check name, not an HTTP error code. refused_before_dispatch is a dispatch outcome marker, not an HTTP status or a replacement error.code. Unknown outcome is not proof that nothing was sent.

Optional `request_id` is a UUID saved before one deliberate call intent. Required prompt and the existing behavior without a request ID remain unchanged. A same-ID accepted replay returns HTTP 200 with the same call_id and replayed:true; it does not return to/from. Pending/unknown repeats return 409 and never dispatch again. A 201 with request_status:unconfirmed still preserves the known call ID and safe_to_retry:false. Read the saved UUID through [outbound request status](/api-reference/calls/get-outbound-request).

## Response fields

`201 Created` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `call_id` | string | Accepted call identifier. Save it for reads and reconciliation. |
| `status` | string | The call was initiated, not completed. |
| `to` | string | Requested recipient. |
| `from` | string | Selected originating number. |
| `work_id` | string or null | Optional account work receipt ID. |
| `deletion_work_id` | string | Optional dispatch/deletion safety receipt ID. |
| `persistence` | string | Optional unconfirmed state if accepted work could not be fully saved. |
| `safe_to_retry` | boolean | When supplied, false: do not repeat an accepted or uncertain call. |
| `request_id` | string | Present when the call intent supplied a request UUID. Format: uuid. Pattern: `^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[1-8][0-9a-fA-F]{3}-[89aAbB][0-9a-fA-F]{3}-[0-9a-fA-F]{12}$`. |
| `request_status` | string | The accepted call is known but the final request-journal acknowledgement is unconfirmed. Do not redial. |

HTTP 200 is the accepted replay shape: `call_id`, `request_id`, `status:"initiated"` and `replayed:true`. Unlike the first 201 response, it does not require `to` or `from`.

## Example request

These examples use staging and can place a real call. Set NXF_STAGING_KEY, the owned agent and number, and an approved recipient before running. The cURL example also needs a durably saved NXF_REQUEST_ID. Keep the host and credential in the same environment.

The cURL tab demonstrates the new request UUID. Node/CLI 0.11.0 and Python 0.4.0 are reviewed unpublished candidates; their existing examples below omit request_id and retain the older launch behaviour. Use the cURL request when UUID reconciliation is needed until support is verified in the installed client. No example retries a write.

<RequestExample>

```bash cURL · saved UUID
# Save NXF_REQUEST_ID durably before this first deliberate launch.
# Set NXF_TO_NUMBER to an approved recipient; this can place a real call.
curl --request POST \
  --url 'https://nixflex-voice-engine-staging.up.railway.app/v1/calls/outbound' \
  --header "Authorization: Bearer $NXF_STAGING_KEY" \
  --header 'Content-Type: application/json' \
  --data "{\"agent_id\":\"$NXF_AGENT_ID\",\"to_number\":\"$NXF_TO_NUMBER\",\"prompt\":\"Confirm the requested appointment\",\"request_id\":\"$NXF_REQUEST_ID\"}"
```

```javascript Node · without UUID
import Nixflex from 'nixflex';
const baseUrl = 'https://nixflex-voice-engine-staging.up.railway.app';
const client = new Nixflex({apiKey:process.env.NXF_STAGING_KEY,baseUrl,maxRetries:0});
const result = await client.calls.create({agent_id:process.env.NXF_AGENT_ID,from_number:process.env.NXF_PHONE_NUMBER,to_number:process.env.NXF_TO_NUMBER,prompt:"Confirm the requested appointment"});
// Handle result privately; do not log secrets or call content.
```

```python Python · without UUID
import os, json
from pathlib import Path

with Nixflex(os.environ["NXF_STAGING_KEY"], base_url=base_url,max_retries=0) as client:
    result = client.calls.create(agent_id=os.environ["NXF_AGENT_ID"],from_number=os.environ["NXF_PHONE_NUMBER"],to_number=os.environ["NXF_TO_NUMBER"],prompt="Confirm the requested appointment")
# AsyncNixflex supports the same calls with await (and async with).
```

```bash CLI · without UUID
NIXFLEX_API_KEY="$NXF_STAGING_KEY" nixflex calls create --agent "$NXF_AGENT_ID" --from "$NXF_PHONE_NUMBER" --to "$NXF_TO_NUMBER" --prompt "Confirm the requested appointment" --base-url https://nixflex-voice-engine-staging.up.railway.app --json
```

</RequestExample>

## Retry and idempotency

Save one UUID before the first request for an intended call. Persist it with the request payload so a process restart cannot accidentally create a new intent. Supply it as the JSON field `request_id`, not an Idempotency-Key header.

| Result | What it proves | Next action |
| --- | --- | --- |
| 201 initiated | A call was accepted; completion is still unknown. | Save call_id and request_id; read the call. |
| 200 replayed:true | This UUID already has an accepted call. | Use the same call_id; no second dispatch occurred. |
| 409 outbound_request_pending / outbound_request_unknown | The existing intent cannot be launched again. | Keep the UUID and read request status. |
| 409 request_id_conflict | The same UUID was used with changed input. | Reconcile the original payload; do not automatically replace the UUID. |
| 503 with details.safe_to_retry:false | The journal or launch outcome is uncertain. | Keep the UUID and use bounded status reads. |

A 201 can also include `request_status:"unconfirmed"` and `safe_to_retry:false`: the call ID is known even though the final journal acknowledgement was lost. Never redial it. A new UUID is a new explicit call intent. Requests without request_id retain their existing behaviour and have no launch replay protection.

Read [outbound request status](/api-reference/calls/get-outbound-request). A 404 or an empty history page does not prove that an uncertain call was never placed.
