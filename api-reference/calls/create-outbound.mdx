Start one outbound call from an account-owned number assigned to an active agent. A 201 response means the call was initiated; it does not prove connection, conversation, completion or a successful outcome.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential. Send `Content-Type: application/json`.

## Request fields

Send a JSON object.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `agent_id` | string | Yes | None | Owned active agent ID. Minimum 1 characters. |
| `to_number` | string | Yes | None | Recipient in E.164 format. Minimum 1 characters. |
| `prompt` | string | Yes | None | Required nonblank call purpose. No separate route-level character maximum is declared; request-size and downstream admission rules still apply. Minimum 1 characters. |
| `from_number` | string | No | Omitted | Optional owned outbound-enabled number assigned to this agent. If omitted, the oldest eligible number is selected. |
| `dynamic_vars` | object | No | Omitted | Values for `{{name}}`-style placeholders in the call purpose. Keys must match supported placeholder names. |
| `campaign_id` | string or null | No | `null` | Optional campaign association. Omitted or empty becomes null. |
| `recipient_timezone` | string | No | Omitted | Optional recipient IANA time zone. Used for recipient-local contact checks, not the business clock. |
| `recipient_country` | string | No | Omitted | Optional two-letter recipient country code. |

Only send to a recipient you are authorised to contact. This endpoint has no dry-run option. The examples use an explicit recipient variable and can place a real call when run. Optional recipient location values do not override suppression, contact hours or capacity rules.

Use dynamic_vars for single-call substitutions; campaign recipient variables are a different contract. There is no fallback to an agent-level phone_number. When from_number is omitted, selection uses the oldest eligible number by creation time then row ID. Selection does not bypass the final ownership and availability checks.

## Response fields

`201 Created` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `call_id` | string | Accepted call identifier. Save it for reads and reconciliation. |
| `status` | string | The call was initiated, not completed. |
| `to` | string | Requested recipient. |
| `from` | string | Selected originating number. |
| `work_id` | string or null | Optional account work receipt ID. |
| `deletion_work_id` | string | Optional dispatch/deletion safety receipt ID. |
| `persistence` | string | Optional unconfirmed state if accepted work could not be fully saved. |
| `safe_to_retry` | boolean | When supplied, false: do not repeat an accepted or uncertain call. |

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Set `NXF_AGENT_ID`, `NXF_TO_NUMBER` to the intended account-owned identifiers or approved recipient before running. Running a successful example contacts the recipient; use only an approved test destination.

<RequestExample>

```bash cURL
curl --request POST \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/calls/outbound" \
  --header "Authorization: Bearer $NXF_STAGING_KEY" \
  --header "Content-Type: application/json" \
  --data "{\"agent_id\":\"$NXF_AGENT_ID\",\"to_number\":\"$NXF_TO_NUMBER\",\"prompt\":\"Confirm the appointment time requested by the recipient.\"}"
```

```javascript Node
import { Nixflex } from 'nixflex';

const client = new Nixflex({
  apiKey: process.env.NXF_STAGING_KEY,
  baseUrl: 'https://nixflex-voice-engine-staging.up.railway.app',
  maxRetries: 0,
});
const body = {
  "agent_id": process.env.NXF_AGENT_ID,
  "to_number": process.env.NXF_TO_NUMBER,
  "prompt": "Confirm the appointment time requested by the recipient."
};
const result = await client.calls.create(body);
console.log('Request completed.');
```

```python Python
import os
from nixflex import Nixflex

body = {
  "agent_id": os.environ["NXF_AGENT_ID"],
  "to_number": os.environ["NXF_TO_NUMBER"],
  "prompt": "Confirm the appointment time requested by the recipient."
}

with Nixflex(
    api_key=os.environ["NXF_STAGING_KEY"],
    base_url="https://nixflex-voice-engine-staging.up.railway.app",
    max_retries=0,
) as client:
    result = client.calls.create(**body)
    print("Request completed.")
```

```bash CLI
NIXFLEX_API_KEY="$NXF_STAGING_KEY" nixflex calls create --agent "$NXF_AGENT_ID" --to "$NXF_TO_NUMBER" --prompt "Confirm the appointment time requested by the recipient." \
  --base-url "https://nixflex-voice-engine-staging.up.railway.app" --json
```

</RequestExample>

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

## Retry and idempotency

Never automatically retry POST, including after 429, a timeout or 5xx. A failed response can be uncertain after dispatch. Save call_id, work_id and safe error details when returned; inspect call history and known IDs before any deliberate new call. An initiated response with persistence: unconfirmed must not be replayed.
