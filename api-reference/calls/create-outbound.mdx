---
title: "Create outbound call"
description: "POST /v1/calls/outbound"
api: "POST https://api.nixflex.com/v1/calls/outbound"
---

Triggers Nixflex to call a phone number. The agent dials, waits for pickup, runs voicemail detection, and starts the conversation when a human answers.

<Note>
  You don't pass a `from_number`. The engine uses the Twilio number assigned to your agent via the [phone numbers](/api-reference/phone-numbers/import) endpoint. Make sure your agent has a phone number assigned first.
</Note>

## Request

```bash
curl -X POST https://api.nixflex.com/v1/calls/outbound \
  -H "Authorization: Bearer KEY_ID:KEY_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "agent_id": "agent_125207e452f8714a",
    "to_number": "+447386172392",
    "prompt": "You are Sarah from Bright Smile Dental. Call to remind {patient_name} about their appointment on {appointment_time} and confirm they can still attend.",
    "dynamic_vars": {
      "patient_name": "Sarah",
      "appointment_time": "Tuesday at 2pm"
    }
  }'
```

## Body parameters

| Field | Type | Required | Notes |
|---|---|---|---|
| `agent_id` | string | Yes | Agent that will handle this call |
| `prompt` | string | Yes | The call purpose - what the agent should say and why it is calling. Sent fresh per call, stored nowhere. Separate from the agent's own prompt. |
| `to_number` | string | Yes | Recipient in E.164 format (`+44...`) |
| `dynamic_vars` | object | No | Key-value pairs injected into the agent's prompt |
| `campaign_id` | string | No | Link this call to a batch campaign |

## Dynamic variables

Variables in `dynamic_vars` are interpolated into the system prompt. In your prompt, reference them with curly braces:

```
You are calling {patient_name} about their appointment on {appointment_time}.
```

The engine replaces `{patient_name}` with `"Sarah"` before sending to the agent. If a variable referenced in the prompt isn't in `dynamic_vars`, it's left as-is (the agent will see the literal `{patient_name}`).

## Response

`201 Created`:

```json
{
  "call_id": "CA1234567890",
  "status": "initiated",
  "to": "+447386172392",
  "from": "+447446466847"
}
```

The response returns immediately. Twilio dials within ~5 seconds. The actual call lifecycle (ringing -> connected -> ended) happens asynchronously - you'll get a webhook when the call ends if you have `webhook_url` set on the agent.

## Validation order

The engine validates in this order:

1. `agent_id`, `to_number`, and `prompt` are present
2. `to_number` is E.164 format (e.g. `+447386172392`, not `07386172392`)
3. Agent belongs to your API key
4. Agent has a phone number assigned (via the phone_numbers table)
5. Twilio credentials exist for that phone number

If any check fails, you get a 400 with the specific `code`.

## Errors

| Code | HTTP | Cause |
|---|---|---|
| `missing_field` | 400 | `agent_id`, `to_number`, or `prompt` missing |
| `invalid_phone_format` | 400 | `to_number` not E.164 |
| `agent_missing_phone_number` | 400 | Agent has no phone number assigned. Import one via [Phone numbers](/api-reference/phone-numbers/import) |
| `agent_missing_twilio_credentials` | 400 | Phone number has no Twilio credentials stored |
| `outbound_failed` | 502 | Twilio rejected the dial (see `details.twilio_error`) |

## What happens next

After you trigger the call:

1. Twilio dials the `to_number` using the agent's assigned phone number
2. Voicemail detection runs (AMD + speech-pattern matching)
3. If voicemail is detected, the engine ends the call
4. If a human answers, the agent starts the conversation
5. Call ends naturally or via `[END_CALL]` / timeout
6. Recording is saved, post-call analysis runs
7. Webhook fires to your agent's `webhook_url`

See [Outbound calls](/concepts/outbound-calls) for the full conceptual overview.
