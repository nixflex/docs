Read one account-owned call. Use view=detail for the explicit nullable detail shape, failed-start IDs and retained metadata stubs. Omitting view keeps the legacy row response.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `id` (path) | string | Yes | None | Call ID from this account. Detail mode accepts up to 200 characters, including failed: IDs. Maximum 200 characters. |
| `view` (query) | string | No | Omitted | detail selects the explicit detail response. Omitted or another value selects the legacy response. |

Do not send a request body.

Nullable fields remain null; a retained stub may omit fields. Detail mode masks expired or scheduled-for-deletion content and always returns recording_url: null. Use the recording endpoint for a fresh link. This read does not restore erased content. The response example is illustrative, not a claim that a recording exists.

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Set `NXF_CALL_ID` to the intended account-owned identifiers or approved recipient before running.

<RequestExample>

```bash cURL
curl --request GET \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/calls/$NXF_CALL_ID?view=detail" \
  --header "Authorization: Bearer $NXF_STAGING_KEY"
```

```javascript Node
import { Nixflex } from 'nixflex';

const client = new Nixflex({
  apiKey: process.env.NXF_STAGING_KEY,
  baseUrl: 'https://nixflex-voice-engine-staging.up.railway.app',
  maxRetries: 0,
});
const result = await client.calls.read(process.env.NXF_CALL_ID);
console.log('Request completed.');
```

```python Python
import os
from nixflex import Nixflex

with Nixflex(
    api_key=os.environ["NXF_STAGING_KEY"],
    base_url="https://nixflex-voice-engine-staging.up.railway.app",
    max_retries=0,
) as client:
    result = client.calls.read(os.environ["NXF_CALL_ID"])
    print("Request completed.")
```

```bash CLI
NIXFLEX_API_KEY="$NXF_STAGING_KEY" nixflex calls read "$NXF_CALL_ID" \
  --base-url "https://nixflex-voice-engine-staging.up.railway.app" --json
```

</RequestExample>

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 400 | [`invalid_call_id`](/api-reference/errors#invalid_call_id) | The detail-mode ID is empty or exceeds 200 characters. | Use the exact ID returned by a list. |
| 404 | [`not_found`](/api-reference/errors#not_found) | The call is absent, explicitly deleted or owned by another account. | Check the account and call ID; do not infer another account’s data. |
| 503 | [`call_data_unavailable`](/api-reference/errors#call_data_unavailable) | Call data could not be read safely. | Retry the read after recovery; absence has not been proved. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

This is a read-only request. Retry transient connection or server failures with bounded backoff; respect Retry-After for 429. Do not retry validation or ownership errors unchanged. A later read can return newer state.
