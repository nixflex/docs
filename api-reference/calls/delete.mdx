Guarded cleanup request for an owned call. Can refuse with 409/503 for in-progress/unsettled work or pending/failed cleanup. Not a promise of immediate all-copy erasure. Never blindly retry an uncertain response.

## Authentication

Use `Authorization: Bearer KEY_ID:KEY_SECRET` for the owning account. An organisation API key has Owner authority. Personal sessions use the role rules documented in [Authentication](/api-reference/authentication); do not treat a Member session as an API key.

## Request fields

| Field | Type | Required | Default and limits |
| --- | --- | --- | --- |
| `id` (path) | string | Yes |  |

Do not send a request body.

Requests guarded cleanup of one owned call. It is not a promise of immediate erasure of every copy.

An ended, settled call with a skipped managed recording can now complete a narrow empty-recording path. It requires proof of no stored object or carrier copy, a closed upload fence, complete saved call context, finished post-call work and settlement, no active writers/read leases or unknown copies, and a fresh owned-resource absence check. Any missing or unknown proof keeps the strict 409 refusal. A stored object row in any state does not qualify. Bulk and account deletion are unchanged.

A recording marked unavailable (tracking_unavailable), an empty URL or zero recorded seconds is not proof of erasure. The call may have completed normally while deletion remains pending. The narrow path makes no carrier or storage DELETE request.

### Not reversible

<Warning>Completed removal cannot be undone through this API. Do not promise immediate completion, automatic retry or removal from customer-owned storage and external copies. Lost replies leave the outcome unknown: check before retrying.</Warning>

Billing and retained financial evidence are unaffected. Call usage remains part of the account's financial records. This operation does not promise to remove webhook delivery logs.

## Response fields

`200` returns the following shape.

| Field | Type | Meaning |
| --- | --- | --- |
| `call_id` | string | Always returned. |
| `deleted` | boolean | Always returned. |
| `recording_deleted` | boolean | Whether legacy cleanup counted at least one requested recording or transfer-audio path. False for the successful narrow empty-recording path; not proof that a recording existed or every copy was erased. |

The example shows successful narrow empty-recording cleanup: `deleted` is true and `recording_deleted` is false.

`recording_deleted` reflects whether the legacy cleanup path counted a requested recording or transfer-audio path. That path can request removal of a possible transfer-audio object even when none exists. The flag is not proof that a recording existed or every copy was erased. A refused or unknown request must not be shown as deleted.

## Errors

Branch on `error.code`, not the wording of `error.message`. The envelope includes `type`, `code`, `message`, `doc_url` and `details`.

| Status | Meaning |
| --- | --- |
| 400 | Invalid request - missing or malformed parameters. |
| 401 | Authentication failed - bad or missing API key. |
| 404 | Not found on your account. |
| 409 | Call work, settlement or recording cleanup is unfinished. details.deleted=false and details.safe_to_retry=false; do not claim deletion or automatically repeat the request. |
| 429 | Rate limit exceeded. Honour the Retry-After header. |
| 503 | Deletion safety could not be confirmed. No completed deletion is claimed; preserve the unknown/pending state. |

| Status | Code | Meaning |
|---|---|---|
| 404 | `not_found` | No call with that ID on your account. Also returned for a call you have already deleted. |
| 409 | `call_in_progress` | The call is still in progress; wait for it to end. |
| 409 | `deletion_unsettled` | Outcome/charge is not confirmed; do not claim deletion. |
| 409 | `recording_cleanup_pending`, `cleanup_pending_confirmation` | Storage/transfer-audio cleanup needs confirmation; contact support. |
| 409 | `deletion_cleanup_failed` | Cleanup did not finish; contact support before retrying. |
| 503 | `deletion_unavailable` | Safety could not be checked; deletion is not confirmed. |

Only calls made with your own API key can be deleted; another account's call ID returns the same `404`.

Safety refusals include `details.deleted=false`, `details.account_locked=false`, the `reason` code, nullable `review_due`, and `details.safe_to_retry=false`. A review timestamp is not a promise that cleanup will finish by that time. Keep the pending state and reconcile through support before another deliberate action.

## Retry and idempotency

Disable automatic write retries. A lost response leaves the result uncertain; read the affected resource before another deliberate action. No general Idempotency-Key replay guarantee applies. See [retry rules](/api-reference/retries).
