## Authentication

Use `Authorization: Bearer KEY_ID:KEY_SECRET` for the owning account. An organisation API key has Owner authority. Personal sessions use the role rules documented in [Authentication](/api-reference/authentication); do not treat a Member session as an API key.

## Request fields

| Field | Type | Required | Default and limits |
| --- | --- | --- | --- |
| `request_id` (path) | string | Yes | The UUID saved for the original call intent. |

Do not send a request body.

Use the same UUID that was saved before the launch request. This is an account-scoped lookup. Invalid, absent and foreign UUIDs share one 404. The response uses Cache-Control: no-store.

## Response fields

`200 OK` returns `request_id`, `state`, `call_id` and `reason`. The last two fields can be null. The response is `Cache-Control: no-store`.

| State | Meaning | Next action |
| --- | --- | --- |
| pending | The saved intent is still being checked. | Keep the UUID and refresh the read with a limit. |
| accepted | A call ID was recorded; the call may not be complete. | Read that call ID. |
| rejected | A bounded refusal was recorded. | Review reason and correct the cause before a new deliberate intent. |
| unknown | The launch outcome cannot be confirmed. | Keep the UUID and reconcile; never automatically redial. |

Pending records display unknown after 15 minutes. They are never recycled into another dispatch. Neither a 404 nor an unavailable status read makes a new UUID safe automatically.

## Errors

Branch on `error.code`, not the wording of `error.message`. The envelope includes `type`, `code`, `message`, `doc_url` and `details`.

| Status / code | What it means | What to do |
| --- | --- | --- |
| 401 · `unauthorized` | The credential is missing or invalid. | Check the full account credential and API host privately; stop the retry loop. |
| 403 · `permission_denied` | This actor cannot perform the operation. | Resolve the account or role restriction through an authorised person. |
| 404 · `not_found` | UUID is invalid, missing or foreign. Reconcile the original intent; do not automatically redial. | Check the exact owned identifier and current resource state; do not probe another account. |
| 429 · `rate_limit_exceeded` | The request limit was reached. | Wait at least Retry-After and use a bounded read retry. |
| 503 · `outbound_request_unavailable` | The status read failed. Keep the previous uncertainty and retry the read. | Keep the saved UUID and retry this status read with bounded backoff. Do not launch another call. |

Keep the UUID after a 503 or lost response. Retry this status read with bounded backoff. Neither an unavailable read nor a 404 authorises an automatic new call or a replacement UUID.

## Retry and idempotency

This read does not reserve an intent, place a call or charge the account. Retry temporary read failures with bounded backoff while keeping the saved UUID. A failed read or 404 is not permission to launch with a new UUID. This endpoint is not paginated.
