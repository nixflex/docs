## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `limit` (query) | integer | No | `50` | Positive parsed integer, capped at 200. Missing, zero, negative or unparseable values use 50. Minimum 1. Maximum 200. |
| `offset` (query) | integer | No | `0` | Parsed offset. Missing, negative or unparseable values use zero. Minimum 0. |
| `view` (query) | string | No | Omitted | history selects the history envelope and its different filtering rules. Other values keep the legacy array. |

Do not send a request body.

Legacy mode ignores unsupported filters such as agent_id. It has no total or next_cursor. Increase offset by the returned length and stop on an empty/short page within the 200-row cap. Offset reads are not a frozen snapshot; concurrent writes can shift rows. Legacy responses can contain retained transcript/recording fields, so handle them as private account data.

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Kit examples require Node/CLI 0.11.0 or later and Python 0.4.0 or later.

<RequestExample>

```bash cURL
curl --request GET \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/calls?limit=25&offset=0" \
  --header "Authorization: Bearer $NXF_STAGING_KEY"
```

```javascript Node
import Nixflex from 'nixflex';
const baseUrl = 'https://nixflex-voice-engine-staging.up.railway.app';
const client = new Nixflex({apiKey:process.env.NXF_STAGING_KEY,baseUrl,maxRetries:0});
const result = await client.calls.list({limit:25,offset:0});
// Handle result privately; do not log secrets or call content.
```

```python Python
import os, json
from pathlib import Path
from nixflex import Nixflex
base_url = "https://nixflex-voice-engine-staging.up.railway.app"
with Nixflex(os.environ["NXF_STAGING_KEY"], base_url=base_url,max_retries=0) as client:
    result = client.calls.list(limit=25,offset=0)
# AsyncNixflex supports the same calls with await (and async with).
```

```bash CLI
NIXFLEX_API_KEY="$NXF_STAGING_KEY" nixflex calls list --limit 25 --offset 0 --base-url https://nixflex-voice-engine-staging.up.railway.app --json
```

</RequestExample>

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 400 | [`invalid_call_history`](/api-reference/errors#invalid_call_history) | A history-mode query is invalid. | Use the history filter/cursor rules when view=history. |
| 500 | [`server_error`](/api-reference/errors#server_error) | Legacy call rows could not be read. | Retry a bounded read after recovery. |
| 503 | [`call_data_unavailable`](/api-reference/errors#call_data_unavailable) | History data could not be confirmed. | Retry the read; do not turn the failure into an empty page. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

This is a read-only request. Retry transient connection or server failures with bounded backoff; respect Retry-After for 429. Do not retry validation or ownership errors unchanged. A later read can return newer state.
