Read stored account usage and call-capacity information. Occupancy can include unresolved reservations, so it is not simply the number of connected conversations.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential.

## Request fields

No request body or query fields are required.

No request fields are required. The three reservation fields are present only when that capacity implementation is enabled. Historical counters are not a complete billing ledger. Optional fields can be absent; preserve null values instead of turning them into zero.

## Response fields

`200 OK` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `plan` | string or null | Saved account plan label. |
| `total_calls` | number or null | Stored account call counter. |
| `total_minutes` | number or null | Stored account minutes; can be fractional. |
| `total_cost` | number or null | Stored account cost value; this is not an invoice or independent carrier charge total. |
| `rate_limit_per_minute` | number or null | Saved request limit. Request headers describe the effective limit. |
| `max_concurrent` | integer | Current configured call capacity; legacy fallback is 10 when no positive limit is stored. Minimum 0. |
| `peak_concurrent_this_month` | integer | Observed monthly peak; legacy telemetry is best effort. Minimum 0. |
| `rejected_at_cap_this_month` | integer | Recorded monthly refusals at capacity; best-effort telemetry can be zero when unavailable. Minimum 0. |
| `occupied_call_slots` | integer | Optional owned reservation count, including unresolved reservations. Minimum 0. |
| `capacity_source` | string | Present with owned-reservation capacity. |
| `capacity_measured_since` | string or null | Optional start of capacity measurement. Format: date-time. |

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Kit examples use the supplied Node/CLI 0.11.0 and Python 0.4.0 candidates; these versions are unpublished.

<RequestExample>

```bash cURL
curl --request GET \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/usage" \
  --header "Authorization: Bearer $NXF_STAGING_KEY"
```

```javascript Node
import Nixflex from 'nixflex';
const baseUrl = 'https://nixflex-voice-engine-staging.up.railway.app';
const client = new Nixflex({apiKey:process.env.NXF_STAGING_KEY,baseUrl,maxRetries:0});
const result = await client.usage.get();
// Handle result privately; do not log secrets or call content.
```

```python Python
import os, json
from pathlib import Path
from nixflex import Nixflex
base_url = "https://nixflex-voice-engine-staging.up.railway.app"
with Nixflex(os.environ["NXF_STAGING_KEY"], base_url=base_url,max_retries=0) as client:
    result = client.usage.get()
# AsyncNixflex supports the same calls with await (and async with).
```

```bash CLI
NIXFLEX_API_KEY="$NXF_STAGING_KEY" nixflex usage --base-url https://nixflex-voice-engine-staging.up.railway.app --json
```

</RequestExample>

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 503 | [`capacity_lookup_unavailable`](/api-reference/errors#capacity_lookup_unavailable) | The current owned call capacity could not be confirmed. | Wait and retry the read; do not invent zero occupancy. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

This is a read-only request. Retry transient connection or server failures with bounded backoff; respect Retry-After for 429. Do not retry validation or ownership errors unchanged. A later read can return newer state.
