Replace the current account secret immediately. The key ID remains the same; the old secret stops working when rotation succeeds. The organisation signing secret is separate and does not rotate here.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential.

## Request fields

No request body or query fields are required.

No path, query or body fields are required. Use the current account credential. Coordinate application secret replacement and a possible interruption; this endpoint provides no overlap window for old and new secrets.

## Response fields

`200 OK` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `message` | string | Save the returned credential securely; the secret is returned only by creation or rotation. |
| `key_id` | string | Stable API account identifier. |
| `key_secret` | string | Sensitive secret. Never log, share or commit it. |

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Set `NXF_SECRET_RESPONSE_FILE` to a new file in a private, access-restricted location before using cURL or CLI. Save the returned secret in your secret store; do not log or commit the response.

<RequestExample>

```bash cURL
curl --request POST \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/keys/rotate" \
  --header "Authorization: Bearer $NXF_STAGING_KEY" \
  --output "$NXF_SECRET_RESPONSE_FILE"
```

```javascript Node
import { Nixflex } from 'nixflex';

const client = new Nixflex({
  apiKey: process.env.NXF_STAGING_KEY,
  baseUrl: 'https://nixflex-voice-engine-staging.up.railway.app',
  maxRetries: 0,
});
const result = await client.keys.rotate();
// Save result.key_secret in your secret store; do not log it.
```

```python Python
import os
from nixflex import Nixflex

with Nixflex(
    api_key=os.environ["NXF_STAGING_KEY"],
    base_url="https://nixflex-voice-engine-staging.up.railway.app",
    max_retries=0,
) as client:
    result = client.keys.rotate()
    # Save result["key_secret"] in your secret store; do not log it.
```

```bash CLI
NIXFLEX_API_KEY="$NXF_STAGING_KEY" nixflex keys rotate --confirm \
  --base-url "https://nixflex-voice-engine-staging.up.railway.app" --json > "$NXF_SECRET_RESPONSE_FILE"
```

</RequestExample>

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 500 | [`server_error`](/api-reference/errors#server_error) | The rotation result could not be confirmed. | Do not rotate again blindly. Check which credential still authenticates and use the account recovery process if the new secret was lost. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

Never automatically retry rotation. A repeated successful request invalidates the previous newly issued secret. Save the response in a secret store, update all consumers, and verify authentication without printing credentials.
