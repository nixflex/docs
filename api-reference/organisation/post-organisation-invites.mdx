Send a 24-hour team invitation. The invited person accepts using their own verified login. Opening an email does not accept the invitation.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` for server-side organisation API-key authority, or a verified personal dashboard Bearer session. The shared API key has Owner authority for these methods; keep it server-side. A personal session is checked against current membership and MFA. Owner and Admin personal sessions are allowed. Members are refused. Admins can act on Member invitations only; Owner authority can act on Admin or Member invitations. The environment must have organisations enabled; otherwise these routes return 404. Personal invitation acceptance, leaving and ownership transfer are separate dashboard flows and are not API-key methods. Send `Content-Type: application/json`.

## Request fields

Send a JSON object.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `email` | string | Yes | None | Invited email; trimmed and lowercased by the service. Maximum 254 characters. |
| `role` | string | Yes | None | Required team role; owner is not accepted. Allowed: `"admin"`, `"member"`. |

Delivery can be sent, failed or unknown. A sent receipt confirms email-provider acceptance only. If delivery is uncertain, read the team list before deciding whether to resend. Never accept an invitation using the shared API key.

## Response fields

`201 Created` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

### New invitation receipt

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | UUID identifier. Format: uuid. |
| `delivery` | string | Email submission outcome; sent is not inbox delivery. Allowed: `"sent"`, `"failed"`, `"unknown"`. |
| `expires_in` | integer | Invitation lifetime in seconds. Value: `86400`. |

### Existing invitation receipt

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | UUID identifier. Format: uuid. |
| `delivery` | string | Stored delivery status. Allowed: `"pending"`, `"sent"`, `"failed"`, `"unknown"`. |
| `created` | boolean | An existing receipt was returned without a new invitation. Value: `false`. |

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Kit tabs use the reviewed Node/CLI 0.10.0 and Python 0.3.0 unpublished candidates. Method presence does not promise complete field coverage.

<RequestExample>

```bash cURL
curl --request POST \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/organisation/invites" \
  --header "Authorization: Bearer $NXF_STAGING_KEY" \
  --header "Content-Type: application/json" \
  --data '{"email":"person@example.com","role":"member"}'
```

```javascript Node
import { Nixflex } from 'nixflex';

const client = new Nixflex({
  apiKey: process.env.NXF_STAGING_KEY,
  baseUrl: 'https://nixflex-voice-engine-staging.up.railway.app',
  maxRetries: 0,
});
const body = {
  "email": "person@example.com",
  "role": "member"
};
const result = await client.organisation.invite("person@example.com", "member");
// Handle the result privately; do not log credentials or destination URLs.
```

```python Python
import os
from nixflex import Nixflex

body = {
  "email": "person@example.com",
  "role": "member"

with Nixflex(
    api_key=os.environ["NXF_STAGING_KEY"],
    base_url="https://nixflex-voice-engine-staging.up.railway.app",
    max_retries=0,

    result = client.organisation.invite("person@example.com", "member")
    # Handle the result privately; never log credentials or destination URLs.
```

```bash CLI
NIXFLEX_API_KEY="$NXF_STAGING_KEY" nixflex organisation invite --set email=person@example.com --set role=member --confirm \
  --base-url "https://nixflex-voice-engine-staging.up.railway.app" --json
```

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

## Retry and idempotency

No idempotency key is accepted. After a timeout or 503, read the current team or organisation state before repeating the action. Invitation creation and resend can send email and consume quota; never replay them blindly.
