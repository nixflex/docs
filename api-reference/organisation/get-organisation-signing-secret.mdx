Explicitly retrieve the organisation signing secret for verifying event deliveries. Keep the result in a private secret store; never expose it in logs, chat or tool output.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` for server-side organisation API-key authority, or a verified personal dashboard Bearer session. The shared API key has Owner authority for these methods; keep it server-side. A personal session is checked against current membership and MFA. Personal access is Owner only. The environment must have organisations enabled; otherwise these routes return 404. Personal invitation acceptance, leaving and ownership transfer are separate dashboard flows and are not API-key methods.

## Request fields

No request body or query fields are required.

The organisation context and member list never contain this secret. There is no candidate SDK, CLI or MCP reveal method. The cURL example writes only to a new private response file; handle the response privately in code. Automated C6 checks perform authentication refusal only; a successful reveal is pending manual test.

## Response fields

`200 OK` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `signing_secret` | string | Private organisation signing secret. Independent of API-key rotation. |

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Set `NXF_SECRET_RESPONSE_FILE` to a new file in a private, access-restricted location. Never log or share the returned secret. Tabs labelled **direct HTTP** do not rely on an SDK or CLI method; the reviewed kit has no matching method.

<RequestExample>

```bash cURL
curl --request GET \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/organisation/signing-secret" \
  --header "Authorization: Bearer $NXF_STAGING_KEY" \
  --output "$NXF_SECRET_RESPONSE_FILE"
```

```javascript Node (direct HTTP)
const response = await fetch(`https://nixflex-voice-engine-staging.up.railway.app/v1/organisation/signing-secret`, {

  headers: { Authorization: `Bearer ${process.env.NXF_STAGING_KEY}` },

if (!response.ok) throw new Error(`HTTP ${response.status}`);
const result = await response.json();
```

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 404 | [`not_found`](/api-reference/errors#not_found) | Organisation routes are not enabled in this environment. | Check deployment availability; do not retry unchanged. |
| 503 | [`organisation_unavailable`](/api-reference/errors#organisation_unavailable) | The organisation action could not be confirmed. | Refresh the current state before trying again. |
| 403 | [`permission_denied`](/api-reference/errors#permission_denied) | The current personal role does not allow this action. | Use an authorised personal session; do not share the organisation key. |
| 403 | [`membership_revoked`](/api-reference/errors#membership_revoked) | The personal membership has ended. | Sign in again or contact the Owner. |
| 401 | [`invalid_token`](/api-reference/errors#invalid_token) | The personal session is invalid or expired. | Sign in with your own login again. |
| 503 | [`auth_unavailable`](/api-reference/errors#auth_unavailable) | The personal session could not be verified. | Retry the read later; reconcile uncertain changes. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

This is a read-only request. Retry transient connection or server failures with bounded backoff; respect Retry-After for 429. Do not retry validation or ownership errors unchanged. A later read can return newer state.
