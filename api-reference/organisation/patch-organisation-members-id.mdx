Change a non-Owner member to Admin or Member. Only Owner authority may change roles. This is not an ownership transfer.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` for server-side organisation API-key authority, or a verified personal dashboard Bearer session. The shared API key has Owner authority for these methods; keep it server-side. A personal session is checked against current membership and MFA. Personal access is Owner only. The environment must have organisations enabled; otherwise these routes return 404. Personal invitation acceptance, leaving and ownership transfer are separate dashboard flows and are not API-key methods. Send `Content-Type: application/json`.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `id` (path) | string | Yes | None | UUID identifier. Format: uuid. |

Send a JSON object.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `role` | string | Yes | None | New role; owner is not allowed. Allowed: `"admin"`, `"member"`. |

A 200 response has live_disconnect_pending=false. A 202 response means the membership change committed but live disconnection remains unconfirmed. Neither status promises AI hand-back or ends an ongoing human call. Recheck access and current membership before retrying.

## Response fields

`200 OK` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `user_id` | string | UUID identifier. Format: uuid. |
| `state` | string | Resulting membership state. Value: `"active"`. |
| `live_disconnect_pending` | boolean | True when the membership change committed but live disconnection is unconfirmed. |

## Example request

Examples use the supplied, unpublished Node/CLI 0.11.0, Python 0.4.0 and MCP 0.5.0 candidates. Keep the staging key in `NXF_STAGING_KEY`; the PowerShell CLI reads it through `NIXFLEX_API_KEY`. The cURL example uses Bash. Use approved owned fixtures and keep configuration responses private. Python shows sync usage; AsyncNixflex uses the same method with async with and await. Configure the existing MCP installation for the same account and staging host. Save the request JSON fields from the example below in request-154.json privately before using cURL or CLI; replace fixture credentials only in that private file. Review the target and payload before this write.

```json request-154.json
{
  "role": "admin"
}
```

<RequestExample>

```bash cURL
curl --request PATCH \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/organisation/members/11111111-1111-4111-8111-111111111111" \
  --header "Authorization: Bearer $NXF_STAGING_KEY" \
  --header "Content-Type: application/json" \
  --data-binary @request-154.json
```

```javascript Node
import { Nixflex } from 'nixflex';
const c = new Nixflex({apiKey:process.env.NXF_STAGING_KEY,baseUrl:'https://nixflex-voice-engine-staging.up.railway.app',maxRetries:0});
```

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

## Retry and idempotency

No idempotency key is accepted. After a timeout or 503, read the current team or organisation state before repeating the action. Invitation creation and resend can send email and consume quota; never replay them blindly.
