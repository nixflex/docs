Invalidate the old invitation and send a replacement with a new ID and 24-hour link. Resending uses the daily invitation quota again.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` for server-side organisation API-key authority, or a verified personal dashboard Bearer session. The shared API key has Owner authority for these methods; keep it server-side. A personal session is checked against current membership and MFA. Owner and Admin personal sessions are allowed. Members are refused. Admins can act on Member invitations only; Owner authority can act on Admin or Member invitations. The environment must have organisations enabled; otherwise these routes return 404. Personal invitation acceptance, leaving and ownership transfer are separate dashboard flows and are not API-key methods.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `id` (path) | string | Yes | None | UUID identifier. Format: uuid. |

Do not send a request body.

Delivery can be sent, failed or unknown. A sent receipt confirms email-provider acceptance only. If delivery is uncertain, read the team list before deciding whether to resend. Never accept an invitation using the shared API key.

## Response fields

`200 OK` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

### New invitation receipt

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | UUID identifier. Format: uuid. |
| `delivery` | string | Email submission outcome; sent is not inbox delivery. Allowed: `"sent"`, `"failed"`, `"unknown"`. |
| `expires_in` | integer | Invitation lifetime in seconds. Value: `86400`. |

### Existing invitation receipt

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | UUID identifier. Format: uuid. |
| `delivery` | string | Stored delivery status. Allowed: `"pending"`, `"sent"`, `"failed"`, `"unknown"`. |
| `created` | boolean | An existing receipt was returned without a new invitation. Value: `false`. |

## Example request

Examples use the supplied, unpublished Node/CLI 0.11.0, Python 0.4.0 and MCP 0.5.0 candidates. Keep the staging key in `NXF_STAGING_KEY`; the PowerShell CLI reads it through `NIXFLEX_API_KEY`. The cURL example uses Bash. Use approved owned fixtures and keep configuration responses private. Python shows sync usage; AsyncNixflex uses the same method with async with and await. Configure the existing MCP installation for the same account and staging host. Review the target and payload before this write.

<RequestExample>

```bash cURL
curl --request POST \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/organisation/invites/11111111-1111-4111-8111-111111111111/resend" \
  --header "Authorization: Bearer $NXF_STAGING_KEY"
```

```javascript Node
import { Nixflex } from 'nixflex';
const c = new Nixflex({apiKey:process.env.NXF_STAGING_KEY,baseUrl:'https://nixflex-voice-engine-staging.up.railway.app',maxRetries:0});
const result = await c.organisation.resend("11111111-1111-4111-8111-111111111111");
// Keep private responses out of logs and AI conversations.
```

```python Python
import os
```

## Retry and idempotency

No idempotency key is accepted. After a timeout or 503, read the current team or organisation state before repeating the action. Invitation creation and resend can send email and consume quota; never replay them blindly.
