Remove an accepted source with explicit confirmation of affected topics.

## Authentication

Send Authorization: Bearer KEY_ID:KEY_SECRET using the owning account’s server-side API credential. API keys have Owner authority. Personal Owner and Admin may perform this action; Member is refused. Personal dashboard visibility can hide API-origin agents. Never send owner fields to select another account.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `kb` (path) | string | Yes | None | Opaque identifier. Keep it as a string. Format: uuid. |
| `id` (path) | string | Yes | None | Opaque identifier. Keep it as a string. Format: uuid. |
| `Idempotency-Key` (header) | string | Yes | None | Unique 8–128-character operation key: letters, numbers, dot, underscore, colon or hyphen. The prompt: prefix is reserved. Reuse only with the identical operation and payload. Maximum 128 characters. Minimum 8 characters. Pattern: `^[A-Za-z0-9_.:-]{8,128}$`. |

Send a JSON object.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `expected_revision` | integer | Yes | None | Latest integer revision read from this resource; it must still match when the request runs. Minimum 1. |
| `topic_ids` | array of string | Yes | None | Must include every affected current topic ID. Minimum 0 items. |
| `manual` | string | No | Omitted | Required if affected topics include manual edits. Allowed: `"keep"`, `"delete"`. |

expected_revision is the base revision. Keeping manual topics detaches this source evidence. Removal revokes pending drafts, jobs and export snapshots for the base so old copies cannot restore deleted text.

## Response fields

`200 OK` returns the fields below. Follow the job and current revision where this operation queues work; an accepted response is not proof of publication.

| Field | Type | Meaning |
| --- | --- | --- |
| `kb` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `deleted` | boolean | Value: `true`. |
| `expected_revision` | integer | Latest integer revision read from this resource; it must still match when the request runs. Minimum 1. |

## Example request

These examples target Node/CLI 0.10.0 and Python 0.3.0; confirm the installed version supports the method before use. The cURL tab uses Bash; CLI uses PowerShell. Python shows sync usage; AsyncNixflex uses the same JSON methods with async with and await. Set the staging credential in `NXF_STAGING_KEY` and the owned path identifiers shown below in environment variables. Set `NXF_IDEMPOTENCY_KEY` to a new valid key for one intended operation. This operation changes state. Review the request and disable automatic write retries.

```json request-113.json
{
  "expected_revision": 1,
  "topic_ids": [
    "22222222-2222-4222-8222-222222222222"
  ],
  "manual": "keep"
}
```

## Retry and idempotency

Use a new Idempotency-Key for each intended change. The same key with the identical operation and payload replays the stored result; a different payload conflicts. Do not automatically repeat an uncertain write. Read the current job/resource first, then reconcile with the original key. Check expected_revision against current state; a fresh key does not bypass revision checks.
