Read ordered owner-scoped knowledge events for reconciliation.

## Authentication

Send Authorization: Bearer KEY_ID:KEY_SECRET using the owning account’s server-side API credential. API keys have Owner authority. With a personal dashboard session, Owner, Admin and Member may read visible knowledge; membership is checked before and after the read. Personal dashboard visibility can hide API-origin agents.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `cursor` (query) | string | No | `"0"` | Last seen decimal sequence; use 0 initially. Pattern: `^\d+$`. |

Do not send a request body.

This endpoint returns an array, not items/next_cursor. Send the final sequence string as cursor; an empty result means caught up. Reconcile by IDs and current revisions.

## Response fields

`200 OK` returns the fields below. Follow the job and current revision where this operation queues work; an accepted response is not proof of publication.

| Field | Type | Meaning |
| --- | --- | --- |
| `[]` | array of object | Up to 100 events in increasing sequence order. |
| `[].sequence` | string | Decimal sequence string. Keep exact; pass the last sequence as cursor. |
| `[].id` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `[].kb` | string or null | Opaque identifier. Keep it as a string. Format: uuid. |
| `[].type` | string | Event name such as knowledge.updated or knowledge.job_ready. |
| `[].data` | object | Event-specific data; additional event fields can be present. |
| `[].data.revision` | one of the shapes below | Saved value. |
| `[].data.job_id` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `[].data.kind` | string | Saved value. |
| `[].data.topic_id` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `[].data.source_id` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `[].data.topic_count` | integer | Saved value. |
| `[].data.question` | string | Private unanswered observation text, when present. |
| `[].data.channel` | string | Saved value. |
| `[].data.found` | boolean | Saved value. |
| `[].created_at` | string | UTC timestamp. Format: date-time. |

## Example request

These examples target Node/CLI 0.10.0 and Python 0.3.0; confirm the installed version supports the method before use. The cURL tab uses Bash; CLI uses PowerShell. Python shows sync usage; AsyncNixflex uses the same JSON methods with async with and await. Set the staging credential in `NXF_STAGING_KEY` and the owned path identifiers shown below in environment variables. Keep private responses out of logs.

```json request-127.json
{
  "cursor": "0"
}
```

<RequestExample>

```bash cURL (Bash)
curl --request GET \

  --header "Authorization: Bearer $NXF_STAGING_KEY"
```

```javascript Node
import { Nixflex } from 'nixflex';
const c = new Nixflex({apiKey:process.env.NXF_STAGING_KEY,baseUrl:'https://nixflex-voice-engine-staging.up.railway.app',maxRetries:0});
const result = await c.knowledge.events({"cursor":"0"});
```

## Errors

Failures use `error.type`, `error.code`, `error.message`, `error.doc_url` and optional `error.details`. Knowledge failures include a request ID in details when available. Read the safe message as text. A job can return HTTP 200 with state `failed` and `error`; that is a job failure, not an HTTP error. Source failures can arise during preparation after the initial accepted response.

## Retry and idempotency

This is a read or calculation. GET requests may retry transient connection failures once with bounded backoff; respect Retry-After. Do not retry invalid input or ownership errors unchanged. POST calculations are not automatically retried.
