## Authentication

Send Authorization: Bearer KEY_ID:KEY_SECRET using the owning account’s server-side API credential. API keys have Owner authority. With a personal dashboard session, Owner, Admin and Member may read visible knowledge; membership is checked before and after the read. Personal dashboard visibility can hide API-origin agents.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `id` (path) | string | Yes | None | Opaque identifier. Keep it as a string. Format: uuid. |

Do not send a request body.

Poll with bounded backoff and respect next_retry_at for scheduled safety checks. needs_review requires explicit review; ready may mean unchanged, exported or published depending on kind/result. Never invent progress from elapsed time.

## Response fields

`200 OK` returns the fields below. Follow the job and current revision where this operation queues work; an accepted response is not proof of publication.

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `kb` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `kind` | string | Work type; includes import, discovery, publish, manual, export, delete and automatic-term maintenance. |
| `state` | string | Allowed: `"pending"`, `"running"`, `"needs_review"`, `"ready"`, `"failed"`, `"cancelled"`, `"deleted"`. |
| `stage` | string | Current work stage, including reading, preparing, indexing, safety_check or safety_waiting. |
| `progress` | object | Saved value. |
| `progress.percent` | integer | Completed-stage progress, not elapsed-time prediction. Minimum 0. Maximum 100. |
| `progress.phase` | string | Reading or naming phase. |
| `progress.page` | integer | Current page number. |
| `progress.pages` | integer | Total input pages or entries. |
| `progress.completed` | integer | Completed preparation units. |
| `progress.total` | integer | Total preparation units. |
| `result` | object or null | Fields depend on job kind. Poll the job until a terminal state or needs_review; ready alone is not a claim that new text was published. |
| `result.draft_id` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `result.warnings` | array of string | Saved value. |
| `result.summary` | object | Saved value. |
| `result.summary.pages` | integer | Website pages processed. |
| `result.summary.pieces` | integer | Prepared pieces. |
| `result.summary.duplicates_skipped` | integer | Duplicate pieces or repeated source skipped. |
| `result.unchanged` | boolean | No new publishable content was produced. |
| `result.revision` | one of the shapes below | Saved value. |
| `result.expected_revision` | integer | Latest integer revision read from this resource; it must still match when the request runs. Minimum 1. |
| `result.expires_at` | string | UTC timestamp. Format: date-time. |
| `result.deleted` | boolean | Saved value. |
| `result.private_objects_remaining` | integer | Saved value. |
| `result.pages` | array of object | Saved value. |
| `result.pages[].id` | string | Discovery page ID, use exactly as returned. |
| `result.pages[].url` | string | Discovered public page URL. |
| `result.pages[].title` | string | Discovered page title. |
| `error` | object or null | Saved value. |
| `error.code` | string | Machine-readable failure code; see the error catalog. |
| `error.message` | string | Display as escaped text; never execute or insert as HTML. |
| `next_retry_at` | string or null | UTC timestamp. Format: date-time. |
| `paid_work_started` | boolean | Whether paid preparation work began; not an invoice or an additional charge. |
| `created_at` | string | UTC timestamp. Format: date-time. |

## Example request

These examples target Node/CLI 0.11.0 and Python 0.4.0; confirm the installed version supports the method before use. The cURL tab uses Bash; CLI uses PowerShell. Python shows sync usage; AsyncNixflex uses the same JSON methods with async with and await. Set the account credential in `NIXFLEX_API_KEY` and the owned path identifiers shown below in environment variables. Keep private responses out of logs.

<RequestExample>

```bash cURL (Bash)
curl --request GET \
  --url "https://api.nixflex.com/v1/knowledge/jobs/$(node -p 'encodeURIComponent(process.env.NXF_RESOURCE_ID)')" \
  --header "Authorization: Bearer $NIXFLEX_API_KEY"
```

```javascript Node
import { Nixflex } from 'nixflex';
const c = new Nixflex({apiKey:process.env.NIXFLEX_API_KEY,baseUrl:'https://api.nixflex.com',maxRetries:0});
const result = await c.knowledge.getJob(process.env.NXF_RESOURCE_ID);
// Keep knowledge and private results out of logs.
```

```python Python
import os
from nixflex import Nixflex

with Nixflex(api_key=os.environ["NIXFLEX_API_KEY"], base_url="https://api.nixflex.com", max_retries=0) as c:
    result = c.knowledge.get_job(os.environ["NXF_RESOURCE_ID"])
    # Keep knowledge and private results out of logs.
```

```powershell CLI (PowerShell)
nixflex knowledge getJob "$env:NXF_RESOURCE_ID" --json --base-url "https://api.nixflex.com"
```

## Errors

Failures use `error.type`, `error.code`, `error.message`, `error.doc_url` and optional `error.details`. Knowledge failures include a request ID in details when available. Read the safe message as text. A job can return HTTP 200 with state `failed` and `error`; that is a job failure, not an HTTP error. Source failures can arise during preparation after the initial accepted response.

## Retry and idempotency

This is a read or calculation. GET requests may retry transient connection failures once with bounded backoff; respect Retry-After. Do not retry invalid input or ownership errors unchanged. POST calculations are not automatically retried.
