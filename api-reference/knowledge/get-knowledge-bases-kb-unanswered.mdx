Read recent real questions from delivered turns without a retrieval match.

## Authentication

Send Authorization: Bearer KEY_ID:KEY_SECRET using the owning account’s server-side API credential. API keys have Owner authority. With a personal dashboard session, Owner, Admin and Member may read visible knowledge; membership is checked before and after the read. Personal dashboard visibility can hide API-origin agents.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `kb` (path) | string | Yes | None | Opaque identifier. Keep it as a string. Format: uuid. |
| `limit` (query) | integer | No | `20` | Maximum rows in this page. Minimum 1. Maximum 100. |
| `cursor` (query) | string | No | Omitted | Opaque cursor from the prior response; omit for the first page. |

Do not send a request body.

Seven-day retention. Tester questions and load/timeout failures are excluded. Small-base whole-context mode cannot identify every unknown question, so the list is intentionally incomplete.

## Response fields

`200 OK` returns the fields below. Follow the job and current revision where this operation queues work; an accepted response is not proof of publication.

| Field | Type | Meaning |
| --- | --- | --- |
| `items` | array of object | Saved value. |
| `items[].id` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `items[].question` | string | Private question, truncated to 4,000 characters. Maximum 4000 characters. |
| `items[].channel` | string | Allowed: `"inbound"`, `"outbound"`, `"web_voice"`, `"web_chat"`, `"sms"`. |
| `items[].created_at` | string | UTC timestamp. Format: date-time. |
| `next_cursor` | string or null | Opaque cursor. Send it unchanged for the next page; null ends this list. |

## Example request

K5 examples use unpublished Node/CLI 0.10.0 and Python 0.3.0. The cURL tab uses Bash; CLI uses PowerShell. Python shows sync usage; AsyncNixflex uses the same JSON methods with async with and await. Set the staging credential in `NXF_STAGING_KEY` and the owned path identifiers shown below in environment variables. Keep private responses out of logs.

```json request-123.json
{
  "limit": 2
}
```

<RequestExample>

```bash cURL (Bash)
curl --request GET \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/knowledge-bases/$(node -p 'encodeURIComponent(process.env.NXF_KNOWLEDGE_BASE_ID)')/unanswered?limit=2" \
  --header "Authorization: Bearer $NXF_STAGING_KEY"
```

```javascript Node
import { Nixflex } from 'nixflex';
const c = new Nixflex({apiKey:process.env.NXF_STAGING_KEY,baseUrl:'https://nixflex-voice-engine-staging.up.railway.app',maxRetries:0});
const result = await c.knowledge.unanswered(process.env.NXF_KNOWLEDGE_BASE_ID, {"limit":2});
// Keep knowledge and private results out of logs.
```

```python Python
import os
from nixflex import Nixflex

with Nixflex(api_key=os.environ["NXF_STAGING_KEY"], base_url="https://nixflex-voice-engine-staging.up.railway.app", max_retries=0) as c:
    result = c.knowledge.unanswered(os.environ["NXF_KNOWLEDGE_BASE_ID"], {
      "limit": 2
    })
    # Keep knowledge and private results out of logs.
```

```powershell CLI (PowerShell)
$env:NIXFLEX_API_KEY = $env:NXF_STAGING_KEY
# Save the JSON below privately as request-123.json.
nixflex knowledge unanswered "$env:NXF_KNOWLEDGE_BASE_ID" --body '@request-123.json' --json --base-url "https://nixflex-voice-engine-staging.up.railway.app"
```

</RequestExample>

## Errors

Failures use `error.type`, `error.code`, `error.message`, `error.doc_url` and optional `error.details`. Knowledge failures include a request ID in details when available. Read the safe message as text. A job can return HTTP 200 with state `failed` and `error`; that is a job failure, not an HTTP error. Source failures can arise during preparation after the initial accepted response.

## Retry and idempotency

This is a read or calculation. GET requests may retry transient connection failures once with bounded backoff; respect Retry-After. Do not retry invalid input or ownership errors unchanged. POST calculations are not automatically retried.
