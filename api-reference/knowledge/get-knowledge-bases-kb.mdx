Read a knowledge base’s settings, revision and active published index.

## Authentication

Send Authorization: Bearer KEY_ID:KEY_SECRET using the owning account’s server-side API credential. API keys have Owner authority. With a personal dashboard session, Owner, Admin and Member may read visible knowledge; membership is checked before and after the read. Personal dashboard visibility can hide API-origin agents.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `kb` (path) | string | Yes | None | Opaque identifier. Keep it as a string. Format: uuid. |

Do not send a request body.

rev is the integer used for expected_revision. active identifies the published index and can be null.

## Response fields

`200 OK` returns the fields below. Follow the job and current revision where this operation queues work; an accepted response is not proof of publication.

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `owner` | string | Owning account identifier; it never grants access when sent by a caller. |
| `kind` | string | Knowledge belongs to an agent. Value: `"agent"`. |
| `target` | string | Owning agent ID. |
| `rev` | integer | Latest integer revision read from this resource; it must still match when the request runs. Minimum 1. |
| `active` | string or null | Active published index revision, or null before publication. Format: uuid. |
| `state` | string | Lifecycle state. Allowed: `"ready"`, `"deleting"`, `"deleted"`. |
| `settings` | object | Only channels, match and not_found may be supplied. Omitted settings retain the saved value on update. |
| `settings.channels` | array of string | Enabled knowledge channels. An empty list turns knowledge off for all channels. Allowed items: `"inbound"`, `"outbound"`, `"web_voice"`, `"web_chat"`, `"sms"`. |
| `settings.match` | string | Answer matching mode. Allowed: `"Strict"`, `"Normal"`. |
| `settings.not_found` | string | Nonblank response when suitable knowledge is missing. Maximum 500 characters. Minimum 1 characters. |
| `tombstones` | array of object | Records that prevent refreshed sources restoring removed pieces. |
| `tombstones[].id` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `tombstones[].subject_hash` | string | Normalized title digest. |
| `tombstones[].evidence` | array of object | Saved value. |
| `tombstones[].evidence[].source` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `tombstones[].evidence[].segment` | integer | Source segment index. |
| `tombstones[].evidence[].quote` | string | Original evidence text. |
| `tombstones[].evidence[].quote_hash` | string | Digest used by a deletion record. |
| `tombstones[].evidence[].topic_id` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `tombstones[].evidence[].revision` | string | Opaque identifier. Keep it as a string. Format: uuid. |
| `tombstones[].evidence[].title` | string | Title snapshot at answer time. |
| `created_at` | string | UTC timestamp. Format: date-time. |

## Example request

K5 examples use unpublished Node/CLI 0.10.0 and Python 0.3.0. The cURL tab uses Bash; CLI uses PowerShell. Python shows sync usage; AsyncNixflex uses the same JSON methods with async with and await. Set the staging credential in `NXF_STAGING_KEY` and the owned path identifiers shown below in environment variables. Keep private responses out of logs.

<RequestExample>

```bash cURL (Bash)
curl --request GET \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/knowledge-bases/$(node -p 'encodeURIComponent(process.env.NXF_KNOWLEDGE_BASE_ID)')" \
  --header "Authorization: Bearer $NXF_STAGING_KEY"
```

```javascript Node
import { Nixflex } from 'nixflex';
const c = new Nixflex({apiKey:process.env.NXF_STAGING_KEY,baseUrl:'https://nixflex-voice-engine-staging.up.railway.app',maxRetries:0});
const result = await c.knowledge.getBase(process.env.NXF_KNOWLEDGE_BASE_ID);
// Keep knowledge and private results out of logs.
```

```python Python
import os
from nixflex import Nixflex

with Nixflex(api_key=os.environ["NXF_STAGING_KEY"], base_url="https://nixflex-voice-engine-staging.up.railway.app", max_retries=0) as c:
    result = c.knowledge.get_base(os.environ["NXF_KNOWLEDGE_BASE_ID"])
    # Keep knowledge and private results out of logs.
```

```powershell CLI (PowerShell)
$env:NIXFLEX_API_KEY = $env:NXF_STAGING_KEY
nixflex knowledge getBase "$env:NXF_KNOWLEDGE_BASE_ID" --json --base-url "https://nixflex-voice-engine-staging.up.railway.app"
```

</RequestExample>

MCP does not offer this operation yet because the proposed knowledge tools await approval and registration.

## Errors

Failures use `error.type`, `error.code`, `error.message`, `error.doc_url` and optional `error.details`. Knowledge failures include a request ID in details when available. Read the safe message as text. A job can return HTTP 200 with state `failed` and `error`; that is a job failure, not an HTTP error. Source failures can arise during preparation after the initial accepted response.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 400 | [`invalid_input`](/api-reference/errors#invalid_input) | Check the information and try again. | Correct the named fields or reduce the input before retrying. |
| 404 | [`not_found`](/api-reference/errors#not_found) | That topic is not available. | Check the owned identifier and feature availability. |
| 409 | [`deleting`](/api-reference/errors#deleting) | This knowledge base is being deleted. | Read current state and resolve the conflict before sending a new request. |
| 503 | [`unavailable`](/api-reference/errors#unavailable) | Knowledge is unavailable right now. Your saved information is safe. Try again. | Retry reads with bounded backoff; reconcile writes before repeating. |
| 503 | [`knowledge_unconfigured`](/api-reference/errors#knowledge_unconfigured) | Knowledge is not available yet. | Retry reads with bounded backoff; reconcile writes before repeating. |
| 503 | [`knowledge_not_released`](/api-reference/errors#knowledge_not_released) | Knowledge is not released yet. | Retry reads with bounded backoff; reconcile writes before repeating. |
| 403 | [`permission_denied`](/api-reference/errors#permission_denied) | Your personal role does not allow this action. | Use a permitted personal account; do not share the organisation key. |
| 403 | [`membership_revoked`](/api-reference/errors#membership_revoked) | Your membership has ended. | Use a permitted personal account; do not share the organisation key. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for the stated retry/reset time. |

## Retry and idempotency

This is a read or calculation. GET requests may retry transient connection failures once with bounded backoff; respect Retry-After. Do not retry invalid input or ownership errors unchanged. POST calculations are not automatically retried.
