Submit pasted text or a raw file and queue preparation of original-word pieces.

## Authentication

Send Authorization: Bearer KEY_ID:KEY_SECRET using the owning account’s server-side API credential. API keys have Owner authority. Personal Owner and Admin may perform this action; Member is refused. Personal dashboard visibility can hide API-origin agents. Never send owner fields to select another account.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `kb` (path) | string | Yes | None | Opaque identifier. Keep it as a string. Format: uuid. |
| `Idempotency-Key` (header) | string | Yes | None | Unique 8–128-character operation key: letters, numbers, dot, underscore, colon or hyphen. The prompt: prefix is reserved. Reuse only with the identical operation and payload. Maximum 128 characters. Minimum 8 characters. Pattern: `^[A-Za-z0-9_.:-]{8,128}$`. |
| `X-Filename` (header) | string | No | Omitted | Required for a raw upload; filename up to 200 characters. Use a genuine PDF, DOCX or UTF-8 text file. Maximum 200 characters. |
| `X-Source-Title` (header) | string | No | Omitted | Optional source title, at most 200 characters; defaults to filename. Maximum 200 characters. |
| `X-Review` (header) | string | No | Omitted | For imports: exactly true requests review; other/omitted values mean false for API requests. |

Send a JSON object.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `source` | object | Yes | None | Saved value. |
| `source.type` | string | Yes | None | For JSON use text. Files use raw upload; websites use discovery then selection. Value: `"text"`. |
| `source.title` | string | No | Omitted | Optional name; defaults to opening text or uploaded filename. Maximum 200 characters. |
| `source.text` | string | Yes | None | Nonblank pasted UTF-8 text, maximum 20,000 tokens and 10 MiB transport bytes. Minimum 1 characters. |
| `review` | boolean | No | `false` | True requires a review draft; omitted API value is false. |

Dashboard imports always require review. API review:false may publish after preparation, but flags or reminders always force needs_review. Direct qa and url source types are refused; websites use discovery and selected-page import.

Raw upload: Content-Type application/octet-stream, X-Filename, optional X-Source-Title and X-Review; replacements also require X-Expected-Revision. File maximum 10 MiB; PDF maximum 200 pages. Accept clean UTF-8 text, PDF with selectable text, or DOCX. No raw base64/path input, RTF, executable or active-content documents. Preview scan status is not publication clearance. Without a configured scanner, local_checks_only permits bounded local checks. With a configured scanner, PDF/DOCX need a clean result; clean UTF-8 text can use local checks during an outage. Infected files never bypass. Imports may wait at safety_check/safety_waiting with next_retry_at; after 24 hours scan_expired requires a new upload. Raw files are private and never downloaded; accepted storage retains extracted text.

`202 Accepted` returns the fields below. Follow the job and current revision where this operation queues work; an accepted response is not proof of publication.

| `progress.completed` | integer | Completed preparation units. |
| `progress.total` | integer | Total preparation units. |

| `result.deleted` | boolean | Saved value. |

## Example request

These examples target Node/CLI 0.11.0 and Python 0.4.0; confirm the installed version supports the method before use. The cURL tab uses Bash; CLI uses PowerShell. Python shows sync usage; AsyncNixflex uses the same JSON methods with async with and await. Set the staging credential in `NXF_STAGING_KEY` and the owned path identifiers shown below in environment variables. Set `NXF_IDEMPOTENCY_KEY` to a new valid key for one intended operation. This operation changes state. Review the request and disable automatic write retries.

```json request-112.json
{
  "source": {
    "type": "text",
    "title": "Appointments",
    "text": "Appointments are available Monday to Friday."
  },
  "review": true
}
```

Read the safe message as text. A job can return HTTP 200 with state `failed` and `error`; that is a job failure, not an HTTP error. ## Retry and idempotency

Use a new Idempotency-Key for each intended change. The same key with the identical operation and payload replays the stored result; a different payload conflicts. Do not automatically repeat an uncertain write. Read the current job/resource first, then reconcile with the original key. Check expected_revision against current state; a fresh key does not bypass revision checks.
