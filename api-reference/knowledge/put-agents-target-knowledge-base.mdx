## Authentication

Send Authorization: Bearer KEY_ID:KEY_SECRET using the owning account’s server-side API credential. API keys have Owner authority. Personal Owner and Admin may perform this action; Member is refused. Personal dashboard visibility can hide API-origin agents. Never send owner fields to select another account.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `target` (path) | string | Yes | None | Owned agent ID. URL-encode it as a path segment. |
| `Idempotency-Key` (header) | string | Yes | None | Unique 8–128-character operation key: letters, numbers, dot, underscore, colon or hyphen. The prompt: prefix is reserved. Reuse only with the identical operation and payload. Maximum 128 characters. Minimum 8 characters. Pattern: `^[A-Za-z0-9_.:-]{8,128}$`. |

Send a JSON object.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `settings` | object | No | Omitted | Only channels, match and not_found may be supplied. Omitted settings retain the saved value on update. |
| `settings.channels` | array of string | No | `["inbound"]` | Enabled knowledge channels. An empty list turns knowledge off for all channels. Allowed items: `"inbound"`, `"outbound"`, `"web_voice"`, `"web_chat"`, `"sms"`. |
| `settings.match` | string | No | `"Strict"` | Answer matching mode. Allowed: `"Strict"`, `"Normal"`. |
| `settings.not_found` | string | No | `"I don't have that information right now."` | Nonblank response when suitable knowledge is missing. Maximum 500 characters. Minimum 1 characters. |
| `expected_revision` | integer | No | Omitted | Latest integer revision read from this resource; it must still match when the request runs. Minimum 1. |

Creation may omit expected_revision. An existing base requires its current rev. This does not publish source text.

Python shows sync usage; AsyncNixflex uses the same JSON methods with async with and await. Set the staging credential in `NXF_STAGING_KEY` and the owned path identifiers shown below in environment variables. Set `NXF_IDEMPOTENCY_KEY` to a new valid key for one intended operation. This operation changes state. Review the request and disable automatic write retries.

  "settings": {

  }

Failures use `error.type`, `error.code`, `error.message`, `error.doc_url` and optional `error.details`. Knowledge failures include a request ID in details when available. Read the safe message as text. A job can return HTTP 200 with state `failed` and `error`; that is a job failure, not an HTTP error. ## Retry and idempotency

Use a new Idempotency-Key for each intended change. The same key with the identical operation and payload replays the stored result; a different payload conflicts. Do not automatically repeat an uncertain write. Read the current job/resource first, then reconcile with the original key. Check expected_revision against current state; a fresh key does not bypass revision checks.
