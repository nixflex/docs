Update reply behaviour for one owned SMS campaign. This operation does not edit its recipients, schedule or message template, and it is not a cancellation control.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential. Send `Content-Type: application/json`.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `id` (path) | string | Yes | None | Exact saved campaign_id owned by this account. This operation does not declare a route-level length or character validator. |

Send at least one supported field. Omitted fields stay unchanged; unknown fields are ignored. Database constraints still apply.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `is_active` | boolean | No | Omitted | Enable or disable reply behaviour; does not stop dispatch. |
| `reply_context_prompt` | string or null | No | Omitted | Replace reply instructions; null clears. |
| `reply_window_hours` | integer | No | Omitted | Saved reply association window in hours. Use a positive integer; no route-level range validator is declared. Minimum 1. |

The response is the campaign object directly, with no campaign wrapper. It contains saved counters, rather than the recomputed totals returned by list/detail. This route currently has no strict type/length validation before the database; empty updates, missing campaigns and database failures may return 500 server_error. Read detail after an uncertain save.

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Set `NXF_CAMPAIGN_ID` to the intended account-owned identifiers or approved recipient before running. Tabs labelled **direct HTTP** do not rely on an SDK or CLI method; the reviewed kit has no matching method.

<RequestExample>

```bash cURL
curl --request PATCH \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/sms/campaigns/$(node -p 'encodeURIComponent(process.env.NXF_CAMPAIGN_ID)')" \
  --header "Authorization: Bearer $NXF_STAGING_KEY" \
  --header "Content-Type: application/json" \
  --data '{"reply_context_prompt":"Answer questions about this requested appointment reminder.","reply_window_hours":24}'
```

```javascript Node (direct HTTP)
const body = {
  "reply_context_prompt": "Answer questions about this requested appointment reminder.",
  "reply_window_hours": 24
};
const response = await fetch(`https://nixflex-voice-engine-staging.up.railway.app/v1/sms/campaigns/${encodeURIComponent(process.env.NXF_CAMPAIGN_ID)}`, {
  method: 'PATCH',
  headers: { Authorization: `Bearer ${process.env.NXF_STAGING_KEY}`, 'Content-Type': 'application/json' },
  body: JSON.stringify(body),
});
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const result = await response.json();
console.log('Request completed.');
```

```python Python (direct HTTP)
import os
import json
from urllib.request import Request, urlopen
from urllib.parse import quote

body = {
  "reply_context_prompt": "Answer questions about this requested appointment reminder.",
  "reply_window_hours": 24
}
request = Request(
    f"https://nixflex-voice-engine-staging.up.railway.app/v1/sms/campaigns/{quote(os.environ['NXF_CAMPAIGN_ID'], safe='')}",
    method="PATCH",
    headers={"Authorization": "Bearer " + os.environ["NXF_STAGING_KEY"], "Content-Type": "application/json"},
    data=json.dumps(body).encode("utf-8"),
)
with urlopen(request, timeout=30) as response:
    result = json.load(response)
print("Request completed.")
```

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 500 | [`server_error`](/api-reference/errors#server_error) | The result could not be confirmed. | Read the current state before repeating a write. |
| 400 | [`invalid_json`](/api-reference/errors#invalid_json) | Invalid JSON body. | Correct JSON syntax. |
| 413 | [`payload_too_large`](/api-reference/errors#payload_too_large) | The request exceeds the JSON body limit. | Send a smaller request. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

No idempotency key is documented. A timeout or 5xx can follow a committed change. Read the current state before deciding whether to submit again; never automatically repeat an uncertain write.
