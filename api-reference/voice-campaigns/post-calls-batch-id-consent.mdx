Record a consent or consent-withdrawal decision for the current voice campaign policy revision. The owner confirms the selected event explicitly.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential. Send `Content-Type: application/json`.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `id` (path) | string | Yes | None | Account-owned campaign identifier. Maximum 100 characters. Minimum 1 characters. Pattern: `^[A-Za-z0-9_-]+$`. |

Send a JSON object.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `event` | string | Yes | None | Decision to record. Allowed: `"consent"`, `"consent_withdrawn"`. |
| `confirmed` | boolean | Yes | None | Explicitly confirm the selected event, including withdrawal. Value: `true`. |

confirmed must be true for either event. Omitted fields and false are refused. This endpoint does not launch a campaign or clear suppression. Recording consent can unblock otherwise eligible scheduled or running work. Missing campaigns and unconfirmed database results currently return 503 outcome_unknown.

## Response fields

`200 OK` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `campaign_id` | string | Campaign ID. |
| `recorded` | boolean | The decision was recorded. Value: `true`. |

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Set `NXF_CAMPAIGN_ID` to the intended account-owned identifiers or approved recipient before running. Tabs labelled **direct HTTP** do not rely on an SDK or CLI method; the reviewed kit has no matching method.

<RequestExample>

```bash cURL
curl --request POST \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/calls/batch/$(node -p 'encodeURIComponent(process.env.NXF_CAMPAIGN_ID)')/consent" \
  --header "Authorization: Bearer $NXF_STAGING_KEY" \
  --header "Content-Type: application/json" \
  --data '{"event":"consent","confirmed":true}'
```

```javascript Node (direct HTTP)
const body = {
  "event": "consent",
  "confirmed": true
};
const response = await fetch(`https://nixflex-voice-engine-staging.up.railway.app/v1/calls/batch/${encodeURIComponent(process.env.NXF_CAMPAIGN_ID)}/consent`, {
  method: 'POST',
  headers: { Authorization: `Bearer ${process.env.NXF_STAGING_KEY}`, 'Content-Type': 'application/json' },
  body: JSON.stringify(body),
});
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const result = await response.json();
console.log('Request completed.');
```

```python Python (direct HTTP)
import os
import json
from urllib.request import Request, urlopen
from urllib.parse import quote

body = {
  "event": "consent",
  "confirmed": True
}
request = Request(
    f"https://nixflex-voice-engine-staging.up.railway.app/v1/calls/batch/{quote(os.environ['NXF_CAMPAIGN_ID'], safe='')}/consent",
    method="POST",
    headers={"Authorization": "Bearer " + os.environ["NXF_STAGING_KEY"], "Content-Type": "application/json"},
    data=json.dumps(body).encode("utf-8"),
)
with urlopen(request, timeout=30) as response:
    result = json.load(response)
print("Request completed.")
```

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 400 | [`invalid_request`](/api-reference/errors#invalid_request) | The identifier or request fields are invalid. | Correct the documented fields before resending. |
| 503 | [`outcome_unknown`](/api-reference/errors#outcome_unknown) | The write result could not be confirmed. | Read current state; do not resend automatically. |
| 400 | [`invalid_json`](/api-reference/errors#invalid_json) | Invalid JSON body. | Correct JSON syntax. |
| 413 | [`payload_too_large`](/api-reference/errors#payload_too_large) | The request exceeds the JSON body limit. | Send a smaller request. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

No idempotency key is documented. A timeout or 5xx can follow a committed change. Read the current state before deciding whether to submit again; never automatically repeat an uncertain write. Each accepted request appends a decision event; it is not a deduplicated update.
