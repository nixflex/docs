Delete an owned SMS campaign in draft, scheduled, done, failed or cancelled state. Running, launching and other active states are refused.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `id` (path) | string | Yes | None | Exact saved campaign_id owned by this account. This operation does not declare a route-level length or character validator. |

Do not send a request body.

No body is used. A missing owned campaign also returns 200 with the same acknowledgement. Deletion does not cancel an active run, recall accepted messages, or prove erasure of every message copy. The CLI may read detail before deletion for its confirmation preview.

## Response fields

`200 OK` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `message` | string | Deletion acknowledgement. |

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Set `NXF_CAMPAIGN_ID` to the intended account-owned identifiers or approved recipient before running.

<RequestExample>

```bash cURL
curl --request DELETE \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/sms/campaigns/$(node -p 'encodeURIComponent(process.env.NXF_CAMPAIGN_ID)')" \
  --header "Authorization: Bearer $NXF_STAGING_KEY"
```

```javascript Node
import { Nixflex } from 'nixflex';

const client = new Nixflex({
  apiKey: process.env.NXF_STAGING_KEY,
  baseUrl: 'https://nixflex-voice-engine-staging.up.railway.app',
  maxRetries: 0,
});
const result = await client.sms.campaigns.delete(process.env.NXF_CAMPAIGN_ID);
console.log('Request completed.');
```

```python Python
import os
from nixflex import Nixflex

with Nixflex(
    api_key=os.environ["NXF_STAGING_KEY"],
    base_url="https://nixflex-voice-engine-staging.up.railway.app",
    max_retries=0,
) as client:
    result = client.sms.campaigns.delete(os.environ["NXF_CAMPAIGN_ID"])
    print("Request completed.")
```

```bash CLI
NIXFLEX_API_KEY="$NXF_STAGING_KEY" nixflex sms campaigns delete "$NXF_CAMPAIGN_ID" --confirm \
  --base-url "https://nixflex-voice-engine-staging.up.railway.app" --json
```

</RequestExample>

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 400 | [`invalid_request`](/api-reference/errors#invalid_request) | The campaign is in a state that cannot be deleted. | Read its state; use cancellation when you intend to stop future work. |
| 500 | [`server_error`](/api-reference/errors#server_error) | The result could not be confirmed. | Read the current state before repeating a write. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

No idempotency key is documented. A timeout or 5xx can follow a committed change. Read the current state before deciding whether to submit again; never automatically repeat an uncertain write. Repeating deletion of an already absent ID returns 200, but an earlier unknown request still needs state reconciliation.
