Create an SMS campaign and its recipient rows. The default now mode immediately requests launch; schedule mode saves scheduled work that can run automatically. There is no public draft-only flag.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential. Send `Content-Type: application/json`.

## Request fields

Send a JSON object.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `agent_id` | string | Yes | None | Active agent owned by this account. |
| `from_number` | string | Yes | None | International number with + and digits; no spaces. Pattern: `^\+[1-9][0-9]{6,14}$`. |
| `name` | string | No | Omitted | Campaign label. Empty or omitted uses the channel-specific Untitled campaign label. |
| `recipients` | array of object | Yes | None | At least one accepted recipient; atomic storage allows at most 100,000. The HTTP body limit still applies. Maximum 100000 items. Minimum 1 items. |
| `recipients[].phone` | string | Yes | None | Trimmed E.164 string, 8–15 digits after +; country numbering-plan validation also applies. Pattern: `^\+[1-9][0-9]{7,14}$`. |
| `recipients[].variables` | object | No | `{}` | Per-recipient template values. |
| `recipients[].country` | string | No | Omitted | Uppercase supported two-letter country. Omitted uses conservative number inference. Maximum 2 characters. Minimum 2 characters. |
| `recipients[].timezone` | string | No | Omitted | Explicit recipient IANA Area/City zone; preferred over number inference. Unknown location is held, never replaced by the campaign clock. Maximum 80 characters. |
| `schedule_type` | string | No | `"now"` | now requests launch immediately after creation. schedule saves scheduled work that the scheduler can launch. Allowed: `"now"`, `"schedule"`. |
| `scheduled_date` | string or null | No | `null` | Required for schedule; YYYY-MM-DD calendar date. Recipient-local eligibility still applies. Format: date. |
| `window_start_minutes` | integer or null | No | `null` | Start minute after midnight; supply both ends. Zero means midnight. Minimum 0. Maximum 1439. |
| `window_end_minutes` | integer or null | No | `null` | End minute after midnight; supply both ends. A lower end denotes an overnight window. Minimum 0. Maximum 1439. |
| `window_days` | array or null | No | `null` | Optional selected weekdays; duplicate values are collapsed and empty means unset. Allowed items: `"mon"`, `"tue"`, `"wed"`, `"thu"`, `"fri"`, `"sat"`, `"sun"`. |
| `timezone` | string or null | No | `null` | Optional valid IANA campaign time zone. It does not replace a recipient’s location. |
| `source` | string | No | `"api"` | Origin label only; API clients should keep api. Allowed: `"api"`, `"dashboard"`. |
| `skip_invalid` | boolean | No | `false` | When true, omit invalid phone rows only. At least one valid row remains required; other validation failures still refuse. |
| `duplicate_policy` | string | No | `"warn"` | warn retains duplicate rows and reports them; allow explicitly keeps them; reject refuses duplicates. warn is advisory and does not prevent automatic launch. No silent deduplication. Allowed: `"allow"`, `"warn"`, `"reject"`. |
| `consent_confirmed` | boolean | No | `false` | Record confirmation for this campaign. Missing consent holds contact until recorded. |
| `allow_wider_hours` | boolean | No | `false` | Request wider hours with a recorded explanation. Recipient policy and other checks still apply. |
| `hours_confirmation` | string | No | Omitted | Required when wider hours is true: trimmed explanation at least 20 characters; raw maximum 1,000. Maximum 1000 characters. Minimum 20 characters. |
| `message_template` | string | Yes | None | Nonblank text template. Each placeholder such as `{{name}}` must have a value in every recipient’s variables. |
| `reply_context_prompt` | string or null | No | `null` | Instructions for replies associated with this campaign. |
| `reply_window_hours` | integer | No | `168` | Hours for campaign reply association; positive integer. Omitted or zero uses 168. Minimum 1. |

### Scheduling, consent and duplicate rows

The scheduler and final contact checks use recipient-local eligibility, consent, suppression and capacity. A campaign time zone is not a substitute for an unknown recipient location. Preview contact hours before saving; a preview is advisory. Wider hours require the recorded explanation and remain subject to policy.

Choose duplicate_policy deliberately. reject refuses repeated accepted numbers, allow keeps every row, and warn reports duplicates but still allows this route to request launch. The duplicate_choice_required response flag is advisory. It does not create a safe draft or block sending.

The scheduled example can contact its recipients when due. Use an approved destination and consent; the date is illustrative. No public draft-only flag is accepted. SMS creation always creates a new campaign. reuse_campaign_id does not implement SMS reuse; do not send it.

JSON request size and database constraints can limit a request before the maximum accepted-recipient count. No additional text length limit is declared for the prompt or message template on this route.

## Example request

These examples use the unpublished client candidates: Node/CLI 0.10.0, Python 0.3.0 and MCP 0.4.0. Keep `NXF_STAGING_KEY` private. cURL uses Bash; CLI uses PowerShell and reads the key through `NIXFLEX_API_KEY`. Replace fixture identifiers and reserved example numbers with approved account-owned values. Configure the existing MCP installation for the same staging host and account before using the shown tool arguments. Python shows the synchronous client; `AsyncNixflex` uses the same method with `async with` and `await`. This example changes state. Review the target and payload before running it. Running it can contact recipients immediately or when scheduled; scheduled creation is executable, not a draft. The existing MCP create tool does not expose nullable timezone as a typed argument, so its example omits that field.

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

| 400 | [`campaign_creation_failed`](/api-reference/errors#campaign_creation_failed) | Required settings, ownership, template values, duplicate policy or recipient metadata failed validation. | Read error.details when present; correct the request before creating again. |
| 400 | [`invalid_phone_format`](/api-reference/errors#invalid_phone_format) | Phone validation failed or no valid recipients remain. | Fix invalid rows; skip_invalid only skips invalid phone rows. |

## Retry and idempotency

Creation is not idempotent. Do not automatically retry after a timeout, 5xx, or saved-but-refused launch. Read the campaign list/detail using the returned campaign_id when available; ask support to reconcile an unknown result. Duplicate detection compares input rows, not repeated HTTP requests. Queue admission or a sent count does not prove contact or delivery.
