Read one owned SMS campaign with recipient and message history. The campaign counters cover the whole campaign; the two history lists have independent cursors.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `id` (path) | string | Yes | None | Exact saved campaign_id owned by this account. This operation does not declare a route-level length or character validator. |
| `limit` (query) | integer | No | Omitted | Supplying this enables paging; page default 200, maximum 500. Minimum 1. Maximum 500. |
| `recipient_cursor` (query) | string | No | Omitted | Last recipient UUID from pagination.recipient_cursor. Format: uuid. |
| `message_cursor` (query) | string | No | Omitted | Last message UUID from pagination.message_cursor. Format: uuid. |

Do not send a request body.

Provide limit to request bounded pages. Each list is ordered by id ascending and advances independently. Keep an exhausted list finished in your client; omitting its cursor restarts that list. A full page can return a cursor even at the end, so another empty read may be needed.

Without limit or cursors, the server collects history in 200-row chunks, with a 100,000-row ceiling per list, then sorts by created_at ascending with missing timestamps last. This compatibility mode is not a snapshot. Invalid limits or malformed UUID cursors currently return 500 server_error; a missing campaign or failed initial lookup returns 404 not_found. Retention can remove content between reads.

## Example request

These examples use the unpublished K3 candidates: Node/CLI 0.10.0, Python 0.3.0 and MCP 0.4.0. Keep `NXF_STAGING_KEY` private. cURL uses Bash; CLI uses PowerShell and reads the key through `NIXFLEX_API_KEY`. Replace fixture identifiers and reserved example numbers with approved account-owned values. Configure the existing MCP installation for the same staging host and account before using the shown tool arguments. Python shows the synchronous client; `AsyncNixflex` uses the same method with `async with` and `await`. This is the first page; use only cursors returned by the API for subsequent pages.

<RequestExample>

```bash cURL
curl --request GET \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/sms/campaigns/campaign_fixture?limit=2" \
  --header "Authorization: Bearer $NXF_STAGING_KEY"
```

```javascript Node
import { Nixflex } from 'nixflex';

const c = new Nixflex({
  apiKey: process.env.NXF_STAGING_KEY,
  baseUrl: 'https://nixflex-voice-engine-staging.up.railway.app',
  maxRetries: 0,
});
const result = await c.sms.campaigns.get("campaign_fixture", {"limit": 2});
```

```python Python
import os
from nixflex import Nixflex

with Nixflex(
    api_key=os.environ["NXF_STAGING_KEY"],
    base_url="https://nixflex-voice-engine-staging.up.railway.app",
    max_retries=0,
) as c:
    result = c.sms.campaigns.get('campaign_fixture', limit=2)
```

```powershell CLI (PowerShell)
$env:NIXFLEX_API_KEY = $env:NXF_STAGING_KEY
nixflex sms campaigns get campaign_fixture --limit 2 --json --base-url "https://nixflex-voice-engine-staging.up.railway.app"
```

```json MCP
{
  "name": "get_sms_campaign",
  "arguments": {
    "limit": 2,
    "campaign_id": "campaign_fixture"
  }
}
```

</RequestExample>

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 404 | [`not_found`](/api-reference/errors#not_found) | No matching object belongs to this account. | Check the account and identifier. |
| 500 | [`server_error`](/api-reference/errors#server_error) | The result could not be confirmed. | Read the current state before repeating a write. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

This is a read-only request. Retry transient connection or server failures with bounded backoff; respect Retry-After for 429. Do not retry validation or ownership errors unchanged. A later read can return newer state.
