Delete the complete caller-context record for one caller on one account-owned business number. This removes both customer-supplied and engine-learned context in that record.

<div className="nxf-facts">
  <div><small>Method</small><strong>DELETE</strong></div>
  <div><small>Success</small><strong>200</strong></div>
  <div><small>Scope</small><strong>Owning account</strong></div>
</div>

<div className="nxf-important">

**The important part**

- Delete the intended caller context for the selected number.
- This does not erase all call records or copies held by external systems.

</div>

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `phoneNumber` (path) | string | Yes | None | Owned business number. Use E.164 and encode it as one URL path segment. |
| `callerNumber` (path) | string | Yes | None | Caller whose context is scoped to this business number. Use E.164. |

Do not send a request body.

Use E.164 numbers for both path values. The route removes whitespace and adds + when missing; it does not enforce a numeric length limit. This operation does not erase the caller’s call records, recordings, or context on other business numbers. Later conversations or imports can create new context.

## Response fields

`200 OK` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `phone_number` | string | Normalized business number. |
| `caller_number` | string | Normalized caller number. |
| `deleted` | boolean | True after deleting the context record. |

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Kit examples use the supplied Node/CLI 0.11.0 and Python 0.4.0 candidates; these versions are unpublished. Set `NXF_PHONE_NUMBER`, `NXF_CALLER_NUMBER` to the intended account-owned identifiers or approved recipient before running.

<RequestExample>

```bash cURL
curl --request DELETE \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/phone-numbers/$NXF_PHONE_NUMBER/callers/$NXF_CALLER_NUMBER" \
  --header "Authorization: Bearer $NXF_STAGING_KEY"
```

```javascript Node
import Nixflex from 'nixflex';
const baseUrl = 'https://nixflex-voice-engine-staging.up.railway.app';
const client = new Nixflex({apiKey:process.env.NXF_STAGING_KEY,baseUrl,maxRetries:0});
const result = await client.callers.delete(process.env.NXF_PHONE_NUMBER,process.env.NXF_CALLER_NUMBER);
// Handle result privately; do not log secrets or call content.
```


## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 400 | [`missing_field`](/api-reference/errors#missing_field) | A business or caller number is missing. | Supply both path values. |
| 404 | [`phone_number_not_found`](/api-reference/errors#phone_number_not_found) | The business number is not owned by this account. | Use an owned business number. |
| 404 | [`caller_not_found`](/api-reference/errors#caller_not_found) | No caller-context record exists for this pair. | Check the scope; after an uncertain delete, absence may confirm it succeeded. |
| 500 | [`database_error`](/api-reference/errors#database_error) | Reading or deleting the record failed. | Read the current state before retrying. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

There is no documented idempotency-key replay guarantee. A repeat after successful deletion returns 404 caller_not_found. After an uncertain result, read the caller record before another attempt; repeating later could remove newly created context. Disable automatic write retries.
