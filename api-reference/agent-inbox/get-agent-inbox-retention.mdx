Read the account retention default and inbox cleanup availability. Include a number to resolve its assigned agent’s web-message retention policy.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `number` (query) | string | No | Omitted | International number with + and digits; no spaces. Pattern: `^\+[1-9][0-9]{6,14}$`. |

Do not send a request body.

Only number is accepted as a query field. URL-encode + in a query value. Without number, web_days is null rather than the account default. Zero days means cleanup on the next cleanup run after reply, not an immediate response-time deletion guarantee. Archiving does not extend retention. Requests return Cache-Control: no-store.

## Response fields

`200 OK` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `call_retention_days` | integer | Account retention default, 90 when unset. |
| `web_days` | integer or null | Effective agent or account web days when number is supplied; null without number. |
| `web_expiry_confirmed` | boolean | Web cleanup database prerequisites are confirmed. |
| `applies_to` | string | Policy scope. Value: `"new_messages_agent_policy"`. |
| `legacy_web_policy` | string | Legacy-message fallback. Value: `"account_policy_at_creation_or_90_days"`. |
| `zero_days_means` | string | Zero-day cleanup timing. Value: `"next_cleanup_after_reply"`. |
| `archive_changes_retention` | boolean | Archiving does not change retention. Value: `false`. |
| `sms_days` | integer | SMS retention days. Value: `90`. |
| `sms_processing_enabled` | boolean | SMS cleanup processing is enabled. |
| `web_processing_enabled` | boolean | Cleanup enabled and web prerequisites confirmed. |

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Tabs labelled **direct HTTP** do not rely on an SDK or CLI method; the reviewed kit has no matching method.

<RequestExample>

```bash cURL
curl --request GET \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/agent-inbox/retention" \
  --header "Authorization: Bearer $NXF_STAGING_KEY"
```


## Retry and idempotency

This is a read-only request. Retry transient connection or server failures with bounded backoff; respect Retry-After for 429. Do not retry validation or ownership errors unchanged. A later read can return newer state.
