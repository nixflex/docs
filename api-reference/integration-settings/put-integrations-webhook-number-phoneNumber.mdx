Set the first webhook setting for an owned number. Each webhook slot is independent. Saved destinations receive call events when the relevant delivery feature is available.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential. When personal dashboard sessions are enabled, Owner and Admin sessions can write these settings; Member sessions can read only. Ownership checks still apply. Send `Content-Type: application/json`.

## Request fields

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `phoneNumber` (path) | string | Yes | None | Owned E.164 number. URL-encode the leading plus sign. |

Send a JSON object.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `url` | string | Yes | None | HTTPS destination. The handler trims the value and requires the https:// prefix. |

The GET response returns the saved URL. Keep URLs private because they can contain credentials. Setting a URL does not test delivery or verify the destination.

## Response fields

`200 OK` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `ok` | boolean | Request succeeded. Value: `true`. |
| `phone_number` | string | Owned phone number. |
| `provider` | string | Integration identifier. Value: `"webhook"`. |

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Kit tabs use the reviewed Node/CLI 0.10.0 and Python 0.3.0 unpublished candidates. Method presence does not promise complete field coverage. Set `NXF_PHONE_NUMBER` privately to the intended owned identifiers or integration values before running.

<RequestExample>

```bash cURL
curl --request PUT \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/integrations/webhook/number/$(node -p 'encodeURIComponent(process.env.NXF_PHONE_NUMBER)')" \
  --header "Authorization: Bearer $NXF_STAGING_KEY" \
  --header "Content-Type: application/json" \
  --data '{"url":"https://example.com/events"}'
```

```javascript Node
import { Nixflex } from 'nixflex';

const client = new Nixflex({
  apiKey: process.env.NXF_STAGING_KEY,
  baseUrl: 'https://nixflex-voice-engine-staging.up.railway.app',
  maxRetries: 0,
});
const body = {
  "url": "https://example.com/events"
};
const result = await client.webhooks.set(process.env.NXF_PHONE_NUMBER, "https://example.com/events", 1);
// Handle the result privately; do not log credentials or destination URLs.
```

```python Python
import os
from nixflex import Nixflex

body = {
  "url": "https://example.com/events"
}

with Nixflex(
    api_key=os.environ["NXF_STAGING_KEY"],
    base_url="https://nixflex-voice-engine-staging.up.railway.app",
    max_retries=0,
) as client:
    result = client.webhooks.set(os.environ["NXF_PHONE_NUMBER"], "https://example.com/events", slot=1)
    # Handle the result privately; never log credentials or destination URLs.
```

```bash CLI
NIXFLEX_API_KEY="$NXF_STAGING_KEY" nixflex webhooks set "$NXF_PHONE_NUMBER" "https://example.com/events" --slot 1 \
  --base-url "https://nixflex-voice-engine-staging.up.railway.app" --json
```

</RequestExample>

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 404 | [`not_found`](/api-reference/errors#not_found) | No matching owned resource or saved configuration was found. | Check the identifier and owning account. |
| 500 | [`server_error`](/api-reference/errors#server_error) | The result could not be confirmed. | Read the current state before retrying a write. |
| 400 | [`missing_field`](/api-reference/errors#missing_field) | A required field is missing or has the wrong type. | Correct the request before retrying. |
| 400 | [`invalid_url`](/api-reference/errors#invalid_url) | The destination URL is not accepted. | Use the required HTTPS destination. |
| 400 | [`invalid_phone`](/api-reference/errors#invalid_phone) | The number is not valid E.164. | Correct the request before retrying. |
| 400 | [`invalid_json`](/api-reference/errors#invalid_json) | The JSON body could not be parsed. | Correct the request before retrying. |
| 413 | [`payload_too_large`](/api-reference/errors#payload_too_large) | The request body is too large. | Reduce the request body. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

</div>

## Retry and idempotency

The operation writes one saved setting and has no idempotency token. Read the current value after an uncertain response. Repeating it can overwrite a newer change, so reconcile before resending.
