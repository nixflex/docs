Attaches a phone number you already own to one of your agents. Nixflex supports **Twilio** and **Telnyx**.

You do not choose the carrier with a field — it is inferred from the credentials you send. Send Twilio credentials and the number is imported as a Twilio number; send a Telnyx API key and it is imported as a Telnyx number.

<Note>
  The documented request and success-response fields stay the same. Send one carrier
  credential set only. Conflicting aliases and unsupported fields are now rejected.
</Note>

## Safety and retrying

Before changing carrier routing, Nixflex validates the whole request, checks the active
account and owned active agent, and reserves the exact number. Existing imports and
pending imports, removals or releases block competing operations. A refused preflight
makes no carrier write. A pending new import cannot answer or originate calls.

If routing succeeded but database completion failed, `number_save_pending` means retry
the **identical request**, with the same credentials, agent and settings. The saved
carrier acknowledgement lets that retry finish without sending another routing change.

If the carrier response or acknowledgement was lost, `number_cleanup_uncertain` means
the number stays reserved. Contact support with `error.details.operation_id` when present.
Do not restore routing blindly, delete a reservation, or switch credentials and retry.
There is no automatic expiry or automatic replay of an uncertain carrier write.

Ordinary removal uses the same reservation. It returns `deleted: true` only after the
carrier cleanup and exact database-row removal both complete. An uncertain cleanup
keeps the row and blocks re-import; it is not reported as a successful deletion.

## Twilio

```bash
curl -X POST https://api.nixflex.com/v1/phone-numbers \
  -H "Authorization: Bearer KEY_ID:KEY_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "phone_number": "+447446466847",
    "twilio_sid":   "ACxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    "twilio_token": "your_twilio_auth_token",
    "agent_id":     "agent_125207e452f8714a"
  }'
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `phone_number` | string | Yes | E.164 format (`+44...`). Must already exist in your Twilio account |
| `twilio_sid` | string | Yes | Your Twilio Account SID, format `AC` + 32 hex characters |
| `twilio_token` | string | Yes | Your Twilio Auth Token |
| `agent_id` | string | Yes | Must be an agent you own |
| `custom_prompt` | string | No | Per-number prompt override. Max 8000 characters |

Nixflex points the number's voice, SMS and status webhooks at the engine for you.

<Warning>
  Importing **replaces the existing webhooks** on the Twilio number. If another
  system uses this number, it will stop receiving calls and SMS.
</Warning>

## Telnyx

Telnyx works differently, and the difference matters.

On Twilio, the webhook URL lives **on the number**. On Telnyx, the webhook lives on a **TeXML Application**, and numbers are assigned to that application. Nixflex never creates the application — you create it once in your Telnyx portal, then every number you assign to it is handled by Nixflex.

<Steps>
  <Step title="Create a TeXML Application in your Telnyx portal">
    Set its voice webhook URL to `https://api.nixflex.com/telnyx-voice`, method **POST**, webhook API version **2**. Copy the application's ID — that is your `telnyx_connection_id`.
  </Step>
  <Step title="Check the codec settings">
    Enable **G711U**. Turn **G722 / HD Voice** off. The engine speaks mu-law only; a call that negotiates another codec will connect but carry no usable audio.
  </Step>
  <Step title="Import the number">
    Nixflex assigns the number to your TeXML application for you.
  </Step>
</Steps>

```bash
curl -X POST https://api.nixflex.com/v1/phone-numbers \
  -H "Authorization: Bearer KEY_ID:KEY_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "phone_number":         "+443301901028",
    "telnyx_api_key":       "KEY0123456789...",
    "telnyx_connection_id": "2512345678901234567",
    "agent_id":             "agent_125207e452f8714a"
  }'
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `phone_number` | string | Yes | E.164 format. Must already exist in your Telnyx account |
| `telnyx_api_key` | string | Yes | A Telnyx API key with access to the number |
| `telnyx_connection_id` | string | Yes | The ID of your TeXML Application |
| `telnyx_public_key` | string | No | Webhook signing public key copied from your Telnyx portal; canonical base64 of exactly 32 bytes (44 characters ending in `=`) |
| `agent_id` | string | Yes | Must be an agent you own |
| `custom_prompt` | string | No | Per-number prompt override. Max 8000 characters |

<Note>
  camelCase works everywhere too: `phoneNumber`, `twilioSid`, `twilioToken`,
  `telnyxApiKey`, `telnyxConnectionId`, `telnyxPublicKey`, `agentId`, `customPrompt`.
</Note>

### Telnyx signing key lifecycle

The optional `telnyx_public_key` is different from your secret `telnyx_api_key`.
Saving the public key creates an **unverified candidate**, not proof that it belongs to
your Telnyx account. Nixflex checks a signed voice callback, reads the same call back
with this number's own Telnyx API key, and compares the call/account, direction and
phone numbers. Verification then requires Nixflex operator approval of that evidence.
Import success alone does not mean the signing key is verified.

Paste the public key exactly: spaces, a private key, PEM text, an empty value or `null`
are rejected. It can also be supplied later using `PATCH /v1/phone-numbers/:number`.
Changing it creates another candidate; an overlapping previous key can make a further
rotation return `telnyx_key_rotation_pending`. Neither import nor PATCH can force a key
to be verified. Supplying a Telnyx public key with Twilio credentials is rejected.

**What Telnyx numbers support today**

| | Status |
|---|---|
| Inbound calls | Yes |
| Recording | Yes |
| Cold and warm transfer | Yes |
| Concurrency limits | Yes |
| Booking, custom functions, analysis, webhooks | Yes |
| Live Monitor | Yes |
| Inbound SMS and auto-reply | Yes |
| Sending SMS | Yes |
| SMS delivery status | Yes |
| SMS campaigns | Yes |
| Outbound calls | Yes |
| Outbound recording | Yes |
| Keypad input (DTMF) | Yes |
| Carrier voicemail detection (AMD) | Yes |

<Note>
  Telnyx numbers support the same feature set as Twilio numbers, including SMS campaigns
  and delivery receipts. You do not need to pick a carrier based on features - pick on
  price, coverage, and whichever account you already have.
</Note>

## Response

`201 Created`:

```json
{
  "phone_number": {
    "phone_number": "+447446466847",
    "agent_id": "agent_125207e452f8714a",
    "twilio_number_sid": "PN451e0ddf654327e36baab58dfbcd30d6",
    "inbound_enabled": true,
    "outbound_enabled": true
  }
}
```

The current Twilio import response does not include `provider`. A Telnyx import returns
`"provider": "telnyx"` and `telnyx_number_id` instead of `twilio_number_sid`. Neither
response returns carrier secrets or the signing key's internal verification fields.

## Errors

**Both carriers**

| Code | HTTP | Cause |
|---|---|---|
| `missing_field` | 400 | A required field is empty |
| `invalid_phone_format` | 400 | Not E.164 format |
| `custom_prompt_too_long` | 400 | Over 8000 characters |
| `agent_not_found` | 404 | `agent_id` does not exist |
| `agent_not_owned` | 403 | The agent belongs to a different API key |
| `number_already_imported` | 409 | Already attached to an agent |
| `mixed_provider_credentials` | 400 | More than one carrier credential set |
| `conflicting_fields` / `unknown_field` / `invalid_request` | 400 | Conflicting aliases, unsupported fields or invalid value types |
| `account_unavailable` | 403 | Account is inactive or closing |
| `agent_unavailable` | 409 | Agent is inactive |
| `number_operation_pending` / `number_release_pending` | 409 | Another number operation must finish first |
| `number_cleanup_uncertain` | 503 initially; 409 on retry | Carrier outcome is not confirmed; support must reconcile it |
| `number_save_pending` | 503 | Carrier change acknowledged; retry the identical request to finish the database step |
| `number_operation_unavailable` | 503 | Database operation could not be confirmed; this request sent no new carrier change |

**Twilio**

| Code | HTTP | Cause |
|---|---|---|
| `invalid_twilio_sid` | 400 | SID does not match `AC` + 32 hex |
| `twilio_invalid_credentials` | 401 | SID and token rejected by Twilio |
| `number_not_in_twilio` | 404 | Number not in your Twilio account |

**Telnyx**

| Code | HTTP | Cause |
|---|---|---|
| `telnyx_invalid_credentials` | 401 | API key rejected by Telnyx |
| `number_not_in_telnyx` | 404 | Number not in your Telnyx account |
| `number_cleanup_uncertain` | 503 | Assignment was not confirmed; check the application ID and contact support before re-importing |
| `invalid_telnyx_public_key` | 400 | Public key is not canonical base64 of exactly 32 bytes |
| `telnyx_public_key_not_applicable` | 400 | A Telnyx public key was supplied for a Twilio import |

## Use case: reseller onboarding

```javascript
// 1. Buy a number from your Twilio account
const twilio = require('twilio')(YOUR_TWILIO_SID, YOUR_TWILIO_TOKEN);
const available = await twilio.availablePhoneNumbers('GB').local.list({ limit: 1 });
const purchased = await twilio.incomingPhoneNumbers.create({
  phoneNumber: available[0].phoneNumber
});

// 2. Attach it to your Nixflex agent
await fetch('https://api.nixflex.com/v1/phone-numbers', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${NIXFLEX_KEY_ID}:${NIXFLEX_KEY_SECRET}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    phone_number: purchased.phoneNumber,
    twilio_sid: YOUR_TWILIO_SID,
    twilio_token: YOUR_TWILIO_TOKEN,
    agent_id: 'agent_your_template'
  })
});
```
