Connect a number you already own to an active agent on the same account. Import can replace existing number routing, so another application using that routing can stop receiving calls or texts.

## Authentication

Send `Authorization: Bearer KEY_ID:KEY_SECRET` using the owning account’s server-side credential. Send `Content-Type: application/json`.

## Request fields

The public fields are shown here. Successful import additionally requires an existing legacy connection credential payload. Those credential field names are deliberately undocumented; this schema is not a complete credential validator.

| Field | Type | Required | Default | Limits and meaning |
| --- | --- | --- | --- | --- |
| `phone_number` | string | Yes | None | Business number. Up to 64 input characters; spaces, hyphens, parentheses and dots are removed before E.164 validation. Maximum 64 characters. |
| `agent_id` | string | Yes | None | Owned active agent identifier; trimmed, nonblank, at most 200 characters. Maximum 200 characters. |
| `custom_prompt` | string or null | No | `null` | Optional number-specific prompt, at most 8,000 characters. Maximum 8000 characters. |

The engine currently requires legacy connection credential fields as well as the public fields below. Their names remain undocumented; there is no neutral credential alias in this API revision. For a new setup, connect the number in the dashboard. Existing integrations can supply their securely prepared private import.json unchanged. The examples read that file and do not show, print or invent credential fields. The neutral fields alone are not a successful import request.

Unknown import fields are refused. Use only one connection credential set; do not mix it with another. custom_prompt does not configure the remaining per-number switches.

## Response fields

`201 Created` returns the shape below. Nullable fields can be unknown or unset; do not turn null into zero or false.

| Field | Type | Meaning |
| --- | --- | --- |
| `phone_number` | object | Neutral fields from the imported number. Legacy identifier fields may also be present. |
| `phone_number.phone_number` | string | Imported business number. |
| `phone_number.agent_id` | string | Agent to which the number is attached. |
| `phone_number.inbound_enabled` | boolean | Inbound calls are enabled on successful import. |
| `phone_number.outbound_enabled` | boolean | Outbound calls are enabled on successful import. |

## Example request

The examples use staging. Keep `NXF_STAGING_KEY` in your environment; the CLI uses it through `NIXFLEX_API_KEY`. The shell examples use Bash syntax. Kit examples use the tested Node/CLI 0.10.0 and Python 0.3.0 candidates; these versions are unpublished. Prepare `import.json` privately using your existing integration’s accepted payload; the neutral fields in this page are not a complete connection credential payload.

<RequestExample>

```bash cURL
curl --request POST \
  --url "https://nixflex-voice-engine-staging.up.railway.app/v1/phone-numbers" \
  --header "Authorization: Bearer $NXF_STAGING_KEY" \
  --header "Content-Type: application/json" \
  --data-binary @import.json
```

```javascript Node
import Nixflex from 'nixflex';
import { readFileSync } from 'node:fs';
const baseUrl = 'https://nixflex-voice-engine-staging.up.railway.app';
const client = new Nixflex({apiKey:process.env.NXF_STAGING_KEY,baseUrl,maxRetries:0});
const result = await client.phoneNumbers.import(JSON.parse(readFileSync("import.json","utf8")));
// Handle result privately; do not log secrets or call content.
```

```python Python
import os, json
from pathlib import Path
from nixflex import Nixflex
base_url = "https://nixflex-voice-engine-staging.up.railway.app"
with Nixflex(os.environ["NXF_STAGING_KEY"], base_url=base_url,max_retries=0) as client:
    result = client.phone_numbers.import_(**json.loads(Path("import.json").read_text()))
# AsyncNixflex supports the same calls with await (and async with).
```

```bash CLI
NIXFLEX_API_KEY="$NXF_STAGING_KEY" nixflex numbers import --body @import.json --base-url https://nixflex-voice-engine-staging.up.railway.app --json
```

</RequestExample>

## Errors

Failures return an `error` object with `code`, `message`, `doc_url` and optional details. Each code links to the shared error catalog. Read the message and details before deciding whether to resend.

<div className="agent-error-table">

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 400 | [`invalid_phone_format`](/api-reference/errors#invalid_phone_format) | The number format is invalid. | Use a complete E.164 number. |
| 403 | [`account_unavailable`](/api-reference/errors#account_unavailable) | The account is not active. | Resolve account access before attempting another number operation. |
| 409 | [`number_operation_pending`](/api-reference/errors#number_operation_pending) | Another import or removal is pending. | Read the current number and wait; do not change its routing. |
| 409 | [`number_cleanup_uncertain`](/api-reference/errors#number_cleanup_uncertain) | A previous routing change is unconfirmed. | Contact support to reconcile it before importing or removing again. |
| 503 | [`number_cleanup_uncertain`](/api-reference/errors#number_cleanup_uncertain) | The routing outcome from this attempt is unconfirmed. | Do not resend or change routing; reconcile through support. |
| 503 | [`number_save_pending`](/api-reference/errors#number_save_pending) | Routing changed but local completion could not be confirmed. | Read current state and contact support; never replay automatically. |
| 503 | [`number_operation_unavailable`](/api-reference/errors#number_operation_unavailable) | The operation could not be confirmed. | Reconcile the number before another write. |
| 400 | [`missing_field`](/api-reference/errors#missing_field) | A required number, agent or connection value is missing. | Complete the privately prepared import payload; do not invent credential aliases. |
| 400 | [`unknown_field`](/api-reference/errors#unknown_field) | An unsupported import field was supplied. | Use PATCH separately for other number settings. |
| 400 | [`conflicting_fields`](/api-reference/errors#conflicting_fields) | Two aliases supplied conflicting values. | Supply each value once. |
| 400 | [`mixed_provider_credentials`](/api-reference/errors#mixed_provider_credentials) | More than one connection credential set was supplied. | Use the single connection that owns this number. |
| 400 | [`custom_prompt_too_long`](/api-reference/errors#custom_prompt_too_long) | The prompt exceeds 8,000 characters. | Shorten the number-specific prompt. |
| 403 | [`agent_not_owned`](/api-reference/errors#agent_not_owned) | The target agent belongs to another account. | Choose an agent owned by the authenticated account. |
| 404 | [`agent_not_found`](/api-reference/errors#agent_not_found) | The target agent does not exist. | Use a returned agent ID. |
| 409 | [`agent_unavailable`](/api-reference/errors#agent_unavailable) | The target agent is not active. | Choose an active owned agent. |
| 409 | [`number_already_imported`](/api-reference/errors#number_already_imported) | The number is already imported. | Read the existing number; use PATCH for a deliberate move or settings change. |
| 409 | [`number_release_pending`](/api-reference/errors#number_release_pending) | A prior release needs reconciliation. | Wait for its outcome to be resolved. |
| 401 | [`unauthorized`](/api-reference/errors#unauthorized) | The credential is missing or invalid. | Check the account credential and environment. |
| 429 | [`rate_limit_exceeded`](/api-reference/errors#rate_limit_exceeded) | The account request limit was reached. | Wait for Retry-After. Reconcile uncertain writes before resending. |

## Retry and idempotency

Never automatically retry an import. Save any returned operation_id from safe error details. A pending completion may allow an exact, deliberate reconciliation request after state is checked; an uncertain routing outcome needs support. Do not re-import to work around number_cleanup_uncertain.
