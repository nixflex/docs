---
title: "Disable agent"
description: "DELETE /v1/agents/:id — soft disable only"
api: "DELETE https://api.nixflex.com/v1/agents/{agent_id}"
---

Draft. This operation only writes `is_active=false` and updates the timestamp.
It does not detach phone numbers, erase the row/history, or send carrier requests.

The existing response is kept for compatibility, but its wording means **soft disable**:

```json
{ "message": "Agent deleted" }
```

GET by ID can still return the owned disabled agent. List returns only active agents.
PUT `{"is_active":true}` can re-enable it. This is not the dashboard's permanent erasure process.

The update must affect an owned row before success is returned.
Missing/foreign rows return `404 not_found`; database failures return
`503 agent_store_unavailable`. Check the agent before retrying an uncertain result.
