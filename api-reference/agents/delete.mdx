Switch an owned agent off by setting is_active to false. GET still returns the inactive record. This is not permanent erasure.

## Authentication

Use `Authorization: Bearer KEY_ID:KEY_SECRET` for the owning account. An organisation API key has Owner authority. Personal sessions use the role rules documented in [Authentication](/api-reference/authentication); do not treat a Member session as an API key.

## Request fields

| Field | Type | Required | Default and limits |
| --- | --- | --- | --- |
| `id` (path) | string | Yes |  |

Do not send a request body.

This operation only writes `is_active=false` and updates the timestamp.
In plain words: **switch off**, not permanent deletion or a wait-for-live-calls operation.
It does not detach phone numbers, erase the row/history, or send carrier requests.

The existing response is kept for compatibility, but its wording means **soft disable**:



GET by ID can still return the owned disabled agent. List defaults to active only;
use `status=disabled` or `status=all` to include it.
PUT `{"is_active":true}` can re-enable it. This is not the dashboard's permanent erasure process.

The update must affect an owned row before success is returned.
Missing/foreign rows return `404 not_found`; database failures return
`503 agent_store_unavailable`. Check the agent before retrying an uncertain result.

## Response fields

`200` returns the following shape.

| Field | Type | Meaning |
| --- | --- | --- |
| `message` | string | Compatibility wording for switching the agent off. |

## Errors

Branch on `error.code`, not the wording of `error.message`. The envelope includes `type`, `code`, `message`, `doc_url` and `details`.

| Status | Meaning |
| --- | --- |
| 400 | Invalid request - missing or malformed parameters. |
| 401 | Authentication failed - bad or missing API key. |
| 404 | Not found on your account. |
| 429 | Rate limit exceeded. Honour the Retry-After header. |
| 500 | Server error. |
| 503 | Agent storage or catalog unavailable; check before retrying a write. |



## Retry and idempotency

Disable automatic write retries. A lost response leaves the result uncertain; read the affected resource before another deliberate action. No general Idempotency-Key replay guarantee applies. See [retry rules](/api-reference/retries).
