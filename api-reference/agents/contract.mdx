Draft only: publish with the matching engine release, not before staging verification.
All four read/write responses use the same reviewed projection. Responses never contain
`twilio_auth_token`; `twilio_account_sid` is a legacy readable account identifier.

## Inputs

No coercion of strings into booleans/numbers. Valid 0/false values are preserved.
Omitted fields retain defaults (create) or the saved value (update).
Pickup delay is the deliberate legacy exception: this release does not alter its
validation, values or defaults. Do not change it as part of the staging helper.

`func_end_call` governs duration/silence timers; it is not a blanket prohibition on model END_CALL.
This release does not turn inert compatibility settings into features, and does not
change channel rules, billing, recording, pickup timing or the dashboard's direct writes.

Extraction entries: required `name` (unique identifier, 1-64 letters/digits/underscores,
starting with a letter/underscore; __proto__/constructor/prototype forbidden) and
`type` (text / selector / boolean / number). Optional `description` and
`format_example` are strings up to 2000; `optional` is boolean.
`choices` is up to 100 unique non-blank strings, each at most 200 characters;
a selector requires at least one. Unknown nested properties reject the whole request.

## Errors and warnings

Empty/unknown-only PUT: 400 empty_agent_update.
Mixed supported/unknown fields: supported fields save, with a JSON `warnings` array
containing code unknown_fields, unknown names, and "These fields were not saved."
Unknown input values are not echoed. Empty POST still creates defaults.

Known invalid input fails before writing. Dedicated prompt, recording-source,
remember-callers, retention, voice-selection and credential errors remain.
Missing/foreign agent: 404 not_found. Database failure: 503 agent_store_unavailable.
Catalog lookup outage: 503 catalog_unavailable. No blind write retries.

## Kits

See the feature-branch examples/agent-contract.md in Node+CLI, Python and MCP.
The CLI already passes all fields via repeated --set or --body; no new CLI flags
or mutation-retry behavior are needed. MCP publishes named settings while retaining
unknown keys so the engine can issue its warning. No package publication in this run.

DELETE soft-disables only and retains the legacy response {"message":"Agent deleted"}.
It does not detach numbers, erase history or make GET of an owned disabled agent return 404.
