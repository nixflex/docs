Draft for the Batch 2 engine release; not published in this run.

Creates an agent. Every field is optional. An empty object uses the new defaults below.
It does not import a phone number or start a call.

```json
{
  "name": "Contract test",
  "system_prompt": "Help the caller.",
  "temperature": 0,
  "response_eagerness": 0,
  "timezone": "Europe/London",
  "stt_confidence": 0,
  "stt_max_silence_ms": 0,
  "incall_sms_enabled": true,
  "post_call_sms_enabled": true,
  "post_call_sms_template": "Thanks for calling.",
  "voicemail_leave_enabled": true,
  "voicemail_message": "Please call us back.",
  "data_extraction_fields": [
    { "name": "interested", "type": "boolean", "optional": true }
  ]
}
```

All writable fields and exact limits are in [Agent contract](/api-reference/agents/contract).
POST now stores the same legitimate settings as PUT, except retention:
`call_retention_days` inherits the account default on create. Sending it to POST
returns `400 retention_inherited`; change it with PUT afterwards if needed.

## Defaults (NEW agents only)

Dynamic greeting, maximum duration and silence timeout now match the dashboard's
new-agent form. No existing agent is migrated, and PUT still changes only sent fields.
Dynamic greeting means the AI writes the inbound greeting from the agent prompt;
the saved welcome text is used when you explicitly turn dynamic greeting off.

| Fields | Default |
|---|---|
| name | Untitled Agent |
| system_prompt | You are a friendly AI assistant. Help callers with their questions. |
| welcome_message | Hello! How can I help you today? |
| voice_id / voice_key | Ashley, resolved to its catalog key |
| language / temperature / response_length | multi / 0.3 / short |
| response_eagerness / stt_confidence / stt_max_silence_ms | Database defaults: 200 / 0 / 0 |
| is_active / ai_speaks_first / dynamic_greeting / func_end_call / record_call / greet_by_name | true |
| func_cold_transfer / func_send_sms / amd_enabled / require_booking_confirmation | false |
| incall_sms_enabled / post_call_sms_enabled / voicemail_leave_enabled | Database default false |
| max_call_duration_seconds / silence_hangup_seconds | 300 / 10 |
| wait_tag_seconds / ivr_timeout_seconds | null / 240 |
| interruption_sensitivity / pickup_delay | 50 / 10; pickup handling unchanged |
| transfer_type / recording_source | cold / provider |
| voice_speed / speaking_rate / dtmf_enabled | 0.85 / null / null |
| timezone | Valid account time zone, otherwise UTC; explicit valid timezone wins |
| data_extraction_fields | Database default [] |

Omitted database-managed settings stay database-managed. The release does not
change their defaults or any existing agent. Explicit valid values win, including
zero/false, empty name/prompt/welcome/model/fallback text and nullable timers.
Explicit timer null is stored as null and keeps the existing runtime fallback; it
does not mean "use the new create default". The dashboard can use the browser time
zone if the account has none; a server API has no browser, so it uses UTC instead.
Existing language-empty normalization to multi, voice validation, speaking-rate clamp,
recording-source normalization and pickup handling remain unchanged.

## Response and errors

`201` returns the same reviewed safe agent projection as PUT, GET and each list item.
No carrier secret or unreviewed future column is returned.
Mixed unknown keys add `warnings`; only unknown keys returns `400`.
The ID and owner are generated by the server, never supplied by the caller.

Missing/foreign agent reads are `404 not_found`. Database failures are
`503 agent_store_unavailable` (catalog lookup failures: `503 catalog_unavailable`).
After an uncertain write, check before retrying; do not blindly repeat a create.
