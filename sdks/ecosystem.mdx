## Reviewed kit versions

K6 supplies locally built candidates: **Node/CLI 0.11.0**, **Python 0.4.0** and
**MCP 0.5.0 with 94 tools**. Its offline checks pass; registry publication and real
staging writes remain separate. Install the supplied, hash-verified archives when
testing these versions. A plain registry install does not prove candidate availability.

Node and Python now include four Google Calendar methods and an in-place number
credential update. See the [Node examples](/sdks/node#reviewed-0-11-0-candidate),
[Python examples](/sdks/python#reviewed-0-4-0-candidate) and [CLI commands](/cli/commands#google-calendar-and-number-credentials).

MCP adds `connect_google_calendar`, `get_google_calendar`,
`disconnect_google_calendar`, `update_google_calendar_settings` and
`update_phone_number_credentials`. Each new write requires `confirm: true`; carrier
credentials come only from the privately configured server process. The previous 89
tool contracts remain unchanged. There is still no direct booking or knowledge
publication tool. The [AI setup guides](/ai-tools/overview) cover the supplied
0.5.0 candidate, its 94 registered tools and private credential setup limits.

Single-SMS suppression uses HTTP 409 `do_not_contact`. Node and Python expose
`NixflexDoNotContactError` and `NixflexConflictError`; preserve old 400 handling too.
Do not retry an opt-out. Booking models cover call and SMS events, but do not replace
raw-body signature verification or add a webhook receiver tool.

The new [`call.bookings` event](/api-reference/call-bookings) is documented from the
later engine change. The supplied K6 candidates do not establish typed support for
its separate `timeline` and `final` payload. Use the documented JSON contract and
verify signatures before processing; check a later client release before relying
on new event-specific types or helpers.
