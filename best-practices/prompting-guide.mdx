---
title: "Agent instructions: write clear tasks and useful fallbacks"
description: "Write Nixflex agent instructions with a clear purpose, essential facts and action rules, then test ordinary questions, missing facts and failed actions."
---

Good instructions describe one useful job in plain language. They do not need repeated demands or a long list of claims that every request will succeed.

Using the dashboard? Start with [set up your business agent](/business). Developers can save the same intended behaviour through the [agent contract](/api-reference/agents/contract).

## Give each section a job

| Section | Include |
| --- | --- |
| Identity | Business name, role and intended customers |
| Purpose | What this conversation should achieve |
| Essential facts | Facts needed on almost every call |
| Conversation | Questions to ask, one at a time |
| Actions | When to use each permitted connection or tool |
| Uncertainty | What to do when a fact or outcome is unknown |
| Finish | A polite completion or human-handoff rule |

Example instructions for a fictional studio:

```text
You are Willow Studio's appointment assistant.
Help the caller understand a service and request an appointment.
Ask which service they want, then their preferred date and time.
Use approved knowledge for service details. Do not invent prices.
Check the connected calendar before offering a specific slot.
Read back the service, date, time and time zone when confirmation is required.
Say the appointment is booked only after the calendar confirms success.
If an answer is missing, explain that and offer the business's follow-up option.
Ask one question at a time and keep replies short.
```

## Put detailed facts in knowledge

Keep rules and frequent facts in the main call instructions. Use [knowledge](/concepts/knowledge) for detailed policies, menus and exceptions. When knowledge is active, the main-prompt admission budget is 3,000 tokens; the separate field character limit is not permission to exceed that combined workflow's prompt budget. A token is a piece of text, not one word.

SMS and website instructions are separate from the main call prompt. An outbound call also needs its own purpose. Moving a number changes the agent and its knowledge, so review the resulting conversation before using it with customers.

## Check facts and outcomes

Confirm important names, dates and numbers instead of filling gaps from a weak transcript. Explain the intended time zone explicitly when a customer could be elsewhere. A prompt does not grant calendar, text, transfer or custom-function permissions.

Test an ordinary question, an unknown fact, an interruption, a changed appointment and a failed action. Check the actual calendar or message result. Typed knowledge Test validates facts; it does not replace a full call test with real speech and timing.
